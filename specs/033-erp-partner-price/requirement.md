# 需求规格：客户价格、账期与信用额度（erp-partner-price）

> 进销存扩展路线（`specs/ROADMAP.md`）批次四第四项，依赖 `023-erp-settlement`（应收口径与往来台账）。
> 本规格同时把 `023` §5 列出的「账期、信用额度、催收提醒」中的前两者落地（催收提醒随 `035` 的站内信能力）。

## 1. 背景

现状销售侧的价格与授信是**空白**的：

- **价格靠脑记**：销售出库的单价默认带商品销售价，给大客户的协议价只能每单手工改（改错就是真金白银的损失），也没有地方记录「这个客户就是这个价」。
- **账期靠人记**：什么时候该收款（单据日期 + 账期）系统里没有，只能线下维护表格。
- **授信无上限**：客户能欠多少完全不受控，赊销风险只能事后发现（`023` 提供了应收余额，但没有闸门）。

`023` 已把「单据 → 资金」闭环打通（已结算金额、往来对账），本规格在闭环上加两个业务规则：**取价规则**与**授信闸门**。

## 2. 目标

1. **客户协议价**：按「客户 × 商品」维护协议单价（唯一），支持列表 / 新增 / 编辑 / 删除。
2. **取价优先级单一**：销售出库开单时，单价 = **客户协议价（若配置）→ 否则商品销售价**；前端只做默认带出与来源标注，后端**不信任前端传值**（仍按前端传入单价落库，见 `design.md` §0 说明）。
3. **账期**：往来单位维护「账期天数」；单据到期日 = 单据日期 + 账期天数（推导，不落列）；往来对账页展示到期日与**逾期**标识（未结清且已过到期日）。
4. **信用额度**：往来单位维护「信用额度」（`0` = 不限）；销售出库保存时校验「客户当前应收余额 + 本单金额 ≤ 信用额度」，超限拒绝（`40130`）。
5. **前端**：新增「客户价格」页（`/partner-prices`，归「资金」分组）；往来单位抽屉追加账期与额度字段；销售开单页按客户批量取价并在明细标注「协议价 / 默认价」；往来对账页追加到期日 / 逾期列与「仅看逾期」筛选。

## 3. 功能点

- **F1 数据模型**：`PartnerPrices`（客户 × 商品唯一 + 单价 + 备注 + 审计）；`Partners` 追加 `PaymentTermDays`（账期天数）与 `CreditLimit`（信用额度）。
- **F2 用例**：`GetPartnerPrices`（客户 / 商品 / 关键词筛选 + 分页）/ `CreatePartnerPrice` / `GetPartnerPriceById` / `UpdatePartnerPrice` / `DeletePartnerPrice` / `GetEffectivePrices`（批量取生效价，供开单页）。
- **F3 销售开单取价**：选中客户后按商品批量取价（一次请求）；明细行单价默认取生效价并标注来源；用户仍可手工改（改后标注消失）。
- **F4 信用校验**：`CreateSalesOrder`（出库）在写单前校验额度；超限 → `40130`（message 含客户名、额度、当前应收、本单金额）；`CreditLimit = 0` 视为不限；采购侧不校验。
- **F5 账期与逾期**：往来对账（`023` 页面）按客户展示「账期天数 / 到期日 / 逾期天数」；列表支持「仅看逾期」筛选；单据详情展示到期日（销售类）。
- **F6 e2e 覆盖**：配置协议价 → 销售开单自动带出协议价并标注；协议价低于销售价时以协议价为准；额度 1000、应收 800 时开 300 被拒（`40130`）、开 200 通过；额度 0 不限；往来对账逾期标识与筛选。

## 4. 验收标准

1. `cd backend && dotnet build` / `dotnet test` 通过（含取价优先级、额度校验边界、协议价唯一性、删除后回退默认价等单测）。
2. `cd frontend && npm run type-check` / `npm run lint` / `npm run build` 全绿；`npm run test:e2e` 全量通过（含新增 `partner-price.spec.ts` 与 `sale` / `report` / `settlement` 既有用例回归）。
3. 手工验证（取价）：
   - 客户甲 + 商品 A 配置协议价 8.80（商品销售价 10.00）→ 销售开单选客户甲、商品 A → 单价自动 8.80 且标注「协议价」。
   - 未配置协议价的商品 → 单价 10.00 且标注「默认价」。
   - 删除该协议价 → 再开单回到 10.00。
4. 手工验证（额度）：客户乙额度 1000、当前应收 800 → 开 300 → 拒绝（`40130`，提示含额度 / 应收 / 本单）；开 200 → 通过，应收变为 1000；再开 0.01 → 拒绝。额度 0 的客户不受限。
5. 手工验证（账期）：客户丙账期 30 天，7 月 1 日开单 → 到期日 7 月 31 日；8 月 5 日（未结清）→ 往来对账显示「逾期 5 天」且「仅看逾期」可筛出；收款结清后不再显示逾期。
6. 口径单一：取价优先级、额度口径、到期日与逾期判定只在 `design.md` §0 定义一次；应收余额口径引用 `023` §0，本规格不重复定义。

## 5. 范围外（不做）

- **供应商采购价协议 / 采购取价**：本期只做销售侧客户价（采购审批与供应商谈判价另立）。
- **阶梯价 / 数量折扣 / 促销价 / 会员价**：单一协议价，不做按数量区间的阶梯与时效性促销。
- **价格生效期与价格历史**：协议价单值（改了即覆盖）；变更留痕由 `029-erp-audit-log` 承担，不做价格版本与生效时间窗。
- **按仓 / 按业务员 / 按渠道差异价**：不做多维定价。
- **多币种与汇率**：单币种（人民币）记账（同 `023`）。
- **账期利息 / 滞纳金 / 信用保险**：不做资金成本计算。
- **自动锁定客户（超额度禁止开单的开关策略）**：本期为**强制拦截**（不可配置为「仅提醒」）；审批例外由 `036-erp-approval` 覆盖。
- **催收提醒（站内信 / 邮件）**：随 `035-erp-stock-alert` 的站内信能力落地（本规格只提供逾期数据与页面标识）。
- **信用额度调整流程（申请 / 审批）**：直接改往来单位字段（变更留痕走 `029`）。
- **发票与税务**：`034-erp-invoice`。
