# 需求规格：招聘管理（erp-recruit）

> ERP 全域路线（`specs/ROADMAP.md` §4.2）**P8 深化**项（**待评估**：须业务场景确认后启用）；补齐 `ROADMAP` §3「人力域 · HCM」的「招聘」后置缺口。
> 依赖：`030`（部门 / 岗位 / 员工）、`028`（权限）。
> 范围克制：只做**招聘需求 + 候选人 + 阶段流转 + 录用转入职**；**绩效另立规格**（见范围外）；不做题库 / 测评 / Offer 审批 / 招聘渠道对接。

## 1. 背景

`030` 建成了组织 / 岗位 / 员工档案，但**入职之前**的招聘过程没有载体：

- 招聘需求（要招什么人、招几个、归哪个部门）无处登记，招聘进度靠口头跟进。
- 候选人信息散落在表格 / 邮件里，阶段（待筛选 / 面试中 / 已录用 / 已淘汰）无法统一追踪。
- 录用后需再手工在员工档案里录一遍，重复劳动且易漏字段（部门 / 岗位来自同一需求）。

本规格补上 HCM 的**招聘前段**：招聘需求 → 候选人 → 阶段流转 → 录用一键转入职（生成员工档案），与前段形成"招聘 → 入职 → 薪酬"闭环。

## 2. 目标

1. **招聘需求**：登记（岗位 / 部门 / 招聘人数 / 发布时间 / 状态 开放 / 关闭），单号 `JR + yyyyMMdd + 4`。
2. **候选人**：登记（姓名 / 性别 / 电话 / 邮箱 / 应聘需求 / 来源 / 备注）+ 阶段流转（待筛选 → 面试中 → 已录用 / 已淘汰）。
3. **录用转入职**：`Hired` 候选人一键转入职 → 同事务生成员工档案（`030`）+ 回写候选人 `EmployeeId`（只能转一次）。
4. **规则**：需求关闭后不可新增 / 流转候选人（`40192`）；阶段流转受控（`40193`）；已入职候选人不可重复转（`40194`）。
5. **权限与菜单**：权限点续行 `028` §0.2（`jobRequisitions.*` / `candidates.*`）；菜单「人事」分组续行（`025` §0.2）。
6. **前端**：需求列表 / 候选人列表（抽屉表单 + 阶段推进 + 转入职）；**e2e 覆盖**。

## 3. 功能点

- **F1 招聘需求**：`GET/POST /api/job-requisitions`、`GET/PUT /{id}`、`PUT /{id}/close`（关闭后不可改）。
- **F2 候选人**：`GET/POST /api/candidates`、`GET/PUT /{id}`（按需求 / 阶段 / 关键词筛选）。
- **F3 阶段流转**：`PUT /api/candidates/{id}/stage`（白名单流转，见 `design.md` §0.1；非法 → `40193`）。
- **F4 转入职**：`POST /api/candidates/{id}/convert`（仅 `Hired`，否则 `40193`；已关联员工 → `40194`）；同事务建 `Employee`（`030`）+ 回写。
- **F5 权限与菜单**：`028` §0.2 续行 `jobRequisitions.*` / `candidates.*`；`025` §0.2「人事」分组续行两项。
- **F6 e2e**：建需求 → 建候选人 → 推进阶段 → 转入职 → 员工档案出现；关闭需求后新增候选人 `40192`。

## 4. 验收标准

1. `cd backend && dotnet build` / `dotnet test` 通过（阶段白名单、需求关闭限制、转入职一致性 / 唯一性）。
2. `cd frontend && npm run type-check` / `npm run lint` / `npm run build` 全绿；`npm run test:e2e` 全量通过（新增 `recruit.spec.ts`）。
3. 手工验证：
   - 建需求（岗位 / 部门 / 3 人）→ 建候选人 → 阶段：待筛选 → 面试中 → 已录用 → 转入职 → 员工档案出现该员工（部门 / 岗位取自需求）。
   - 重复转入职 → `40194`；需求关闭后新增候选人 → `40192`；非法阶段跳转 → `40193`。
4. 口径单一：阶段取值 / 流转白名单 / 转入职判据只在 `design.md` §0 定义一次。
5. 联动：`028` §0.2 续行、`025` §0.2「人事」分组续行、`030` §0.2 增「招聘可转入职」指针、`ROADMAP` §6.7 单号前缀续行（`JR`）、`ROADMAP` §6 错误码续行；**绩效出 056 范围**（`ROADMAP` §4.2 / §5 同步）。

## 5. 范围外（不做）

- **绩效管理（考核周期 / 评分 / 等级 / 评语）**：**另立规格**（建议序号 `059`），本规格不含；`ROADMAP` §4.2 待同步。
- **Offer 审批 / 薪酬方案 / 入职材料清单**：不做。
- **面试记录 / 面试官安排 / 面试评价表**：本期只做候选人与阶段，无面试过程记录。
- **招聘渠道对接 / 简历解析 / 人才库 / 猎头**：不做。
- **笔试 / 测评 / 题库**：不做。
- **招聘计划 / 编制控制 / 预算**：不做。
- **候选人附件 / 简历上传**：不做文件存储。
- **招聘需求审批**：不做。
