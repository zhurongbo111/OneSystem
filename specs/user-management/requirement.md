# 需求规格：用户管理（user-management）

## 1. 背景

项目脚手架阶段（`specs/project-scaffold/`）的用户仅由内存仓储提供示例账号 `admin / admin123`（明文），无用户表、无用户管理能力，登录账号写死。现在需要实现真正的用户模块：

- 系统**不提供注册入口**，用户由**管理员在后台创建与维护**。
- 本期是**首个接入真实 PostgreSQL 的功能**：建立 `Users` 表、密码哈希存储、登录改为查真实用户表。
- 登录行为需要可追溯：**登录日志单独建表** `UserLoginLogs`，本期只记录**成功登录**，并提供独立的「登录日志」查询页。
- 前端提供用户列表页与新增/编辑表单（复用既有列表页 / 表单页约定）。

> 角色 / 权限体系本期不做（用户仅区分"启用 / 禁用"），后续单独规格补充。

## 2. 目标

1. 管理员可在后台对用户进行：查看列表、查看详情、新增、编辑、启用/禁用、重置密码。
2. 无注册入口；密码由管理员设置（创建时手动设置初始密码）。
3. 用户数据落 PostgreSQL，密码哈希存储（禁止明文）。
4. 登录接入真实用户表：校验用户名 + 密码哈希 + 账号状态。
5. 记录成功登录日志（登录人、登录时间、客户端 IP、User-Agent），并提供可分页筛选的查询页面。
6. 前端提供用户管理页面（列表 + 新增/编辑抽屉 + 详情页）与登录日志页面，纳入全局布局与侧边菜单。

## 3. 功能点

- **F1 用户列表**：分页查询，支持按关键词（用户名 / 显示名模糊匹配）与状态（启用 / 禁用）筛选；返回总数。
- **F2 用户详情**：按 id 查看单个用户完整信息。
- **F3 新增用户**：管理员填写用户名、显示名、邮箱、手机号、初始密码；用户名唯一、邮箱/手机号非空时唯一。
- **F4 编辑用户**：修改显示名、邮箱、手机号；**用户名创建后不可修改**。
- **F5 启用 / 禁用**：切换用户状态；禁用后该账号不能登录；不能禁用当前登录账号。
- **F6 重置密码**：管理员为指定用户设置新密码（无需原密码）。
- **F7 不删除用户**：仅通过"禁用"停用账号，保留历史数据，不提供删除接口。
- **F8 登录适配**：`POST /api/auth/login` 改为查真实用户表，校验密码哈希与账号状态，成功时更新最近登录时间。
- **F9 数据持久化**：`Users` 表、`UserLoginLogs` 表（EF Core Migrations 首次建表）、密码哈希组件、EF Core 仓储实现替换 `InMemoryUserRepository`。
- **F10 初始化种子**：系统无用户时自动创建一个内置管理员（`admin`），避免无注册入口下被锁死。
- **F11 前端用户管理页**：用户列表页 `/users`（复用 `list-showcase` 约定）、新增/编辑抽屉（复用 `form-detail-showcase` 约定）、用户详情页 `/users/detail/:id`；侧边菜单新增"用户管理"入口。
- **F12 登录日志记录**：每次**成功**登录追加一条登录日志（用户 id、登录名快照、显示名快照、登录时间(UTC)、客户端 IP、User-Agent）；登录失败（密码错误 / 账号不存在 / 账号已禁用）**不记录**。
- **F13 登录日志查询**：分页查询登录日志，支持按登录名（模糊）与登录时间范围筛选，按登录时间倒序；**只读**（不提供新增 / 修改 / 删除接口）。
- **F14 前端登录日志页**：独立菜单页 `/login-logs`，服务端分页只读表格（登录名、显示名、登录时间、IP、User-Agent）。

## 4. 验收标准

1. `cd backend && dotnet build` 成功（net8.0）；`dotnet test` 全部通过。
2. 执行 EF Core 迁移后 `Users`、`UserLoginLogs` 表存在；表结构与 `design.md` 一致；密码字段为哈希值（非明文）。
3. `POST /api/auth/login`：正确账号返回 `code:0` + JWT；错误密码返回 `40001`；禁用账号返回 `40005`。
4. `GET /api/users`（需登录，分页）返回 `{ items, total, page, pageSize }`；支持 `keyword`、`status` 筛选。
5. `POST /api/users` 新增用户成功；重复用户名返回 `40002`，重复邮箱返回 `40003`，重复手机号返回 `40004`。
6. `PUT /api/users/{id}` 编辑用户成功（用户名不可改）；不存在返回 `40400`。
7. `PUT /api/users/{id}/status` 可启用/禁用；禁用当前登录账号返回 `40006`。
8. `PUT /api/users/{id}/password` 重置密码后，用新密码可登录、旧密码不可登录。
9. 成功登录后 `UserLoginLogs` 追加一条记录（登录名、显示名、登录时间、IP 正确）；登录失败不产生记录。
10. `GET /api/login-logs`（需登录）返回 `{ items, total, page, pageSize }`；支持 `username`、`startTime`、`endTime` 筛选；按登录时间倒序。
11. 前端 `/users`：列表可搜索/筛选/分页，可新增（抽屉）、编辑（抽屉）、启停、重置密码、进入详情；详情页可正常展示与返回列表；禁用用户的标签为红色、启用为绿色。
12. 前端 `/login-logs`：可从侧边菜单进入；列表展示登录记录，支持登录名与登录时间范围筛选、分页；无匹配结果时显示空状态。
13. `cd frontend && npm run build`、`npm run lint` 通过；`npm run test:e2e` 通过（含用户管理与登录日志用例）。
14. 代码与 `AGENTS.md`、backend / frontend 专项规则一致（分层、命名、注释语言、统一响应与错误码）。
15. 新增 / 编辑抽屉打开时先重置表单，详情回填完成前字段不可编辑；详情接口较慢时编辑显示名仍能正确生效，不会被回填覆盖。

## 5. 范围外（不做）

- 用户注册入口。
- 角色 / 权限体系（RBAC）、菜单或按钮级权限。
- 用户自助修改密码、个人中心。
- 删除用户（含软删除 / 物理删除）——一律以禁用代替。
- 禁用后对**已签发 JWT** 的即时吊销（token 有效期内仍可用，本期不做黑名单 / 短周期校验）。
- 用户头像、部门、岗位等扩展属性。
- 邮箱 / 手机号的验证（不做验证码、不校验可达性，仅做格式与唯一性校验）。
- **登录失败 / 登出的日志记录**（本期只记录成功登录，故日志无"结果"字段）。
- **登录日志的修改 / 删除 / 导出、日志清理与归档策略**。
- **用户详情页内嵌该用户的登录记录**（本期用独立「登录日志」页，按登录名筛选）。
