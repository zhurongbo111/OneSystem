# 需求规格：日程与任务待办（oa-schedule-task）

> ERP 全域路线（`specs/ROADMAP.md` §4.2）**P10 办公协同**第二项（边界与决策见 `ROADMAP` §6.11）。
> 依赖：`028`（权限 / 默认拒绝）、`030`（员工档案：参与人 / 负责人）、`041`（站内信通道与定时宿主模式、去重台账）。
> 范围克制：只做**单次日程 / 会议**与**扁平任务待办**；不做周期性日程、会议室资源、外部日历同步、子任务 / 依赖、甘特图（见 §5）。

## 1. 背景

OA 协同的第二条主线是「人与时间 / 事项的协同」：`030` 已把「有哪些人」建好（员工档案 + 账号绑定），`041` 已把「怎么触达」建好（站内信 + 定时扫描宿主 + 去重台账），但**系统里没有任何「约一个会」「派一件事」的对象**——日程与任务只能口头或线下传递，无法在系统内跟踪完成情况。

本规格补两个业务对象：**日程 / 会议**（时间维度，参与人协作）与**任务待办**（事项维度，负责人跟踪），并复用 `041` 的提醒机制在临近时提醒。

## 2. 目标

1. **日程 / 会议**：标题 + 起止时间 + 地点 + 参与人（员工多选）+ 备注；创建人可编辑 / 取消；参与人与创建人可见。
2. **任务待办**：标题 + 负责人 + 协作人 + 截止日 + 优先级 + 状态 + 备注；负责人可推进状态；创建人可编辑 / 删除。
3. **到期提醒**：日程开始前、任务截止前经 `041` 的 `INotificationWriter` 发站内信（复用 `041` 的定时宿主与去重台账模式），**去重保证同一对象同一日只提醒一次**。
4. **我的视图**：日程列表支持「我参与的」筛选；任务列表支持「我负责的 / 我创建的」筛选。
5. **前端**：日程列表（时间范围筛选）+ 任务列表（负责人 / 状态 / 截止日筛选）；菜单「办公 → 日程」「办公 → 任务」。
6. **e2e 覆盖**新建日程 → 参与人可见、新建任务 → 推进状态 → 完成的完整路径。

## 3. 功能点

- **F1 日程管理**：`GET/POST/PUT /api/schedules*` + `POST .../{id}/cancel`；参与人为员工集合（至少一项）；创建人可编辑 / 取消。
- **F2 任务管理**：`GET/POST/PUT/DELETE /api/tasks*` + `POST .../{id}/status`；状态白名单 `Todo → InProgress → Done`、任意非终态 `→ Cancelled`。
- **F3 可见性**：日程仅创建人 + 参与人可见（其他人详情 `40300`）；任务对所有具备 `tasks.view` 的用户可见（协作性质，不裁剪）。
- **F4 到期提醒**：`OaReminderScanner` 扫描「未来 `RemindLeadDays` 天内开始 / 到期」的日程与任务，向参与人 / 负责人发站内信（`NotificationType.ScheduleReminder = 7` / `TaskDue = 8`，实现时续行 `041` §2.1）；去重台账复用 `041` 的 `AlertRecords`（扩 `AlertType`，实现时续行 `041` §2.3）。
- **F5 前端**：`views/ScheduleTaskManagement/`（日程列表 / 详情 / 抽屉表单 + 任务列表 / 抽屉表单）、`api/schedule.ts` / `api/task.ts`。
- **F6 e2e**：新增 `e2e/schedule-task.spec.ts`。

## 4. 验收标准

1. `cd backend && dotnet build` / `dotnet test` 通过（状态白名单、归属判据、可见性、提醒扫描与去重、发信失败降级）。
2. `cd frontend && npm run type-check` / `npm run lint` / `npm run build` 全绿；`npm run e2e:run` 全量通过（新增 `schedule-task.spec.ts`）。
3. 手工验证：
   - 创建日程并选参与人 → 参与人登录后可在「我参与的」中看到，非参与人访问详情 → `40300`；
   - 创建任务指派负责人 → 负责人可推进状态至「已完成」，再编辑 → `40203`；
   - 触发一次提醒扫描 → 参与人 / 负责人在铃铛收到提醒，同日重复扫描不重复发信。
4. 口径单一：日程 / 任务状态取值、可见性与归属判据、提醒口径只在 `design.md` §0 定义一次。
5. 联动（实现时）：`041` §2.1 续行 `NotificationType` 7 / 8、§2.3 续行 `AlertType` 3 / 4（附演进指针）；`028` §0.2 续行 `schedules.*` / `tasks.*`；`029` §0.1 续行资源 `Schedule` / `TodoTask`。

## 5. 范围外（不做）

- **周期性日程**（RRULE / 每周例会）：首期只做单次日程。
- **会议室 / 车辆等资源占用与冲突检测**：不建资源台账。
- **外部日历同步**（CalDAV / Exchange / 企业微信日程）：不做。
- **子任务 / 任务依赖 / 甘特图**：任务为扁平结构。
- **日程邀请回执**（接受 / 拒绝 / 待定）：参与人为直接指派，无 RSVP 状态。
- **附件与评论**：不做。
- **流程化任务**（任务 → 审批链）：任务状态为手工推进，不接 `042`。
