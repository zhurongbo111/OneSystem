# 需求规格：总账（erp-general-ledger）

> ERP 全域路线（`specs/ROADMAP.md` §4.2）**P2 财务闭环**核心项，**"进销存 → ERP"的分水岭**。
> 依赖：`031`（会计科目 / 税率）、`015` / `016` / `021` / `022` / `023`（单据 → 自动凭证）、`026`（成本 → 销售成本结转）。
> 本规格**改造既有单据写入路径**（生效 / 作废时同事务生成 / 作废凭证），改造面与 `026` 同级。

## 1. 背景

`023`（应收应付）、`026`（成本）已把「单据 → 资金 / 成本」打通，但**没有任何会计账簿**：

- 采购、销售、退货、收付款只产生**业务金额**，没有**借贷分录**、没有**科目余额**，出不了资产负债表 / 利润表——这是"进销存"与"完整 ERP"之间最关键的一道缺口（`ROADMAP` §5 原把"财务级账务"列为范围外，`2026-09-20` 升级 ERP 时翻案进入 P2）。
- 老板 / 财务需要"这个月的收入、成本、利润、资产负债状况"，现在只能靠 `025` 的经营报表间接推断。

本规格建立**总账**：会计期间、记账凭证（**从单据自动生成** + 手工录入）、科目余额表与三大报表中的**资产负债表 / 利润表**。

## 2. 目标

1. **会计期间**：按「年-月」维护期间，支持**结账 / 反结账**；已结账期间禁止新增 / 作废凭证。
2. **自动凭证**：采购入库、销售出库、采购退货、销售退货、收款、付款 **6 类单据**在生效 / 作废时**同一事务**生成 / 作废凭证（按凭证模板，见 `design.md` §0.2）；销售出库自动**结转销售成本**（取 `026` 流水成本）。
3. **手工凭证**：手工录入借贷分录，**借贷必须平衡**；分录科目须为**末级且启用**。
4. **科目映射配置**：维护"业务事件 → 会计科目"的映射（存货 / 应收 / 应付 / 收入 / 成本 / 现金 / 银行 / 本年利润），自动凭证按映射取科目；**缺失映射拒绝生成**（`40158`）。
5. **科目余额表**：按期间输出各科目期初 / 本期借贷发生额 / 期末余额。
6. **财务报表**：**资产负债表**（资产 = 负债 + 权益）与**利润表**（损益类科目本期发生额）；现金流量表**不做**（见 §5）。
7. **权限与菜单**：权限点续行至 `028` §0.2（`vouchers.*` / `financialReports.view`）；菜单续行至 `025` §0.2「财务」分组。
8. **前端**：凭证列表 / 新建（手工）/ 详情、科目余额表与财务报表（tab）页面。

## 3. 功能点

- **F1 会计期间**：`GET /api/accounting-periods`；`POST /api/accounting-periods/close`（结账）、`/reverse`（反结账）；期间不存在时禁止记账（`40159`）；已结账期间禁止记账（`40154`）。
- **F2 凭证查询**：`GET /api/vouchers`（按期间 / 来源类型 / 关键词（凭证号 / 摘要）筛选 + 分页）；`GET /api/vouchers/{id}`（含分录）。
- **F3 手工凭证**：`POST /api/vouchers`（借贷平衡校验 `40155`、至少一条分录 `40156`、科目末级且启用 `40157`）。
- **F4 凭证作废**：`PUT /api/vouchers/{id}/void`；**自动凭证随来源单据作废**（同事务）。
- **F5 自动凭证**：`015` / `016` / `021` / `022` / `023` 的 `Create*` / `Void*` 在既有事务内追加凭证生成 / 作废（§`design` §0.2 模板）。
- **F6 科目映射**：`GET` / `PUT /api/account-mappings`（键 → 科目）；种子预置到 `031` 预置科目。
- **F7 科目余额表**：`GET /api/reports/account-balance`（按期间）。
- **F8 资产负债表 / 利润表**：`GET /api/reports/balance-sheet`、`/api/reports/income-statement`（按期间）。
- **F9 权限与菜单**：§0 续行 `028` / `025`。
- **F10 e2e 覆盖**：开采购 / 销售单 → 凭证自动生成且借贷平衡 → 科目余额与毛利一致；手工凭证不平 `40155`；结账后禁记账 `40154`；作废单据 → 凭证作废、余额回退。

## 4. 验收标准

1. `cd backend && dotnet build` / `dotnet test` 通过（凭证模板、借贷平衡、期间控制、自动 / 作废、映射缺失、余额与报表口径等单测）。
2. `cd frontend && npm run type-check` / `npm run lint` / `npm run build` 全绿；`npm run test:e2e` 全量通过（新增 `general-ledger.spec.ts` + 既有单据用例回归）。
3. 手工验证（核心语义）：
   - 采购入库 1000（应付账款 / 库存商品）→ 生成凭证「借 库存商品 1000 / 贷 应付账款 1000」；应付账款余额 +1000。
   - 销售出库 1500、成本 900 → 生成「借 应收账款 1500 / 贷 主营业务收入 1500」+「借 主营业务成本 900 / 贷 库存商品 900」；利润表毛利 600，与 `026` 报表一致。
   - 收款 500 → 「借 银行存款 500 / 贷 应收账款 500」。
   - 作废采购入库单 → 原凭证作废、应付账款余额回退。
4. 平衡与期间：手工凭证借方 ≠ 贷方 → `40155`；科目非末级 / 已停用 → `40157`；已结账期间新增凭证 → `40154`；未映射科目 → `40158`。
5. 报表：资产 = 负债 + 权益（单测恒等式守护，允许"本年利润"未结转的差额以"本年利润"列示闭合）；利润表收入 − 成本 = 毛利（与 `026` `GetCostProfitReport` 同源口径）。
6. 口径单一：凭证模板、科目映射键、余额与报表取数规则只在 `design.md` §0 定义一次；自动凭证与手工凭证共用同一套借贷平衡校验。
7. 联动：`015` / `016` / `021` / `022` / `023` / `026` 的 `design.md` 加「演进（erp-general-ledger）」注记（生效时点追加凭证）。

## 5. 范围外（不做）

- **现金流量表**：需要「现金 / 现金等价物流量」的科目与业务标注，另行评估。
- **合并报表 / 多组织核算 / 多账套**：单主体、单账套（`ROADMAP` §7）。
- **多币种 / 外币折算**：单币种（人民币）。
- **税务申报 / 发票生成凭证**：`032` 发票只到登记（`032` §5）；发票与凭证的联动另行评估。
- **历史单据凭证补录**：从总账上线日起记账；上线前的历史单据**不补生成**凭证（如需补录另行评估）。
- **辅助核算**（部门 / 项目 / 往来 / 商品辅助项）：分录为纯科目 + 金额。
- **凭证的草稿 / 审核 / 复核流程**：凭证生成 / 录入即过账，仅支持作废（复核流程随 `042` 审批路线另行评估）。
- **期末自动结转损益的自动化**：一期以手工凭证 + 报表取数（"本年利润"列示）处理，不做"一键结转"。
- **报表项目自定义映射**：资产负债表 / 利润表按科目类别与一级科目直接列示（§`design` §0.4），不做可配置映射表。
- **预算 / 固定资产 / 费用报销**：`ROADMAP` §7 范围外。
- **凭证附件 / 影像**：不做文件存储。
