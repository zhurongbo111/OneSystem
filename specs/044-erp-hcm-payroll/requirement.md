# 需求规格：考勤与薪酬（erp-hcm-payroll）

> ERP 全域路线（`specs/ROADMAP.md` §4.2）**P6 外围增强**项；HCM 并入主线的**第二阶段**（`ROADMAP` §1「组织 · 岗位 · 员工先行；考勤 · 薪酬后置」）。
> 依赖：`030-erp-org-employee`（员工档案 —— 考勤 / 薪酬的对象）。
> 范围克制：做**考勤登记（请假 / 加班）+ 月度工资单（简单核算）**；**不做**打卡排班、个税 / 社保、招聘 / 绩效。

## 1. 背景

`030` 建立了员工档案（组织 / 岗位 / 员工），但**没有"人在组织里的时间与报酬"**：

- 请假 / 加班无处登记，考勤靠线下表格。
- 工资靠 Excel 算，每月重复劳动，且无法与员工档案关联。

本规格补上 HCM 的两块基础能力：**考勤登记**与**月度工资单**，口径从简（不做复杂薪资规则）。

## 2. 目标

1. **考勤登记**：员工**请假 / 加班**记录的登记与查询（类型 / 起止日期 / 备注）；不做审批、不做打卡。
2. **月度工资单**：按「员工 + 年月」维护工资单（基本工资 / 津贴 / 扣款 / 实发），支持**批量生成**（按在职员工生成草稿）、编辑、**发放**（发放后锁定）。
3. **员工关联**：两者均以 `030` 的员工为主体；离职员工不参与批量生成。
4. **权限与菜单**：权限点续行至 `028` §0.2（`attendance.*` / `payroll.*`）；新建「人事」菜单分组（`025` §0.2 续行），`030` 的组织 / 员工菜单可一并迁入。
5. **前端**：考勤页（列表 + 抽屉）、薪酬页（列表 + 抽屉 + 批量生成 + 发放）。
6. **e2e 覆盖**。

## 3. 功能点

- **F1 考勤登记**：`GET /api/attendances`（按员工 / 类型 / 日期范围筛选 + 分页）；新增 / 编辑 / 删除；同一员工同一日期的同类记录不重复（`Validator` 校验）；离职员工不可新登记。
- **F2 工资单列表 / 编辑**：`GET /api/payrolls`（按期间 / 员工 / 状态筛选 + 分页）；新增 / 编辑（仅草稿）；`NetPay = BaseSalary + Allowance − Deduction`（后端计算）。
- **F3 批量生成**：`POST /api/payrolls/generate?year=&month=`（为在职员工生成草稿；已存在则跳过并计数返回）。
- **F4 发放**：`PUT /api/payrolls/{id}/status`（草稿 → 已发放；发放后锁定，`40171`）；已发放不可删除。
- **F5 权限与菜单**：§0 续行 `028` / `025`（新建「人事」分组）。
- **F6 e2e**：登记请假 / 加班 → 批量生成当月工资单 → 编辑实发 → 发放 → 再改 `40171`。

## 4. 验收标准

1. `cd backend && dotnet build` / `dotnet test` 通过（考勤校验 / 唯一性、工资单核算 / 批量生成 / 发放锁定等单测）。
2. `cd frontend && npm run type-check` / `npm run lint` / `npm run build` 全绿；`npm run test:e2e` 全量通过（新增 `hcm-payroll.spec.ts`）。
3. 手工验证：
   - 为空员工登记请假 2026-09-21～09-22；同员工同日重复登记被拒。
   - 批量生成 2026-09 工资单（在职员工各一条草稿；重复生成不产生重复，返回跳过数）；编辑某条基本工资 / 津贴 / 扣款 → 实发自动重算。
   - 发放后修改 → `40171`；删除已发放 → 拒绝。
4. 口径单一：考勤类型 / 工资单状态取值、实发计算公式、期间唯一性只在 `design.md` §0 定义一次。
5. 联动：`028` §0.2 / `025` §0.2 续行（新增「人事」分组）；`030` `design.md` 注记菜单迁入「人事」。

## 5. 范围外（不做）

- **打卡 / 排班 / 考勤机对接**：只做请假 / 加班**登记**，不做打卡与排班。
- **个税 / 社保 / 公积金 / 专项附加扣除**：工资单只做「基本 + 津贴 − 扣款」的简化核算（扣款项由人工填写，不自动计税）。
- **工资条发放 / 银行代发 / 工资密码**：不做。
- **薪资结构 / 薪级 / 职级 / 多套薪资方案**：单条工资单手工填写金额。
- **招聘 / 绩效 / 培训 / 员工自助**：`ROADMAP` 未纳入或后续评估。
- **考勤与薪酬的自动联动**（按考勤扣薪）：本期两者独立，不做自动计算。
- **薪酬的审批流程**：随 `042` 审批路线另行评估。
- **工资单导出**：一期不做（如需复用 `027` 另评）。
- **多法人 / 多地区社保政策**：单主体（`ROADMAP` §7）。
