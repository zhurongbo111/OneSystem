# 需求规格：仓库调拨（erp-transfer）

> 进销存扩展路线（`specs/ROADMAP.md`）P4 库存精细化 第二项，依赖 `038-erp-multi-warehouse`（仓维度）。
> **范围提示**：路线图原文为「调拨单（转出仓 → 转入仓，**含在途**）」。本规格一期只做**一步式调拨**（转出即转入、无在途），在途列为范围外并说明演进路径，**如需一期含在途请回改需求**（见 §5 与 `design.md` §5 决策）。

## 1. 背景

`038` 让库存按仓分开后，立即出现「仓与仓之间搬货」的日常需求（总仓补货到门店、A 仓调货支援 B 仓）。现状没有调拨单，只能用两种变通做法，都很糟：

- **盘点变通**：A 仓盘亏、B 仓盘盈，开两张盘点单。账实过程不连续（一次搬货拆成两张互不相关的凭证），盘点单的语义（账实差异）也被污染。
- **作废重开**：把 A 仓的入库单作废、在 B 仓重开。彻底抹掉原始业务事实，供应商与金额口径一起失真。

需要一张**调拨单**作为凭证：一次操作，转出仓减少、转入仓增加，可查、可作废、可追溯成本。

## 2. 目标

1. **调拨单**：选择转出仓 + 转入仓 + 商品明细（数量）→ 保存即生效（**转出仓减、转入仓增**，同一事务）。
2. **数量守恒**：一次调拨的转出数量合计 == 转入数量合计（同商品逐行守恒，不产生损耗口径；损耗走盘点）。
3. **库存约束**：转出仓库存不足则整单拒绝（`40103`，message 含仓名）；转入仓无上限。
4. **成本不丢**：按转出仓出库时的成本单价（`026` 组织级移动加权均价）同步结转至转入仓，**组织级成本总额与均价不变**（调拨是组织内移动，不该改变成本）。
5. **流水可追溯**：每行产生两条流水（转出仓 `TransferOut` 负、转入仓 `TransferIn` 正，成本单价相同）；作废产生两条反向流水。
6. **可作废**：一步式单据，不可编辑；作废回冲（转入仓减、转出仓增），与采购 / 销售作废对称。
7. **前端**：调拨列表（单号 / 转出仓 / 转入仓 / 日期筛选 + 分页）、开单页（双仓选择 + 明细带批次 / 库存展示）、详情页（含作废）。

## 3. 功能点

- **F1 数据模型**：`Transfers` / `TransferItems`（字段见 `design.md` §2），单号 `TR + yyyyMMdd + 4`；明细存商品编码 / 名称 / 单位快照。
- **F2 用例**：`GetTransfers` / `CreateTransfer`（转出仓扣减 → 转入仓增加 → 双流水，同一事务）/ `GetTransferById` / `VoidTransfer`（反向回冲 + 反向流水）。
- **F3 流水类型**：`StockMovementType` 追加 `TransferOut = 11`（转出，负）/ `TransferIn = 12`（转入，正），文案与颜色在 `019` §0 续行。
- **F4 前端**：「调拨单」页（`/transfers` 列表 + `/transfers/new` 开单 + `/transfers/detail/:id` 详情，含作废），归「库存」分组（`025` §0.2 总表已预留）。
- **F5 校验**：转出仓 ≠ 转入仓（`40126`）；两仓均需存在且启用（`40400` / `40123`）；明细非空、商品启用、数量 ≥ 1。
- **F6 e2e 覆盖**：调拨 5 件 → A 仓 −5、B 仓 +5（库存查询按仓验证）、流水出现 `-5`「调拨转出」与 `+5`「调拨转入」；作废 → 双仓回冲；A 仓不足 / 同仓调拨被拒。

## 4. 验收标准

1. `cd backend && dotnet build` / `dotnet test` 通过（含调拨用例的成功 / 不足 / 同仓 / 停用仓 / 作废回冲 / 双流水的单测与事务回滚断言）。
2. `cd frontend && npm run type-check` / `npm run lint` / `npm run build` 全绿；`npm run test:e2e` 全量通过（含新增 `transfer.spec.ts` 与既有用例回归）。
3. 手工验证：
   - A 仓 100、B 仓 20；调拨 A → B 30 → A 70、B 50；组织级总库存不变（120）。
   - 同一调拨的明细数量守恒（调入合计 == 调出合计）。
   - A（100）→ B 调拨 150 → 拒绝（`40103` 含「A 仓」），两仓库存均无变化、单据未落库。
   - 作废该调拨 → A 100、B 20 复原；流水出现 `+30`「调拨转出作废」与 `-30`「调拨转入作废」（名称见 `019` §0 续行）。
4. 成本口径：调拨前后**组织级** `Σ 流水 TotalCost == Inventory.CostAmount` 不变；转出与转入两条流水的 `UnitCost` 相同（`026` §0.1 口径不变）。
5. 对账口径：任一「商品 × 仓」满足 `Σ 流水 Quantity == Inventory.Quantity`（`038` 口径的回归）。
6. 口径单一：调拨的仓库维度引用 `038` §0；成本结转引用 `026` §0.1；流水类型文案在 `019` §0 续行；本规格不重复定义。

## 5. 范围外（不做）

- **在途 / 两段式调拨**（发出 → 在途 → 收到，含在途数量与两次确认）：路线图原文含「在途」，一期不做。理由：在途需要在单据上加状态机与「已发出未到达」的数量口径，与 `024-erp-order-flow` 的两段式单据属同一类能力，宜共用模板；**如需一期含在途，请回改本需求**（`design.md` §5 记录演进路径：`Transfers` 加 `Status`（待收货 / 部分收货 / 已完成）与出入库两条单据）。
- **跨仓损耗 / 差异处理**：调拨不产生损耗（数量守恒）；损耗走 `020` 盘点。
- **调拨定价 / 内部结算价**：调拨按成本结转（`026` 组织级均价），不做内部转移定价与内部利润核算。
- **按仓成本（分仓均价）**：`038` §5 已定成本为组织级；调拨因此不影响均价。
- **调拨申请与审批**：`042-erp-approval`（如需大额调拨审批，纳入其规则范围）。
- **批量调拨 / 一单多转出仓**：一张调拨单只有一对「转出仓 → 转入仓」。
- **调拨在途预警 / 超期未达提醒**：随在途能力一起评估（`041` 只做库存预警）。
- **导出与打印**：`027` 已提供导出能力，调拨页在其导出范围表内续行（`027` §0.2 由本规格落地时续行）。
