# 需求规格：期初建账与库存盘点（erp-stock-take）

> 本规格是进销存扩展路线（`specs/ROADMAP.md`）已完成（账务地基），依赖 `019-erp-stock-movement` 的流水落账。

## 1. 背景

现状库存**只能被单据改动**，于是有两个业务空洞：

- **开账无门**：`012-erp-product` 明确「首期库存经采购单建立，不做期初建账」——上线时若仓库里已有存货，只能开一张假采购单把它「买」进来，既污染采购数据也污染供应商往来。
- **账实不符无处修正**：漏记、错发、损耗、退回未记录等造成的差异，系统没有任何修正手段；作废回冲只针对某张单据本身，不能表达「现在实际就是 7 件，账面 10 件」。

`019` 已让每次库存变动可追溯（谁、何时、因何单、变动多少），因此「人工调整库存」这件事可以引入而不破坏审计：任何调整都会留下一条流水。

## 2. 目标

1. **期初建账**：为商品录入开账数量，写「期初建账」流水；仅允许**从未发生过库存变动**的商品建账，防止覆盖既有业务数据。
2. **库存盘点**：录入实盘数量，提交后按差异调整库存并写「盘点调整」流水；盘点单与明细可查询、可查看。
3. 盘点单**一步式提交**（保存即生效、不可编辑、不可作废，纠错靠再盘一次），与既有单据域一致。
4. **只有差异行产生库存变动与流水**；实盘等于账面的明细行只留盘点记录，不产生流水噪音。
5. 差异由**后端重算**（提交时读取账面数量），前端带出的账面值仅供录入参考。

## 3. 功能点

- F1 新增 `StockTakes` / `StockTakeItems` 表（字段见 `design.md` §2），单据含类型（期初建账 / 盘点）。
- F2 商品选择接口 `GET /api/stock-takes/pick-products`：返回启用商品 + 当前库存 + **是否已建账 / 已有库存变动**（供期初模式标注与过滤）。
- F3 新建盘点 `POST /api/stock-takes`：校验明细非空、商品存在且启用、期初模式商品未发生变动；提交时后端读账面 → 重算差异 → 逐差异行改库存并写流水 → 落单与明细（同一事务）。
- F4 盘点单列表 `GET /api/stock-takes`（单号关键词 / 类型 / 日期范围筛选 + 服务端分页）与详情 `GET /api/stock-takes/{id}`。
- F5 前端「库存盘点」页（`/stock-takes`）：列表 + 新建页（类型选择：盘点 / 期初建账；明细子表格录入实盘数量、实时展示差异）+ 详情页（含账面 / 实盘 / 差异明细）。
- F6 库存流水（`019`）新增两种变动类型：期初建账、盘点调整（文案与颜色在 `019` design §0 表内续行）。
- F7 e2e 覆盖：期初建账 → 库存与「期初建账」流水；盘点差异 → 库存按差异变化且「盘点调整」流水方向正确；无差异盘点不产生流水；期初选到已建账商品被拒。

## 4. 验收标准

1. `cd backend && dotnet build` / `dotnet test` 通过（含 `CreateStockTake` / `GetStockTakes` / `GetStockTakeById` / `GetStockTakePickProducts` 用例与差异重算、事务回滚断言）。
2. `cd frontend && npm run type-check` / `npm run lint` / `npm run build` 全绿。
3. `cd frontend && npm run test:e2e` 全量通过（含新增 `stock-take.spec.ts` 与采购 / 销售 / 库存 / 流水既有用例回归）。
4. 手工验证：
   - 期初建账：选一个从未有库存变动的商品，录入期初数量 100 → 库存为 100，流水出现一条 `+100`「期初建账」；再对该商品建一次期初 → 被拒绝（提示商品已有库存变动）。
   - 盘点差异：某商品账面 100，实盘 96 → 提交后库存 96，流水出现 `-4`「盘点调整」；实盘 100 的行不产生流水。
   - 盘点单列表 / 详情的类型、明细行数、差异行数、明细快照（编码 / 名称 / 单位 / 账面 / 实盘 / 差异）展示正确。
5. 对账口径仍成立：任一商品 `Σ 流水变动量 == Inventory.Quantity`（含期初与盘点调整后）。
6. 事务性：提交盘点过程中任一环节失败（如商品停用、期初校验失败）时，**库存与流水均无变化**，且不落单据（单测覆盖 `RollbackAsync`）。

## 5. 范围外（不做）

- **循环盘点计划 / 定时盘点任务**、盘点差异审批：属 `042-erp-approval` 与后续运营能力。
- **分仓盘点**：多仓见 `038-erp-multi-warehouse`（届时盘点单需带仓库维度）。
- **条码 / 手持设备盘点、导入盘点表**：`027-erp-export` 仅做导出 / 打印，不反向导入。
- **盘点单作废与编辑**：一步式单据，纠错靠再盘。
- **库存成本影响调整**：本规格只调整数量；成本核算见 `026-erp-cost`。
- **不开放「直接改库存」的任意调整入口**：所有调整必须经盘点单（带凭证与表头信息），杜绝无凭证改库存。
