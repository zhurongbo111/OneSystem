# 需求规格：商品分类管理页（erp-category）

## 1. 背景

商品分类的维护入口原是商品管理页内的「分类管理」弹窗（erp-product 的 `CategoryManagerModal`）。分类数量增多后，弹窗内承载「列表 + 新增 + 编辑 + 删除」信息密度过大、不便管理。将分类维护升级为独立页面，放入侧边栏「进销存」菜单分组。

本规格包含**后端接口新增**：为分类管理页提供分页查询接口 `GET /api/categories/paged`（搜索 + 分页，参照商品列表 `GET /api/products` 模式）。既有全量接口 `GET /api/categories` 保留不动，继续服务商品页分类下拉筛选与商品抽屉分类选择。

## 2. 目标

1. 提供「分类管理」独立页面：侧边菜单「进销存 → 分类管理」；搜索（名称模糊）/ 分页 / 新增 / 编辑（抽屉）/ 删除；被商品引用的分类删除拦截（40106 统一错误提示）。
2. 后端新增分类分页查询接口（关键词 + 分页，创建时间正序），错误码与既有分类接口一致（40105 / 40106 不变）。
3. 商品域联动调整：商品管理页工具条「分类管理」按钮跳转分类管理页；商品新增 / 编辑抽屉的「新建分类」就地行内输入新增；删除 `CategoryManagerModal.vue` 组件。

## 3. 功能点

- **F1 分类管理页**（路由 `categories`，菜单「进销存」分组「商品管理」之后）：
  - 搜索：按分类名称模糊匹配（关键词，点「搜索」或回车生效，「重置」清空）；
  - 分页：服务端分页（`page` / `pageSize`，默认 20，可选 10 / 20 / 50），创建时间正序；
  - 新增：筛选行行内输入 + 「新增」按钮（回车支持，成功后清空输入并回到第 1 页重新拉取）；
  - 编辑：操作列「编辑」打开抽屉（`CategoryFormDrawer`，名称 1-20 字符，成功刷新列表）；
  - 删除：`a-popconfirm` 确认；被商品引用时后端 40106 统一错误提示；
  - 刷新：重新拉取当前页。
- **F2 商品域入口调整**：商品管理页工具条原「分类管理」（打开弹窗）按钮改为跳转分类管理页；商品新增 / 编辑抽屉「新建分类」就地行内新增（成功后刷新下拉并选中新分类）；删除 `CategoryManagerModal.vue` 组件及其全部引用。
- **F3 既有能力保持**：分类名称唯一（重名 40105 统一错误提示）；删除有引用拦截（40106）；商品新增时「就地新建分类」的可用性与回填行为不变；`GET /api/categories` 全量接口行为不变（下拉数据源）。

## 4. 验收标准

1. 侧边菜单「进销存」分组出现「分类管理」子项（「商品管理」之后），点击进入 `/categories` 页，页面高亮正确。
2. 新增成功入列表（回到第 1 页可见）并清空输入（重名提示 40105 message）；抽屉编辑改名生效（重名提示 40105）；删除确认后移除（有引用提示 40106 message）。
3. 搜索：名称模糊匹配生效（命中行可见、未命中行不可见），重置后恢复全量；分页：跨页数据正确、翻页 / 改每页条数生效、序号跨页连续。
4. 商品管理页工具条「分类管理」按钮跳转 `/categories`；原分类管理弹窗不再渲染。
5. 商品抽屉「新建分类」就地新增可用：新分类出现于下拉并被选中，商品提交成功（e2e 覆盖）。
6. `cd backend && dotnet build` / `dotnet test` 通过；`cd frontend && npm run lint` / `npm run type-check` / `npm run build` / `npm run test:e2e` 通过（含分类管理页用例与商品管理回归用例）。

## 5. 范围外（不做）

- 分类排序（除创建时间正序）、备注、多级分类、停用状态。
- 既有分类写接口（POST / PUT / DELETE）与全量查询接口 `GET /api/categories` 的任何行为变更。
