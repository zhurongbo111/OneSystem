# 需求规格：批次与保质期管理（erp-batch-expiry）

> 进销存扩展路线（`specs/ROADMAP.md`）P4 库存精细化 第三项，依赖 `038-erp-multi-warehouse`（库存维度）。
> **范围提示**：路线图原文为「批次 / 保质期 / **序列号**管理」。本规格做**批次 + 保质期**；序列号（逐件生命周期）列为范围外并说明理由（见 §5），**如需一期含序列号请回改需求**。

## 1. 背景

食品、药品、化工、农资等行业，同一商品不同生产批次的**到期日不同**，必须按批次管理：

- **现状无批次**：库存只有「商品 × 仓」一个维度，同一商品不同批次的货混在一起。一旦发生质量问题需要召回，无法定位「哪一批、卖给了谁」；也无法回答「这批什么时候到期」。
- **过期无拦截**：出库不校验到期日，可能把过期品发给客户（合规风险）。
- **先进先出无从落地**：想按到期日先出（FEFO）也没有批次数据可依据。

`038` 已把库存维度升级为 `(商品, 仓)`，本规格在同一位置再加一维 `批次`（可空），使「不分批次商品」与「按批次商品」在同一套结构里共存，**不破坏既有单据与流水**。

## 2. 目标

1. **商品级开关**：商品档案新增「按批次管理」；关闭的商品行为与现状**完全一致**（`BatchId` 为空）。
2. **批次档案**：批次 = 商品 + 批次号（同商品内唯一）+ 生产日期（可空）+ 到期日（可空）+ 备注；批次**不删除**（保留历史凭证引用），可停用（停用后不可再用于新单）。
3. **库存按批次**：`Inventory` 增加 `BatchId`（可空）；按批次商品的库存行按 `(商品, 仓, 批次)` 拆分，数量与库存在同一维度上读写。
4. **单据带批次**：采购入库（选批次或就地新建）、销售出库（选批次）、采购退货（选批次）、销售退货（选批次或新建）、盘点（按批次行）；**按批次商品的明细行必须指定批次**（`40127`）。
5. **过期拦截**：出库类（销售出库 / 采购退货）**禁止使用已过期批次**（`40128`，日期粒度：到期日当天仍可用，次日起过期）；入库类不限制。
6. **近效期可见**：批次列表与批次选择下拉标注「近效期（≤ 30 天）」与「已过期」，按到期日升序排列，便于人工按 FEFO 选择。
7. **前端**：批次管理页（列表 / 新增 / 编辑 / 停用）；商品抽屉「按批次管理」开关；各开单页明细「批次」列（含就地新建与可用库存展示）；库存查询页「展开批次」视图；盘点按批次录入。

## 3. 功能点

- **F1 数据模型**：`Products.IsBatchManaged`；`Batches` 表；`Inventory.BatchId`（可空 + 部分唯一索引）；`StockMovements.BatchId`；五类单据明细的 `BatchId` / `BatchNo` 快照（字段见 `design.md` §2）。
- **F2 用例**：`GetBatches`（列表：商品 / 批次号 / 状态筛选 + 分页）/ `CreateBatch` / `GetBatchById` / `UpdateBatch` / `UpdateBatchStatus` / `GetBatchPickList`（按商品 + 仓返回可用批次，按到期日升序、含过期标记与可用库存）。
- **F3 库存与单据改造**：`IInventoryRepository` 全部方法追加 `Guid? batchId`；五类单据的创建 / 作废用例按批次读写（流水带批次）。
- **F4 过期与近效期判定**：`ExpiryDate < 今天` → 已过期（出库拒绝）；`ExpiryDate <= 今天 + 30 天` → 近效期（提示）；常量 `BatchFieldConstraints.NearExpiryDays = 30`（唯一来源）。
- **F5 前端**：批次管理页（`/batches`，归「库存」分组）；商品抽屉开关；五类开单页批次列（含就地新建 Modal）；库存查询「展开批次」；库存流水批次列。
- **F6 e2e 覆盖**：开启批次的商品入库两个批次 → 库存按批次显示两行；销售出库选批次 1 → 只有批次 1 减少；选过期批次被拒（`40128`）；按批次商品未选批次被拒（`40127`）；批次列表近效期 / 过期标签正确。

## 4. 验收标准

1. `cd backend && dotnet build` / `dotnet test` 通过（含批次用例、库存按批次、单据必填 / 过期校验、流水带批次、对账口径等单测）。
2. `cd frontend && npm run type-check` / `npm run lint` / `npm run build` 全绿；`npm run test:e2e` 全量通过（既有各域 spec 需回归：新的「批次」列在非批次商品下为 `-`）。
3. **不分批次商品零影响**：未开启按批次管理的商品，库存 / 单据 / 流水行为与 `038` 完全一致（`BatchId` 为空），既有 e2e 全绿。
4. 手工验证：
   - 商品 A 开启按批次；采购入库 2 个批次（B1 到期 2026-12-31、B2 到期 2026-10-01）各 10 件 → 库存查询展开批次显示两行；批次下拉按到期日升序（B2 在前）。
   - 销售出库选 B1 → 仅 B1 减 3（B2 不变）；流水两条信息含批次号。
   - 选 B2（已过期，设为昨天到期）出库 → 拒绝（`40128`，提示含批次号与到期日）。
   - 按批次商品未选批次 → 拒绝（`40127`）。
   - 采购退货选批次 → 该批次减少；销售退货选批次 → 该批次增加。
5. 对账口径：任一「商品 × 仓 × 批次」满足 `Σ 流水 Quantity == Inventory.Quantity`；按仓 / 组织级汇总口径仍成立（`038` / `026` 回归）。
6. 成本口径不变：成本仍为组织级移动加权平均（`026` §0.1），**不做批次成本**；调拨结转（`039`）按商品均价（分支次时按行批次数量，单价仍取商品均价）。

## 5. 范围外（不做）

- **序列号管理**（逐件唯一码、全生命周期追溯、串号出库核对）：路线图原文含序列号；序列号是**逐件**粒度（一件一码、需要出入库逐码核对与全链路追溯），与批次的数量粒度是两套模型，宜独立规格；**如需一期含序列号请回改需求**。
- **FEFO 自动分配（自动按到期日先出）**：一期由用户手工选批次，系统只做「按到期日升序排序 + 近效期 / 过期标注」辅助；自动分配需要出库策略配置与拆行逻辑，另行评估。
- **批次成本（分批次均价）**：成本仍为组织级移动加权平均（`026` §0.1）；按批次成本需分批次成本层，属独立能力。
- **质量状态与质检**（待检 / 合格 / 不合格 / 冻结）：批次只做「启用 / 停用」，不做质检流（属质量管理系统范畴）。
- **召回追溯报表**（批次 → 客户 / 供应商流向查询）：需与销售 / 采购单据双向追溯，数据基础本规格已具备，报表另立。
- **批次拆包 / 合并 / 分装**：不做（拆包等同盘点 + 新建批次，属作业层面）。
- **保质期到期预警通知（站内信 / 推送）**：`041-erp-stock-alert`（本规格只提供到期日与近效期标注）。
- **导入 / 批量建档**：`027` 只做导出；批量导入批次另行评估。
- **多批次的调拨拆分**：调拨（`039`）已按明细行支持批次（`TransferItem.BatchId`），但不做「一条明细自动拆多批次」的智能分配。
