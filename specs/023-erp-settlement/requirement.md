# 需求规格：收付款与应收应付（erp-settlement）

> 进销存扩展路线（`specs/ROADMAP.md`）已完成（单据与资金闭环）；本规格**改造既有单据的结算语义**（`015` / `016` / `021` / `022` 的 `SettlementStatus`），落地前先读本规格 §3 与各规格的演进注记。

## 1. 背景

现状单据的结算只是一个**手工状态位**（`OrderSettlementStatus` 0=未结算 / 1=已结算），由 `PUT /api/{单据}/{id}/settlement` 手工切换，`015` §5 已把它记为「MVP 简化，后续升级为已结算金额」。

这带来三个业务空洞：

- **无法表达部分结算**：客户先付 60%，单据要么「未结算」要么「已结算」，实际金额与欠款无从体现。
- **没有收付款凭证**：钱什么时候收的、走的什么方式、对应哪几张单，系统里没有记录；单据上的状态位无法追溯是谁在什么时候点的。
- **看不到往来余额**：无法回答「某客户还欠多少、某供应商我们还欠多少」。

`021` / `022` 的退货单也会冲减往来金额，同样需要一个统一的资金侧口径。

## 2. 目标

1. **单据结算升级**：`SettlementStatus`（0/1）替换为 `SettledAmount`（已结算金额），结算状态由金额与总额推导（未结 / 部分 / 结清），不再手工切换。
2. **收付款单**：一张收付款单可核销多张单据，支持部分核销；可作废（回退已结算金额）。
3. **核销方向约束**：收款单核销「销售出库单 / 采购退货单」（我们收钱），付款单核销「采购入库单 / 销售退货单」（我们付钱）；核销单据的往来单位必须与收付款单一致。**往来单位的档案类型不按收付款方向限制**：收款既可对客户（销售回款）也可对供应商（收回退货退款），付款同理；正确性由「核销单据的往来单位」隐含保证，不再单独按方向校验档案类型（原 `40109` 校验移除）。
4. **往来对账**：按往来单位聚合应收 / 应付余额与未结单据，可下钻查看未结清单据。**余额按被核销单据的未结金额归集**（不按收付款单类型拆分）：应收 = Σ 销售出库单未结 + Σ 采购退货单未结；应付 = Σ 采购入库单未结 + Σ 销售退货单未结。
5. **口径单一**：移除单据上的手工结算切换接口与按钮，所有结算变化都由收付款单核销驱动。
6. **作废与核销互斥**：单据一旦被核销（`SettledAmount > 0`）即**禁止作废**，必须先作废对应收付款单回退金额；避免出现「单据已作废、收付款单仍挂着核销」的悬空资金口径。
7. **业务类型派生，不新增字段**：收付款单的「具体业务类型」（销售回款 / 采购付款 / 收回退款 / 退出退款）由 `Type`（资金方向）+ 核销明细 `OrderType` 派生，**不新增主表字段**；一张单可混合核销（如「两者」类型往来的收款单同时核销销售出库单与采购退货单），业务类型按明细展开。

## 3. 功能点

- F1 四张单据表（`PurchaseOrders` / `SalesOrders` / `PurchaseReturns` / `SalesReturns`）的 `SettlementStatus` 列替换为 `SettledAmount`（`numeric(18,2)`，默认 0）；迁移时历史「已结算」单据按全额回填（见 `design.md` §2.4）。
- F2 新增 `Settlements` / `SettlementItems` 表：收付款单（类型 / 往来 / 日期 / 金额 / 方式 / 状态）+ 核销明细（单据类型 / 单号 / 单据日期 / 单据总额 / 本次核销金额，均为开单时快照）。主表**不新增**「业务类型」列（由 `Type` + 明细 `OrderType` 派生，见目标 7 / F8）。
- F3 新增用例：`GetSettlements`、`CreateSettlement`（校验方向与未结金额 → 累加各单据 `SettledAmount` → 落单）、`GetSettlementById`、`VoidSettlement`（回退已结算金额）、`GetUnsettledOrders`（按往来 + 方向返回可核销单据）、`GetReconciliation`（往来对账台账：按被核销单据未结金额归集应收 / 应付）。其中 `GetSettlements` 额外支持**按被核销单据反查**（可选 `orderType` + `orderId`，成对传入，复用同一端点与用例），并附带回该单据在每张收付款单上的**本次核销金额**。
- F4 前端「收付款」页（列表 / 新建 / 详情，含作废）与「往来对账」页（往来余额 + 未结单据下钻）；详情**核销明细**与对账**未结单据**的「单号」为超链接，可直达被核销单据详情。列表提供**「单据类型」列**（可选列，默认显示）：取该单核销明细的被核销单据类型**去重集合**（多值时以「、」连接，如「销售出库单、采购退货单」），由明细派生、**不落列**。
- F5 单据侧改造（采购 / 销售 / 采购退货 / 销售退货的前端与接口）：移除「标记已结算 / 改回未结算」操作，列表与详情改为展示**结算状态标签 + 未结金额**，并把操作位改为「去收付款」跳转（预置往来单位与方向；**仅在单据正常且未结算时显示**——已结算无未结金额、入口无效，部分结算仍显示可继续收付未结部分）；四类单据**详情新增只读「收付款明细」区块**（**单号超链接** → 收付款详情 / 方向 / 收付日期 / 本次核销金额 / 状态，已作废单置灰），单号即入口、可定位到具体收付款单。
- F6 e2e 覆盖：部分收款 → 单据显示「部分结算」与未结金额、台账减少；收满 → 「已结算」；作废收付款单 → 金额回退；方向不匹配 / 超额核销被拒；**单据详情「收付款明细」可见对应收付款单并跳转其详情**。
- F7 已核销单据禁止作废：`SettledAmount > 0` 时四类单据作废用例（采购入库单 / 销售出库单 / 采购退货单 / 销售退货单）一律拒绝（`40120`，message 含单号与已结金额），提示先作废对应收付款单；`VoidSettlement` 回退 `SettledAmount` 后即可再作废单据。**前端同步拦截**：已核销时列表与详情的「作废」按钮 `disabled` 并以 tooltip 给出同一处置提示，后端校验作为兜底。
- F8 收款支持供应商（收回退货退款）：`CreateSettlement` **移除「往来档案类型与方向匹配」校验（`40109`）**，往来正确性由「核销单据与收付款单往来一致（`40113`）」+「方向与单据类型匹配（`40114`）」保证；前端新建收付款页的往来下拉**不按类型过滤**（取全部启用往来），使「供应商（纯 `Supplier` 档案）的采购退货单 → 收款」可直接录入。业务类型仍由 `Type` + 明细 `OrderType` 派生（目标 7），不新增字段。

## 4. 验收标准

1. `cd backend && dotnet build` / `dotnet test` 通过（含 6 个新用例、四类单据核销累加与回退、方向与金额校验的单测）。
2. `cd frontend && npm run type-check` / `npm run lint` / `npm run build` 全绿。
3. `cd frontend && npm run test:e2e` 全量通过（含新增 `settlement.spec.ts`，以及采购 / 销售 / 退货用例中**结算相关断言的改造**后回归）。
4. 手工验证：
   - 销售单总额 1000，收 400 → 单据显示「部分结算（未结 600）」；再收 600 → 「已结算」。
   - 核销金额超过未结金额 → 拒绝（`40112`）；用收款单核销采购入库单 → 拒绝（`40114`）；用收款单核销其他往来单位的销售单 → 拒绝（`40113`）。
   - **收款支持供应商**：供应商（纯 `Supplier` 档案）的采购退货单 500 → 前台可选择该供应商创建收款单并核销 500，**不再返回 `40109`**。
   - 作废收 400 的收款单 → 单据回到「未结 1000」，台账应收恢复。
   - 往来对账页：应收 = Σ 销售出库单未结 + Σ 采购退货单未结；应付 = Σ 采购入库单未结 + Σ 销售退货单未结；可下钻查看未结清单据。
5. 数据迁移：迁移前 `SettlementStatus = 1` 的单据，迁移后 `SettledAmount = TotalAmount`（与迁移前展示口径一致）。
6. 口径单一：单据上的手工结算切换接口与按钮**不再存在**，`specs/015` / `016` / `021` / `022` 留有演进注记，其 e2e 断言同步更新。
7. 单据详情结算反查：四类单据详情展示「收付款明细」只读区块；`GET /api/settlements?orderType={0..3}&orderId={id}` 只返回核销了该单据的收付款单（含已作废），并返回每张单对该单据的核销金额；两者未成对传入返回 `40000`。
8. 单号即入口：收付款单详情的**核销明细**、往来对账的**未结单据抽屉**、四类单据详情的**「收付款明细」**区块，一律以**单号超链接**（`a-link`）直达对应单据详情，**不另设「详情」按钮 / 操作列**。
9. 作废与核销互斥：对已核销（`SettledAmount > 0`）的四类单据调用作废接口 → `40120`，message 含单号与已结金额，且**库存 / 流水 / 单据状态均不变**；先作废对应收付款单（金额回退为 0）后再作废成功。
10. 收款支持供应商与业务类型派生：`CreateSettlement` 不再返回 `40109`（往来档案类型不按方向校验），纯 `Supplier` 往来的收款单（核销采购退货单）创建成功并累加对应单据 `SettledAmount`；主表**无**业务类型列，业务类型由 `Type` + 明细 `OrderType` 唯一确定（收款 × 销售出库 = 销售回款；收款 × 采购退货 = 收回退款；付款 × 采购入库 = 采购付款；付款 × 销售退货 = 退出退款）。
11. 列表「单据类型」列：`GET /api/settlements` 每行返回 `orderTypes`（该单核销明细的单据类型**去重升序**集合；无明细时为空数组）；前端列为可选列且默认显示，多值以「、」连接；混合核销（「两者」往来）时能同时展示多类单据类型。

## 5. 范围外（不做）

- **预收 / 预付（未核销余额留存）**：本规格要求收付款单金额等于其核销金额之和；挂账余额（先收钱后开单）属后续能力。
- **账期、信用额度、催收提醒**：`036-erp-partner-price`。
- **发票与税务**：`032-erp-invoice`。
- **财务凭证 / 总账 / 期末结转**：见 `specs/ROADMAP.md` §5（不做财务级账务）。
- **多币种与汇率**：单币种（人民币）记账。
- **手续费 / 折让 / 抹零**：核销金额与收款金额必须相等，不支持差额科目。
- **自动核销策略（按单号 / 自动分配）**：本期由用户手工指定核销明细。
- **业务类型字段与按业务类型筛选**：业务类型由 `Type` + 明细 `OrderType` 派生（目标 7 / F8），不落列、不单设筛选维度。
- **导出 / 打印**：`027-erp-export`。
