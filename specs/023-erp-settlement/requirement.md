# 需求规格：收付款与应收应付（erp-settlement）

> 进销存扩展路线（`specs/ROADMAP.md`）批次二第三项；本规格**改造既有单据的结算语义**（`015` / `016` / `021` / `022` 的 `SettlementStatus`），落地前先读本规格 §3 与各规格的演进注记。

## 1. 背景

现状单据的结算只是一个**手工状态位**（`OrderSettlementStatus` 0=未结算 / 1=已结算），由 `PUT /api/{单据}/{id}/settlement` 手工切换，`015` §5 已把它记为「MVP 简化，后续升级为已结算金额」。

这带来三个业务空洞：

- **无法表达部分结算**：客户先付 60%，单据要么「未结算」要么「已结算」，实际金额与欠款无从体现。
- **没有收付款凭证**：钱什么时候收的、走的什么方式、对应哪几张单，系统里没有记录；单据上的状态位无法追溯是谁在什么时候点的。
- **看不到往来余额**：无法回答「某客户还欠多少、某供应商我们还欠多少」。

`021` / `022` 的退货单也会冲减往来金额，同样需要一个统一的资金侧口径。

## 2. 目标

1. **单据结算升级**：`SettlementStatus`（0/1）替换为 `SettledAmount`（已结算金额），结算状态由金额与总额推导（未结 / 部分 / 结清），不再手工切换。
2. **收付款单**：一张收付款单可核销多张单据，支持部分核销；可作废（回退已结算金额）。
3. **核销方向约束**：收款单核销「销售单 / 采购退货单」（我们收钱），付款单核销「采购单 / 销售退货单」（我们付钱）；往来单位与方向都必须匹配。
4. **往来对账**：按往来单位聚合应收 / 应付余额与未结单据，可下钻查看未结清单据。
5. **口径单一**：移除单据上的手工结算切换接口与按钮，所有结算变化都由收付款单核销驱动。

## 3. 功能点

- F1 四张单据表（`PurchaseOrders` / `SalesOrders` / `PurchaseReturns` / `SalesReturns`）的 `SettlementStatus` 列替换为 `SettledAmount`（`numeric(18,2)`，默认 0）；迁移时历史「已结算」单据按全额回填（见 `design.md` §2.4）。
- F2 新增 `Settlements` / `SettlementItems` 表：收付款单（类型 / 往来 / 日期 / 金额 / 方式 / 状态）+ 核销明细（单据类型 / 单号 / 单据日期 / 单据总额 / 本次核销金额，均为开单时快照）。
- F3 新增用例：`GetSettlements`、`CreateSettlement`（校验方向与未结金额 → 累加各单据 `SettledAmount` → 落单）、`GetSettlementById`、`VoidSettlement`（回退已结算金额）、`GetUnsettledOrders`（按往来 + 方向返回可核销单据）、`GetReconciliation`（往来对账台账）。
- F4 前端「收付款」页（列表 / 新建 / 详情，含作废）与「往来对账」页（往来余额 + 未结单据下钻）。
- F5 单据侧改造（采购 / 销售 / 采购退货 / 销售退货的前端与接口）：移除「标记已结算 / 改回未结算」操作，列表与详情改为展示**结算状态标签 + 未结金额**，并把操作位改为「去收付款」跳转（预置往来单位与方向）。
- F6 e2e 覆盖：部分收款 → 单据显示「部分结算」与未结金额、台账减少；收满 → 「已结算」；作废收付款单 → 金额回退；方向不匹配 / 超额核销被拒。

## 4. 验收标准

1. `cd backend && dotnet build` / `dotnet test` 通过（含 6 个新用例、四类单据核销累加与回退、方向与金额校验的单测）。
2. `cd frontend && npm run type-check` / `npm run lint` / `npm run build` 全绿。
3. `cd frontend && npm run test:e2e` 全量通过（含新增 `settlement.spec.ts`，以及采购 / 销售 / 退货用例中**结算相关断言的改造**后回归）。
4. 手工验证：
   - 销售单总额 1000，收 400 → 单据显示「部分结算（未结 600）」；再收 600 → 「已结算」。
   - 核销金额超过未结金额 → 拒绝（`40112`）；用收款单核销采购单 → 拒绝（`40114`）；用收款单核销其他客户的销售单 → 拒绝（`40113`）。
   - 作废收 400 的收款单 → 单据回到「未结 1000」，台账应收恢复。
   - 往来对账页：客户应收 = Σ销售单总额 − Σ销售退货总额 − Σ已收；供应商应付同理；可下钻查看未结清单据。
5. 数据迁移：迁移前 `SettlementStatus = 1` 的单据，迁移后 `SettledAmount = TotalAmount`（与迁移前展示口径一致）。
6. 口径单一：单据上的手工结算切换接口与按钮**不再存在**，`specs/015` / `016` / `021` / `022` 留有演进注记，其 e2e 断言同步更新。

## 5. 范围外（不做）

- **预收 / 预付（未核销余额留存）**：本规格要求收付款单金额等于其核销金额之和；挂账余额（先收钱后开单）属后续能力。
- **账期、信用额度、催收提醒**：`033-erp-partner-price`。
- **发票与税务**：`034-erp-invoice`。
- **财务凭证 / 总账 / 期末结转**：见 `specs/ROADMAP.md` §5（不做财务级账务）。
- **多币种与汇率**：单币种（人民币）记账。
- **手续费 / 折让 / 抹零**：核销金额与收款金额必须相等，不支持差额科目。
- **自动核销策略（按单号 / 自动分配）**：本期由用户手工指定核销明细。
- **导出 / 打印**：`027-erp-export`。
