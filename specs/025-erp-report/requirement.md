# 需求规格：进销存报表（erp-report）

> 进销存扩展路线（`specs/ROADMAP.md`）已完成（决策与报表），依赖 `019-erp-stock-movement` 的流水。
> 本规格**只读**：不新增业务表、不改变任何写入路径；成本与毛利见 `026-erp-cost`，导出见 `027-erp-export`。

## 1. 背景

`019` 已让每次库存变动可追溯（谁、何时、因何单、变动多少），`014` 提供当前库存的操作视图，但**没有一个按期间汇总的口径**，导致三类问题回答不了：

- **进销存无法对账**：「本月某商品进了多少、出了多少、期末多少、与期初差在哪」只能人工翻流水明细逐条加总。
- **库存结构看不清**：`014` 是逐商品的明细列表，看不到「按分类的余额分布与低库存集中度」。
- **采购 / 销售缺少汇总**：「某个供应商这个月供了多少、某个客户买了多少、退货冲减后净额是多少」需要跨多张单据表手工统计。

报表是「有流水之后才有意义」的能力：报表口径必须**直接读流水**，才能与 `019` 的「Σ 流水变动量 == `Inventory.Quantity`」对账口径同源，避免出现第二套库存口径。

## 2. 目标

1. **进销存报表**（核心）：按「商品 × 期间」给出**期初 + 期间入 − 期间出 = 期末**，四列同时展示，期间可任选；支持按商品 / 分类筛选。
2. **库存余额表**：当前库存按**分类汇总**（分类小计 + 全库合计 + 低库存计数），可下钻到 `014` 的明细视图。
3. **采购汇总 / 销售汇总**：按「往来单位」或「商品」× 期间汇总单据张数、数量、金额，并**冲减退货**（净额口径）。
4. **口径唯一且可对账**：报表 `期末` 与 `Inventory.Quantity` 一致；口径正文落在本规格 `design.md` §0，后续规格（`026` / `038` / `040`）追加维度时在同一表续行。
5. **只读、可复算**：报表不落物化表、不做定时任务，全部按请求实时聚合（数据量级为「单组织的流水」，MVP 可控）。
6. **菜单归属**：新增顶级分组「报表」，容纳 `025` / `026` 的报表页；同步给出 `023`–`045` 的菜单归属总表（`design.md` §0），解决 `024` 遗留的「进销存分组项数过多」问题。

## 3. 功能点

- **F1 进销存报表**（`/reports/inventory-flow`）：筛选（期间起止、商品、分类、只看有变动商品）；列：商品编码、名称、分类、单位、期初数量、期间入、期间出、期末数量；底部合计行（合计各列）；服务端分页。
- **F2 库存余额表**（`/reports/stock-balance`）：筛选（分类、关键词）；列：分类、商品数、库存合计、零库存商品数、低库存商品数、库存占比；按分类聚合（不展开商品行），操作列「查看明细」跳 `014` 库存查询并预置分类筛选。
- **F3 采购汇总**（`/reports/purchase-summary`）：筛选（期间、供应商、分组维度=往来单位 / 商品）；列：供应商（或商品）、入库单数、入库数量、入库金额、退货数量、退货金额、**净额**；合计行；服务端分页。
- **F4 销售汇总**（`/reports/sales-summary`）：同 F3 结构，客户 / 商品维度，出库与退货冲减。
- **F5 后端只读接口**：4 个 `GET`（见 `design.md` §3.3），跨表聚合实现在新增的只读查询仓储内（不新增写路径、不新增表）。
- **F6 菜单与导航**：新增顶级分组「报表」（子项：进销存报表 / 库存余额表 / 采购汇总 / 销售汇总；`026` 追加「成本与毛利」）；既有菜单项按 `design.md` §0 总表归入相应分组。

## 4. 验收标准

1. `cd backend && dotnet build` / `dotnet test` 通过（含 4 个用例的筛选传参、汇总计算、分页与边界用例）。
2. `cd frontend && npm run type-check` / `npm run lint` / `npm run build` 全绿。
3. `cd frontend && npm run test:e2e` 全量通过（含新增 `report.spec.ts` 与既有用例回归；菜单分组调整后既有 spec 的菜单点击仍通过）。
4. 手工验证（对账）：
   - 某商品建账 100（期初流水）→ 采购入库 20 → 销售出库 30 → 盘点调整 −5：查询该商品任取期间，`期末 = 期初 + 期间入 − 期间出` 恒成立；取「全期间」时期末 == 库存查询页数量（85）。
   - 盘点调整（双向）按符号分别计入入 / 出，不整条计入一侧。
   - 采购汇总：开 1 张采购入库 1000、1 张采购退货 300 → 净额 700；作废单据不计入。
   - 库存余额表分类合计 == 各分类下启用商品库存之和；低库存计数与 `014` 的「低于安全库存」行数一致（同分类下）。
   - 跨分类筛选：按分类筛进销存报表时，期初按「该分类商品」的口径计算（不随筛选商品集合变化而漂移）。
5. 口径单一：报表口径写入本规格 `design.md` §0；`期末` 与 `Inventory.Quantity` 的一致性由单测断言（对账用例）。
6. 菜单：新分组「报表」下 4 项可达；既有菜单项按总表归位（`clickMenuItem` helper 同步更新），无重复或丢失入口。

## 5. 范围外（不做）

- **成本 / 毛利报表**：`026-erp-cost`（本规格的金额列只含单据金额，不含成本口径；库存余额表的「库存金额」列由 `026` 追加）。
- **图表 / 看板 / 大屏**：不做可视化图表与首页看板（表格化报表优先，图表另行评估）。
- **自定义报表 / 透视 / 报表设计器**：不做用户自定义列、透视与公式。
- **导出 / 打印**：`027-erp-export`（本规格页面预留导出按钮位，交付时启用）。
- **按仓库 / 批次维度**：`038` / `040` 落地时在 §0 口径表内追加维度列，本规格不分仓、不分批。
- **定时生成与推送**：不做日报 / 月报定时任务与邮件推送（`041` 只做库存预警，不做报表推送）。
- **财务级报表**：总账 / 凭证 / 资产负债等（见 `specs/ROADMAP.md` §5）。
- **物化报表 / 预聚合表**：不做缓存表与预聚合（数据量小，实时聚合即可；如后续性能不足再单独立规格）。
