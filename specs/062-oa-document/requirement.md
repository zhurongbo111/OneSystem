# 需求规格：公文收发登记（oa-document）

> ERP 全域路线（`specs/ROADMAP.md` §4.2）**P10 办公协同**第三项（边界与决策见 `ROADMAP` §6.11）。
> 依赖：`028`（权限 / 默认拒绝）、`030`（员工档案：经办人）、`027`（导出能力，`document.ts` 走 `export.ts` 同一分流）。
> 范围克制：只做**收文 / 发文登记与流转台账**；不做公文正文撰写、套红模板、电子签章、密级管理、流转审批、附件上传（见 §5）。

## 1. 背景

企业公文（上级来文、对外发文）目前**没有任何台账**：文号、来文单位、经办人、办理进度全靠线下 Excel 与纸面，查不到「某份文件现在谁在办、办完没有」，也无法按时间段统计收发文数量。

`ROADMAP` §1 把 OA 定位为「复用内核」：本规格只补一个业务对象（公文）与状态流转，**不新建审批引擎**（公文流转为线下办理 + 系统内登记进度，见 §5）。

## 2. 目标

1. **收文登记**：来文单位 + 对方文号 + 标题 + 收文日期 + 经办人 + 备注；登记时系统生成本单位收文号。
2. **发文登记**：主送单位 + 标题 + 发文日期 + 经办人 + 备注；登记时系统生成本单位发文字号。
3. **状态流转**：`已登记 → 办理中 → 已归档`（归档为终态）；任意非终态可作废。
4. **台账查询**：按方向 / 状态 / 日期范围 / 关键词（标题 / 文号 / 对方单位）筛选；支持导出。
5. **前端**：公文列表 + 详情 + 抽屉表单；菜单「办公 → 公文」。
6. **e2e 覆盖**登记 → 流转 → 归档的完整路径。

## 3. 功能点

- **F1 收文 / 发文登记**：`POST /api/official-documents`；`direction` 区分收文 / 发文；**单号后端生成**（收文 `OD` / 发文 `OW`，形式 `<前缀> + yyyyMMdd + 4 位序号`）。
- **F2 编辑与删除**：仅 `Registered` 可编辑 / 删除（否则 `40205`）；单号与方向**不可改**（请求体不含）。
- **F3 状态流转**：`POST .../{id}/status`；白名单见 `design.md` §0.1；终态拒绝。
- **F4 台账查询与导出**：列表筛选 + `GET /api/official-documents/export`（文件流契约例外，登记 `027` §0.1）。
- **F5 前端**：`views/DocumentManagement/`（列表 + 详情 + 表单抽屉）、`api/officialDocument.ts`、导出走 `api/export.ts` 同分流。
- **F6 e2e**：新增 `e2e/official-document.spec.ts`。

## 4. 验收标准

1. `cd backend && dotnet build` / `dotnet test` 通过（单号生成与唯一性、状态白名单、终态限制、导出）。
2. `cd frontend && npm run type-check` / `npm run lint` / `npm run build` 全绿；`npm run e2e:run` 全量通过（新增 `official-document.spec.ts`）。
3. 手工验证：
   - 登记一份收文 → 列表显示 `OD202610070001` 形式单号；同日再登记序号递增；
   - 状态流转至「已归档」→ 编辑 / 删除 / 再流转入口不可用（`40205`）；
   - 按方向 + 日期范围筛选并导出 Excel 成功。
4. 口径单一：方向与状态取值、单号规则、流转白名单只在 `design.md` §0 定义一次。
5. 联动（实现时）：`028` §0.2 续行 `documents.*`；`029` §0.1 续行资源 `OfficialDocument`；`027` §0.1 导出范围表续行本域；`ROADMAP` §6.7 单号前缀 `OD` / `OW` 已在起草时登记。

## 5. 范围外（不做）

- **公文正文撰写 / 套红模板 / Word 排版**：本规格只登记台账，正文在线下工具完成。
- **电子签章 / 用印**：用印属行政事务（`063`），不在本域。
- **密级管理与涉密管控**：不做密级字段与访问分级。
- **流转审批**（会签 / 传阅 / 批示）：办理进度手工登记，不接 `042`。
- **附件上传**：不做文件存储。
- **与外部公文系统对接**：不做。
