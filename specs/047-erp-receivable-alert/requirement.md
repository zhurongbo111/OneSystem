# 需求规格：逾期应收提醒（erp-receivable-alert）

> ERP 全域路线（`specs/ROADMAP.md` §4.2）**P7 内核收口与运营**项；复用 `041-erp-stock-alert` 的站内信能力与扫描骨架，取 `036-erp-partner-price` 的账期 / 到期日口径。
> 依赖：`036`（账期 / 到期日 / 逾期判据）、`041`（`Notifications` / `INotificationWriter` / `AlertRecords` / 定时宿主）、`023`（未结金额）、`028`（权限）。
> 范围克制：只做**应收侧**（客户欠我方）的逾期提醒；不做应付提醒、周期催收、升级策略、外发（短信 / 邮件）。

## 1. 背景

`036` 已把「账期天数 + 信用额度」落到客户主数据，并在往来对账页给出**逾期单据数 / 最早到期日 / 最大逾期天数**——但这些只在**用户主动打开对账页**时才可见：

- 业务员不会天天盯对账页；一笔应收一旦逾期，"什么时候该催谁"没有主动出口。
- `041` 已建成站内信通道，且 `NotificationType` 在 `042` 续行时**为「逾期应收」显式预留了取值 `5`**（`041` §2.1），只差一个扫描器。
- 到期日与逾期判据（`036` §0.3）已定义且**由后端推导**，扫描器可直接复用同一口径。

本规格补上**逾期应收的主动提醒**：定时（或手动）扫描逾期未结的销售出库单，向具备对账权限的用户发站内信。

## 2. 目标

1. **逾期应收信号**：扫描**未作废、未结清**的**销售出库单**，按 `036` §0.3 口径判定逾期（`单据日期 + 账期 < 今天` 且 `未结金额 > 0`）。
2. **主动通知**：命中信号向具备 `reconciliation.view` 的**启用**用户发站内信（`NotificationType = 5`），带跳转（往来对账「仅看逾期」）。
3. **不刷屏**：**每张逾期单据终身只提醒一次**（去重见 `design.md` §0.1），恢复结清后不再提醒。
4. **复用既有骨架**：与库存预警**同一定时宿主、同一手动扫描入口**，不新建宿主 / 端点。
5. **前端**：站内消息页类型文案 / 颜色扩充；跳转目标落对账页。
6. **e2e 覆盖**。

## 3. 功能点

- **F1 逾期应收扫描**：新增 `IReceivableAlertScanner`（`App.Core/Alerts/`，入参 `utcNow`，可单测）；只读查询逾期未结销售出库单。
- **F2 去重**：复用 `AlertRecords`，`AlertType` 续行 `ReceivableOverdue = 3`；去重键设计使**同一单据只提醒一次**（`design.md` §0.1）。
- **F3 通知**：`INotificationWriter` 批量写入；接收人 = 具备 `reconciliation.view` 的启用用户（无 → warning 跳过）。
- **F4 宿主与手动触发**：既有 `StockAlertBackgroundService` 与 `POST /api/notifications/scan` **同时执行**库存与应收两个扫描器；扫描结果汇总返回（含应收计数）。
- **F5 前端**：`NOTIFICATION_TYPE_META` 增类型 `5`（文案 / 颜色）；站内消息类型筛选可选；跳转 `reconciliation` + `overdueOnly=true`。
- **F6 e2e**：造逾期单据 → 手动扫描 → 站内信出现 → 点击跳转对账页且「仅看逾期」生效。

## 4. 验收标准

1. `cd backend && dotnet build` / `dotnet test` 通过（逾期判定边界、去重一次性、接收人筛选）。
2. `cd frontend && npm run type-check` / `npm run lint` / `npm run build` 全绿；`npm run test:e2e` 全量通过（新增 `receivable-alert.spec.ts`）。
3. 手工验证：
   - 客户账期 30 天，建 40 天前的销售出库单未收款 → 扫描 → 站内信「逾期应收」出现，点击跳对账页且仅看逾期。
   - 再次扫描 → **不再新增**同一单据的消息（一次性）。
   - 结清该单后再扫描 → 不提醒。
4. 口径单一：逾期判据引用 `036` §0.3（不重复定义）；通知类型 / 去重键 / 内容模板只在 `design.md` §0 定义一次。
5. 联动：`041` §0 / §2.1 / §2.3 续行 `AlertType.ReceivableOverdue` 与 `NotificationType = 5` 转生产；`028` §0.2 无新增权限点。

## 5. 范围外（不做）

- **应付逾期提醒**（我方欠供应商）：本期只做应收；应付如需另立（同一骨架可复用）。
- **周期催收 / 提醒升级 / 逾期分级**（如逾期 30 / 60 / 90 天分档提醒、逐级上报）：本期**每单一次性**。
- **外发通道**（短信 / 邮件 / 企业微信 / Webhook）：同 `041`，站内信是唯一通道。
- **催收任务 / 跟进记录 / 对账单发送**：不做（如与 CRM 服务工单联动另行评估）。
- **客户信用额度联动**（逾期触发额度冻结）：`036` 信用额度仍按超限校验，逾期与授信不联动。
- **应收账龄分析报表**：不做（如需并入报表域另立）。
