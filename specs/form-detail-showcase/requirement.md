# 需求规格：表单与详情页样式参照（form-detail-showcase）

## 1. 背景

`list-showcase` 已沉淀列表页标准，但列表页的配套交互——**新增/编辑（表单）与详情（只读展示）**——尚无可参照的实现。后续业务几乎每个列表都带这两种页面，其"页面形态"（独立页面 / 抽屉 / 弹窗）与"详情页和表单页是否共享"是高频设计决策。需要一个纯前端参照，沉淀两种典型形态的标准实现与交互约定。

## 2. 目标

- 落地「列表配套表单与详情」的形态决策为项目约定（正文写入本规格 `design.md` §0）。
- 提供**一个统一列表参照页**（示例业务：订单，`/form`），同一份数据上同时演示两种表单形态：
  - **抽屉形态**：字段较少（≤ 8）的表单用抽屉承载（新增/编辑共用同一抽屉表单）。
  - **独立页面形态**：字段较多（含子表格/多分组）的表单用独立页面承载（新增/编辑独立页面）。
- 列表与操作列只有一套：新增提供「新增·抽屉」「新增·页面」两个入口；操作列「编辑」点击后弹出形态菜单（用抽屉 / 用页面）再打开对应表单。
- 详情页为**唯一独立页面**（`/form/detail/:id`，`a-descriptions` + 商品明细子表格），字段最全。
- 明确并示范：**详情页与表单页不共享同一组件**——详情页只读、强调信息密度；表单页强调录入与校验；仅数据模型类型共享。

## 3. 范围

### 3.1 本期包含

| 功能 | 说明 |
|---|---|
| 列表页 | 参照 `ListShowcaseView`：关键词搜索 + 状态下拉筛选 + 表格（金额格式化、状态 Tag 着色、创建时间）+ 分页；静态 Mock 约 12 条，`useOrderData()` 模块级单例共享 |
| 操作列 | 查看（进统一详情）/ 编辑（点击弹形态菜单：用抽屉 / 用页面）/ 删除（Popconfirm） |
| 新增入口 | 工具条两个按钮：「新增·抽屉」（primary，开抽屉表单）、「新增·页面」（次级，跳独立新增页） |
| 抽屉表单 | `a-drawer` 宽 560、`unmount-on-close`、`:footer="false"` + 底部自定义操作栏，手动 `validate()`：订单号（新增时只读占位/编辑时可看）、客户、商品、金额、状态、创建时间、备注 |
| 独立表单页 | `/form/new`、`/form/edit/:id`，`a-form` 分两组 + 子表格「商品明细」（a-table 内嵌 a-input，可加删行），底部操作栏（提交/取消） |
| 详情页 | 独立页面 `/form/detail/:id`：`a-page-header`（头部操作 编辑/删除）+ `a-descriptions`（含比表单更多的只读字段：创建人、更新时间）+ 商品明细子表格 |
| 校验 | 抽屉：必填 + 金额 > 0，错误走 `a-form` 提示；页面：同左 + 子表格至少 1 行且每行商品名非空 |
| 详情不存在 | 未知 id 显示 `a-result status=404` + 返回列表按钮 |
| 提交闭环 | 抽屉：提交成功后写入数据源、关闭、`Message.success`，列表可见新行；页面：提交成功后写入数据源并跳详情页，`Message.success` |

### 3.2 本期不包含

- 任何后端接口、真实数据、登录态数据（数据为页面内静态 Mock）。
- 权限控制、行内编辑、草稿暂存、步骤条表单等高级能力。
- 表单组件与详情页组件的代码级复用（本规格刻意不共享表单组件，作为反例边界说明见 design §6）。

## 4. 验收标准

1. 已登录后从侧边菜单「表单与详情示例」进入 `/form`，列表按 `list-showcase` 同款布局渲染，标题「订单列表（表单与详情示例）」，静态 Mock 12 条。
2. 抽屉形态：点「新增·抽屉」打开右侧抽屉（宽 560），必填项为空或金额 ≤ 0 时提交被拦截且抽屉不关闭；填完必填项提交，列表出现新行且 `Message.success`。
3. 抽屉形态：操作列「编辑」→「用抽屉」打开抽屉且字段回填，修改后提交，列表该行更新。
4. 页面形态：点「新增·页面」跳 `/form/new`，页面含分组表单与商品明细子表格；「添加行/删除行」可用；校验失败时页面不动、错误可见；提交成功跳 `/form/detail/:id`。
5. 页面形态：操作列「编辑」→「用页面」跳 `/form/edit/:id`，表单与明细回填；提交后回详情页且数据更新。
6. 详情页：「查看」进 `/form/detail/:id`，`a-descriptions` 展示全部字段（含创建人、更新时间）+ 商品明细子表格；详情页「编辑」打开抽屉编辑；未知 id 显示 404 空态。
7. 删除（列表行/详情页）均走 Popconfirm，删除后列表与总数更新。
8. 全部样式基于 Arco 组件与主题变量，无自造样式体系。
9. `npm run build`、`npm run lint` 通过；`npm run test:e2e` 中 `form-showcase.spec.ts` 全绿，且不影响既有 spec。

## 5. 非目标 / 备注

- 数据、行为均为前端静态模拟，目的是形态与交互参照，非真实业务。
- 页面纳入 `AppLayout` 布局（`AppLayout` 子路由，`requiresAuth`），需登录访问。
- 形态选择标准（何时抽屉、何时独立页面、详情页是否共享）沉淀于本规格 `design.md` §0，以该约定为准。
- 历史说明：本规格早期版本为「例 A（/form-drawer）」与「例 B（/form-page）」两个平行示例，因两列表页同源同列、几乎重复，已合并为本版「单一列表 + 双形态入口」。
