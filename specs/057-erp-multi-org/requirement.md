# 需求规格：多公司 / 多组织（erp-multi-org）

> ERP 全域路线（`specs/ROADMAP.md` §4.2）**P9 组织扩展**项（**待评估**：**确有多主体经营时启动**）；`ROADMAP` §7 原「多公司 / 多组织 / 合并报表」范围外项之一，本轮改列待评估。
> 依赖：`028`（权限）、`030`（组织 / 员工）、`033`（账套 / 期间 / 凭证）、`046`（数据范围）、`038`（默认仓「固定 GUID + 回填」惯用范式）。
> 范围克制：只做**法人主体（公司）字典 + 业务 / 账务按公司隔离 + 顶栏公司切换**；**不做合并报表 / 内部交易抵消**（见 `058`）、不做组织树级公司嵌套。

## 1. 背景

现状是**单主体**账套（`ROADMAP` §6.9「单主体起步」）：全库只有一套业务单据、一套会计期间与凭证、一套库存与资金，所有用户共享同一片数据。

一旦出现**两个以上法人主体**（如"贸易公司 A"与"贸易公司 B"，各自开票、各自做账），单主体模型无法表达：

- 业务单据不能归属到具体公司，账务无法"各做各的账"。
- 用户应只能访问自己有权的公司；`046` 的数据范围只在"单公司内部"按部门 / 本人切分，缺"公司"这一层。
- 报表（`025` / `033`）会把两个公司的数据混在一起，失去意义。

本规格引入**多公司**：公司字典 + 全业务 / 账务数据加 `CompanyId` 隔离 + 顶栏切换 + 权限按公司。

## 2. 目标

1. **公司字典**：`Company`（编码 / 名称 / 启用 / 默认标记），权限点续行 `028` §0.2（`companies.*`）。
2. **数据隔离**：所有**业务与账务数据表**追加 `CompanyId`（NOT NULL，FK）；查询 / 写入按**当前公司**限定。**主数据与组织共享**（见 `design.md` §0.1）。
3. **当前公司**：由请求头 `X-Company-Id`（前端切换器）或用户默认公司解析；用户可访问公司集合记 `UserCompany`；无权 `40195`。
4. **默认公司迁移**：迁移内插入**固定 GUID 默认公司**，回填所有既有数据（同 `038` 默认仓范式），升级后行为与单主体一致。
5. **权限 / 数据范围联动**：功能级权限（`028`）不变；数据范围（`046`）以"公司"为最外层，再按部门 / 本人。
6. **前端**：顶栏公司切换器 + 公司管理页；所有列表默认限定当前公司；**e2e 覆盖**。

## 3. 功能点

- **F1 公司管理**：`GET/POST /api/companies`、`GET/PUT /{id}`、`PUT /{id}/status`；默认公司不可停用 / 删除（`40197`）；有数据不可删除（`40196`）。
- **F2 当前公司解析**：`ICurrentCompany`（请求头 / 默认公司；`40195`）；`UserCompany` 维护（用户可访问公司）。
- **F3 数据隔离**：`design.md` §0.2 列出**受影响表分组**，全部追加 `CompanyId` + 回填；查询 / 写入按当前公司过滤。
- **F4 切换**：前端顶栏切换器 → 请求头携带 → 列表 / 报表随之切换。
- **F5 权限与菜单**：`028` §0.2 续行 `companies.*`；`025` §0.2「系统」分组续行。
- **F6 e2e**：切公司 → 单据 / 报表按公司隔离；无权公司 `40195`。

## 4. 验收标准

1. `cd backend && dotnet build` / `dotnet test` 通过（当前公司解析、隔离过滤、默认公司保护、回填回归）。
2. **隔离守卫测试**：断言 `design.md` §0.2 列出的全部实体均含 `CompanyId`（漏加即失败），且查询路径均带公司过滤。
3. `cd frontend && npm run type-check` / `npm run lint` / `npm run build` 全绿；`npm run test:e2e` 全量通过（新增 `multi-org.spec.ts`）。
4. 手工验证：
   - 升级后（默认公司）全部功能行为**与升级前一致**（默认公司回填）。
   - 建公司 B → 用户 A 授权 B → 切换 → 只见 B 的数据；切回 A 数据不串。
   - 未授权用户切 B → `40195`；停用 / 删除默认公司 → `40197`。
5. 口径单一：共享 / 隔离边界、当前公司解析、受影响表分组只在 `design.md` §0 定义一次。
6. 联动：`028` §0.2 续行、`025` §0.2「系统」分组续行、`046` §0.2 数据范围增「公司」层、`ROADMAP` §6 错误码续行、§6.9「单主体起步」标注演进。

## 5. 范围外（不做）

- **合并报表 / 内部交易抵消 / 权益法**：见 `058-erp-multi-currency`（待评估）。
- **主数据按公司隔离**：商品 / 往来 / 分类 / 仓库 / 科目 / 税率 / 组织 / 员工 **共享**（§5 决策）；如需按公司隔离另评。
- **公司层级 / 集团 → 子公司嵌套树**：本期公司为**平级主体**（无父子）。
- **跨公司单据流转 / 内部调拨**：不做。
- **各公司独立数据库 / 独立部署**：单库多租（`CompanyId` 隔离）。
- **公司级编码规则 / 编号**：编码规则（`050`）保持全局。
- **用户跨公司权限的细粒度矩阵**（按公司配角色）：本期用户可访问公司集合由管理员维护，角色仍全局；公司级角色差异另评。
