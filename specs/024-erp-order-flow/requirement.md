# 需求规格：两段式单据（采购订单 → 入库、销售订单 → 出库）（erp-order-flow）

> 进销存扩展路线（`specs/ROADMAP.md`）批次二第四项；本规格**包含一处需用户确认的关键决策**（既有单据表重命名与前缀改写，见 `design.md` §5），实施前须先确认。

## 1. 背景

现状采购 / 销售都是**一步式单据**：保存即入库 / 出库（`015` / `016`），库存变动与业务发生同时完成。这在「货到即入账」的场景够用，但真实业务里更常见的是**先下订单、货分批到**：

- 下了 100 件订单，先到 60 件 → 系统无法记录「还有 40 件在途」，也无法只对到货部分入库。
- 下单后供应商改数量 / 改价 → 一步式单据只能「作废重开」，历史链条断裂。
- 想统计「已下单未到货」的量（备货、跟单）→ 没有数据来源。

`019` 的库存流水与 `023` 的收付款已分别解决「库存可追溯」与「资金可追溯」，本条解决**单据链条**：订单（计划）与出入库单（执行）分离。

## 2. 目标

1. **引入订单层**：采购订单（`PO`）与销售订单（`SO`）记录计划数量与单价，**不直接影响库存**。
2. **出入库单关联订单**：入库 / 出库单可关联订单（可选），关联时按明细回写订单的「累计已收 / 已发数量」，并推导订单状态（待收货 / 部分收货 / 已完成）。
3. **部分收货 / 部分发货**：一张订单可拆成多张出入库单；单次数量不得超过订单明细的未收 / 未发数量。
4. **订单可编辑与可控关闭**：订单在「未开始收货」时可编辑、可作废；「部分收货」后可**手动关闭**（剩余不再收），不可作废（已发生的收货需通过退货处理）。
5. **保持直通用法**：不关联订单的出入库单沿用既有一步式行为（兼容既有数据与「货到即入账」场景）。
6. **在途量可见**：订单列表展示未收 / 未发数量，可据此跟单。

## 3. 功能点

- F1 新增订单表与实体：`PurchaseOrders` / `PurchaseOrderItems`（订单语义）、`SalesOrders` / `SalesOrderItems`（订单语义）；既有出入库单表重命名（见 `design.md` §5 关键决策）。
- F2 订单用例：`GetPurchaseOrders` / `CreatePurchaseOrder` / `GetPurchaseOrderById` / `UpdatePurchaseOrder`（仅未开始收货可改）/ `VoidPurchaseOrder`（仅未开始收货可作废）/ `ClosePurchaseOrder`（手动关闭）；销售侧同构。
- F3 出入库单改造：新增「关联订单」字段与订单查询入口（`GET /api/purchase-receipts/order-lines?orderId=` 拉取订单未收明细），保存时校验并回写累计量、推导订单状态；作废时回退。
- F4 订单状态：`待收货` / `部分收货` / `已完成` / `已关闭` / `已作废`（销售侧为待发货 / 部分发货 / 已发货）。
- F5 前端：订单列表 / 新建 / 编辑 / 详情（含未收数量与关联出入库单）；出入库单开单页支持「关联订单 → 带出明细与未收数量」。
- F6 e2e 覆盖：下单 → 部分入库 → 订单显示「部分收货」与在途量 → 再入库剩余 → 「已完成」；入库单作废 → 状态与在途量回退；订单在部分收货后不可改 / 不可作废、可关闭。

## 4. 验收标准

1. `cd backend && dotnet build` / `dotnet test` 通过（含订单 6 用例 + 出入库单关联回写 / 回退的单测）。
2. `cd frontend && npm run type-check` / `npm run lint` / `npm run build` 全绿。
3. `cd frontend && npm run test:e2e` 全量通过（含新增 `purchase-order.spec.ts` / `sale-order.spec.ts`，以及重命名后既有采购 / 销售 / 退货 / 结算用例的回归）。
4. 手工验证：
   - 采购订单 100 件 → 入库 60 件 → 订单「部分收货」、未收 40；再入库 40 → 「已完成」。
   - 入库单作废 → 订单回到「部分收货」、未收 40。
   - 入库数量超过订单未收量 → 拒绝（提示含订单号与未收数量）；订单在部分收货后编辑 / 作废 → 拒绝（提示状态不允许）。
   - 不关联订单的入库单仍可正常开具（既有行为不变）。
5. 数据迁移：既有出入库单可以 `OrderId = 空` 正常使用；订单表初始为空（历史单据不回溯生成订单）。
6. 库存与流水口径不变：订单不动库存、不写流水；出入库单的库存变化与流水行为与既有完全一致。

## 5. 范围外（不做）

- **订单变更审批 / 变更历史**：`036-erp-approval`。
- **多订单合并收货 / 一单拆多单**：本期一张出入库单只关联一张订单。
- **预付款 / 定金**：资金侧由 `023-erp-settlement` 按单据核销，不做订单级预付。
- **交期提醒与跟单通知**：`035-erp-stock-alert`（预警通知）。
- **订单与采购申请 / 询价**：不做申请单与报价单层级（保持两段：订单 → 出入库）。
- **菜单分组升级**：加入订单后「进销存」菜单项将超过 10 项，需要把菜单改为二级分组（采购 / 销售 / 库存 / 资金），属 `005-app-layout` 的布局约定演进，另行处理。
- **分仓在途 / 按仓收货**：`030-erp-multi-warehouse`。
