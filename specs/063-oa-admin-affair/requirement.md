# 需求规格：行政事务申请（oa-admin-affair）

> ERP 全域路线（`specs/ROADMAP.md` §4.2）**P10 办公协同**第四项（边界与决策见 `ROADMAP` §6.11）。
> 依赖：`028`（权限 / 默认拒绝）、`030`（员工档案：申请人）、`041`（站内信通道）、`042`（**审批口径复用**：审批人取值与自审禁止，**不接阈值规则表**）。
> 范围克制：只做**统一行政申请单 + 固定单级审批**；不做多级 / 会签、办公用品库存台账、车辆调度冲突、采购联动、附件（见 §5）。

## 1. 背景

办公用品申领、用印申请、用车申请等行政事务目前**无申请单、无审批留痕**：口头或微信提出，谁批的、批了没有、办完没有都查不到，也无法统计某类申请的数量与审批时长。

`ROADMAP` §6.11 已明确 OA 的边界：**不新建审批引擎**。本规格的审批为**固定单级**（具备 `adminAffairs.approve` 权限的人审批），复用 `042` 的既有口径（**自审禁止**、驳回意见必填），但**不走 `042` 的阈值规则表**（阈值面向金额型 ERP 单据，与行政申请语义不符）。

## 2. 目标

1. **提交申请**：类型（办公用品 / 用印 / 车辆 / 其他）+ 事由 + 说明 + 期望时间 + 数量（可选）；申请人为当前用户。
2. **固定单级审批**：待审批 → 已批准 / 已驳回（驳回必填意见）；**自审禁止**（申请人不得审批自己的申请）。
3. **办理闭环**：已批准 → 已完成（发放 / 归还 / 用印完毕）；申请人可撤销（仅待审批）。
4. **提醒**：提交时向审批人发站内信，决策时向申请人发站内信（复用 `041` 通道）。
5. **前端**：申请列表 + 详情 + 表单抽屉 + 审批抽屉；菜单「办公 → 行政事务」。
6. **e2e 覆盖**提交 → 审批 → 完成；以及自审拦截。

## 3. 功能点

- **F1 申请单**：`POST /api/admin-requests`；单号后端生成（`AF` + `yyyyMMdd` + 4 位序号）；类型 / 事由 / 说明 / 期望时间 / 数量。
- **F2 撤销**：`POST .../{id}/cancel`；仅申请人且仅「待审批」。
- **F3 审批**：`POST .../{id}/approve` / `.../reject`；仅具备 `adminAffairs.approve` 权限者；**申请人 == 审批人 → `40210`**；驳回意见必填。
- **F4 完成**：`POST .../{id}/complete`；仅「已批准」可完成。
- **F5 触达**：提交时向审批人发 `NotificationType.AdminAffairPending = 9`、决策时向申请人发 `AdminAffairDecided = 10`（实现时续行 `041` §2.1）；发信失败只记日志。
- **F6 前端与 e2e**：`views/AdminAffairManagement/`（列表 / 详情 / 表单 / 审批抽屉）+ `api/adminRequest.ts`；新增 `e2e/admin-affair.spec.ts`。

## 4. 验收标准

1. `cd backend && dotnet build` / `dotnet test` 通过（状态白名单、自审禁止、驳回意见必填、撤销归属、发信调用与降级）。
2. `cd frontend && npm run type-check` / `npm run lint` / `npm run build` 全绿；`npm run e2e:run` 全量通过（新增 `admin-affair.spec.ts`）。
3. 手工验证：
   - 普通用户提交用印申请 → 具备 `adminAffairs.approve` 的用户在铃铛收到「待审批」；
   - 审批人驳回且未填意见 → `40000`；填写意见后驳回 → 申请人收到结果消息；
   - 申请人尝试审批自己的申请 → `40210`；
   - 已驳回 / 已完成 / 已撤销的申请无可用动作（`40208`）。
4. 口径单一：类型与状态取值、流转白名单、审批与归属判据只在 `design.md` §0 定义一次。
5. 联动（实现时）：`041` §2.1 续行 `NotificationType` 9 / 10（附演进指针）；`028` §0.2 续行 `adminAffairs.*`；`029` §0.1 续行资源 `AdminRequest`；`042` §0 留「审批口径被 `063` 复用」指针。

## 5. 范围外（不做）

- **多级审批 / 会签 / 加签**：固定单级（通用工作流引擎属 `ROADMAP` §7 明确不做）。
- **阈值触发规则**：行政申请**一律需要审批**，不接 `042` 的 `ApprovalRules`（阈值面向金额型单据）。
- **办公用品库存台账 / 领用数量扣减**：只记申请数量，不做库存联动。
- **车辆调度与时间冲突检测**：不建车辆资源台账。
- **自动生成采购单 / 费用报销单**：不跨域联动（如需另行评估）。
- **附件上传 / 电子签章**：不做。
