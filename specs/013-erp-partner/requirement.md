# 需求规格：往来单位（erp-partner）

## 0. 进销存功能组定位

本规格是**进销存（ERP）功能组**的往来单位域，为采购 / 销售单据提供供应商 / 客户档案：

| 子规格 | 内容 | 依赖 |
|---|---|---|
| erp-product | 商品分类 / 商品档案 / 库存台账 | 无（可与本规格并行） |
| **erp-partner（本规格）** | 往来单位（供应商 / 客户合并一张表） | 无（可与 erp-product 并行） |
| erp-inventory-query | 库存查询页 | erp-product |
| erp-purchase | 采购入库单 | erp-product + 本规格 |
| erp-sale | 销售出库单 | erp-purchase（单据域共用约定）+ erp-product + 本规格 |

实现顺序：本规格与 erp-product 可并行开发；erp-purchase 须待两者交付后进行。

## 1. 背景

进销存 MVP 整体需求已按功能拆分为多个可独立实现的子规格（见 §0），本规格负责**往来单位档案**：

- 采购 / 销售单据需要供应商 / 客户档案（名称 / 类型 / 联系人 / 电话 / 地址）。
- 供应商与客户**合并一张表**（`Partners` + `Type` 区分），同一单位可同时是供应商又是客户（`Both`）。
- 名称唯一（创建后不可修改，避免单据引用歧义，同用户名不可改原则）。
- 停用不删除：停用的单位不可被新单据选择，已有单据不受影响。

## 2. 目标

1. 管理员可维护**往来单位档案**（供应商 / 客户 / 两者）：列表 / 详情 / 新增 / 编辑 / 停用启用；名称唯一。
2. 按类型校验开单资格：采购单要求 `Type in (Supplier, Both)` 且启用；销售单要求 `Type in (Customer, Both)` 且启用（类型 / 状态校验在 erp-purchase / erp-sale 的 Handler 中执行，本规格提供档案与查询能力）。
3. 前端提供往来单位页面（列表 / 筛选 / 新增 / 编辑 / 启停），侧边菜单「进销存」分组添加「往来单位」子项。

## 3. 功能点

- **F1 往来单位列表**：分页查询，支持按关键词（名称 / 联系人模糊）、类型（供应商 / 客户 / 两者）、状态筛选；返回总数。
- **F2 往来单位详情**：按 id 查看单个单位完整信息（不做独立详情页，用抽屉 disabled 态查看，见 design §5 决策）。
- **F3 新增往来单位**：名称（唯一）、类型、联系人、联系电话、地址、备注。
- **F4 编辑往来单位**：可改类型 / 联系人 / 电话 / 地址 / 备注；**名称创建后不可修改**；**类型只放宽不收窄**——只允许保持原类型或改为「两者」，禁止供应商 / 客户互改、禁止「两者」改回单一类型（避免既有采购 / 销售单据因档案类型丢失而在编辑时校验失败）。
- **F5 往来单位停用 / 启用**：停用的单位不可被新单据选择（开单下拉由 erp-purchase / erp-sale 过滤）；已有单据不受影响。
- **F6 开单往来单位查询**：提供按类型 + 启用状态筛选的查询能力（`GET /api/partners` 的 `type` / `status` 筛选参数），供开单页下拉数据源使用。
- **F7 前端菜单**：侧边菜单「进销存」分组添加「往来单位」子项（分组由 erp-product 创建，本规格仅追加子项；若 erp-partner 先于 erp-product 交付，则本规格同时创建分组，最终分组顺序：商品管理 / 往来单位 / 采购入库 / 销售出库 / 库存查询）。

## 4. 验收标准

1. `cd backend && dotnet build` 成功（net8.0）；`dotnet test` 全部通过。
2. 执行 EF Core 迁移后 `Partners` 表存在，表结构与 `design.md` 一致；`Partners.Name` 有唯一索引。
3. `POST /api/partners` 新增往来单位成功；重名（大小写不敏感）返回 `40102`。
4. `GET /api/partners` 分页 + 关键词 / 类型 / 状态筛选正确。
5. `GET /api/partners/{id}` 返回详情；不存在返回 `40400`。
6. `PUT /api/partners/{id}` 可改类型 / 联系人等字段，**名称不可改**（请求不含 name）；不存在返回 `40400`；类型收窄（供应商→客户、两者→单一类型）返回 `40119`，放宽（供应商 / 客户→两者）或保持原类型成功。
7. `PUT /api/partners/{id}/status` 启用 / 停用切换成功；不存在返回 `40400`。
8. 按类型筛选：`type=1` 仅返回供应商、`type=2` 仅返回客户、`type=3` 仅返回两者。
9. 前端「往来单位」页：列表 / 筛选 / 分页 / 新增 / 编辑 / 启停全部可用；编辑态按原类型**禁用会收窄的类型选项**（供应商 / 客户仅可保持或改「两者」，「两者」仅可保持）；侧边菜单「进销存」分组下「往来单位」可达。
10. `cd frontend && npm run build`、`npm run lint` 通过；`npm run test:e2e` 通过（含往来单位用例：建供应商 / 客户（重名 40102 提示）→ 停用后按 `status=1` 查询不含该单位）。
11. 代码与 `AGENTS.md`、backend / frontend 专项规则一致（分层、命名、注释语言、统一响应与错误码、字段约束单一来源、按钮 loading 约定）。

## 5. 范围外（不做）

- 往来单位对账 / 应收应付余额（由 erp-purchase / erp-sale 的结算简化方案承担：单据记金额 + 已结算 / 未结算状态位）。
- 删除往来单位（一律以停用代替，保留单据引用）。
- 往来单位分级 / 信用等级 / 账期等扩展档案。
- 角色 / 权限控制（RBAC）。
