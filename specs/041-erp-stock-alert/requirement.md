# 需求规格：库存预警通知（erp-stock-alert）

> 进销存扩展路线（`specs/ROADMAP.md`）P5 流程增强 第一项，依赖 `019`（流水 / 库存口径）与 `028`（权限：告警发给谁）。
> 本规格同时落地 `036` 范围外提到的「催收提醒」所需的**站内信通道**（催收规则本身仍属后续）。

## 1. 背景

低库存与临期 / 过期这些「需要人去做事」的信号，现在**只存在于页面上**：

- `014` / `038` / `040` 会把低于安全库存的行标红、把过期批次标红，但**没人会天天翻页面**；等到发现时已经断货或已经报废。
- 仓管 / 采购需要的是「系统主动来找我」，而不是「我去系统里找」。
- `ROADMAP` §6.5 明确：`041` 依赖定时任务能力与权限（谁能收到），因此放在权限体系（`028`）之后。

本规格引入**定时扫描 + 站内信**的最小闭环：扫描 → 去重 → 生成站内信 → 顶栏可见可点可读。

## 2. 目标

1. **定时扫描**：按配置间隔扫描三类信号 —— 低库存（按「商品 × 仓」汇总数量低于仓级安全库存）、近效期批次（`040`，≤ 30 天）、已过期批次（仍有库存）。
2. **站内信**：为**有权限的启用用户**生成站内信（标题 + 内容 + 跳转链接）；顶栏铃铛展示未读数，可查看最近消息并进入列表页。
3. **当日去重**：同一「信号对象 + 类型」**同一天只告警一次**（`AlertRecords` 唯一约束），避免每小时扫描刷屏。
4. **手动触发**：提供「立即扫描」入口（权限点 `notifications.scan`），便于验证与应急（同时让 e2e 可覆盖扫描结果）。
5. **可读可管理**：站内信列表（按类型 / 已读状态筛选 + 分页）、单条标记已读、全部已读；**不提供删除**（保留通知历史）。
6. **逻辑可测**：扫描逻辑放 `App.Core`（`IStockAlertScanner`，纯业务、可单测），定时任务只是薄封装（`BackgroundService`），不把业务写在宿主里。

## 3. 功能点

- **F1 数据模型**：`Notifications`（站内信）+ `AlertRecords`（告警去重台账），字段见 `design.md` §2。
- **F2 扫描能力**：`IStockAlertScanner.ScanAsync(utcNow)` → 扫描三类信号 → 去重 → 写入站内信 → 返回统计（各类型生成条数 / 跳过条数）。
- **F3 定时任务**：`StockAlertBackgroundService`（`BackgroundService`）按 `StockAlert:IntervalMinutes`（默认 60）周期执行；启动后延迟 1 分钟首跑；单次失败记日志不终止循环；`StockAlert:Enabled = false` 时不注册（便于开发与 e2e 稳定）。
- **F4 接收人解析**：具有 `inventory.view` 权限的**启用**用户（`028` 的 `IPermissionResolver` 的反向查询：按权限点找用户）；无匹配用户时记 warning 日志并跳过（不报错）。
- **F5 用例与接口**：`GetNotifications`（分页 + 类型 / 已读筛选）/ `GetNotificationSummary`（未读数）/ `MarkNotificationRead`（单条）/ `MarkAllNotificationsRead` / `ScanStockAlerts`（手动触发）。
- **F6 前端**：`AppLayout` 顶栏铃铛（未读 `a-badge`，下拉展示最近 5 条 + 「查看全部」）；`/notifications` 列表页（筛选 + 分页 + 标记已读 / 全部已读 + 「立即扫描」按钮）；点击消息**按链接跳转**对应页面（低库存 → 库存查询并预置筛选；批次 → 批次管理并预置商品）。
- **F7 e2e 覆盖**：制造低库存 → 点「立即扫描」→ 站内信出现（类型「低库存」）且铃铛未读数 +1；点击消息跳转库存查询并带筛选；标记已读后未读数 -1；同一天重复扫描不重复生成。

## 4. 验收标准

1. `cd backend && dotnet build` / `dotnet test` 通过（含三类信号扫描、当日去重、接收人解析、已读操作等单测；扫描逻辑不依赖定时器即可单测）。
2. `cd frontend && npm run type-check` / `npm run lint` / `npm run build` 全绿；`npm run test:e2e` 全量通过（含新增 `notification.spec.ts` 与既有用例回归）。
3. 手工验证：
   - 商品 A 在上海仓阈值 100、库存 10 → 手动扫描 → 有 `inventory.view` 权限的用户各收到 1 条「低库存」站内信；再次手动扫描（同一天）→ **不再新增**（去重生效）。
   - 次日（或改 `AlertDate`）再扫描 → 重新告警一次。
   - 批次 B 到期日为 10 天后 → 收到「近效期」；到期日为昨天且仍有库存 → 收到「已过期」。
   - 无 `inventory.view` 权限的用户**收不到**任何库存告警。
4. 顶栏：未读数与列表筛选「未读」条数一致；标记已读 / 全部已读后未读数同步归零；点击消息跳转正确（库存查询带 `warehouseId` + `categoryId`? 按实现约定见 `design.md` §4.4）。
5. 定时任务：`StockAlert:Enabled = true` 且间隔 60（分钟级）时按周期执行（日志可见）；扫描异常不影响服务（记录 error 后继续下一周期）。
6. 口径单一：低库存 / 近效期 / 过期判定只在 `design.md` §0 定义一次（分别引用 `038` §0 与 `040` §0），本规格不重复定义判定规则。

## 5. 范围外（不做）

- **邮件 / 短信 / 企业微信 / 钉钉推送**：只做站内信（外部通道需配置与凭据管理，另行评估）。
- **告警规则自定义**（用户自设阈值 / 自选接收对象）：阈值沿用仓级安全库存（`038`）与近效期天数（`040`，常量 30 天）；不做规则引擎与订阅偏好。
- **告警升级 / 值班 / 重复升级策略**：仅当日一次提醒，不做未处理升级。
- **应收逾期催收提醒**：`036` 已提供逾期数据；催收提醒规则（谁提醒、提醒几次）另行评估（本规格只交付通道）。
- **消息删除 / 归档 / 保留策略**：只标记已读，不删除。
- **消息模板管理**：文案硬编码在扫描器内（中文固定模板）。
- **批量操作（批量已读指定类型）**：只做单条已读与全部已读。
- **推送去重的跨天策略配置**（如「连续告警直到补货」）：固定「同日一次」，不做配置。
