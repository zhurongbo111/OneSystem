# 进销存功能路线图（ROADMAP）

> 定位：进销存（`erp-*`）功能组的**路线索引**，用于排定后续功能的批次、序号与依赖。
> 单一事实源：功能需求仍以各 `specs/<序号>-<feature>/` 为准（`AGENTS.md` §2.1）；本文件只写「做什么 / 为何按此顺序 / 依赖谁」，**不复制规格正文**（§10）。
> 序号 = 创建顺序（§2.1，三位定长、`001` 起，仅作目录排序，不属于功能名）；下表「顺序」列即推荐实现顺序，两者保持同向；确需插队时新功能取更大序号并在本表注明。
> 状态取值：`已实现`（`tasks.md` 全勾）/ `规格已起草`（三件套就绪，未开工）/ `待起草`（开工前按 §2.2 起草）。
> 维护：批次 / 序号 / 状态变化时更新本表；本表变更**不算**任何 spec 的正文变更（§2.5，不刷新其 `updated`）。

## 3. 批次划分与排序理由

| 批次 | 包含 | 为什么在这一批 |
|---|---|---|
| 一 · 账务地基 | `019`、`020` | 库存"可信"是一切下游能力的前提：报表、成本、往来对账、审计都要读变动明细；且越晚做，历史变动越无法补记（只能从上线日开始记）。`020` 紧随其后是因为**期初建账**解决"开账时库存怎么进系统"（现状只能靠开采购单造假），盘点解决"账实不符怎么修"，二者都依赖 `019` 的流水落账 |
| 二 · 单据与资金闭环 | `021`–`024` | 现状"作废重开"只能救误录，救不了真实退货；退货补齐后接收付款，把「单据 → 资金」闭环打通；两段式（订单 → 入库 / 出库）成本最高（引入状态机与在途量），放在退货 / 结算之后 |
| 三 · 决策与平台 | `025`–`029` | 有了流水才能出报表与成本；`028` 权限与 `029` 审计是运营化的前置（现状任何登录用户可见全部菜单与数据）；导出 / 打印是高频但独立的小功能，可随时插入 |
| 四 · 精细化 | `030`–`034` | 多仓、调拨、批次 / 保质期、价格策略、发票均属规模或行业特化需求，**默认单仓经营时不做**；启用多仓需先确认业务确有多点经营（见 §4.2） |
| 五 · 流程增强 | `035`、`036` | 预警通知依赖定时任务能力与权限（谁能收到）；审批流依赖组织与权限模型，属于管理成熟后才需要的层 |

## 4. 跨功能前置决策（后续规格共同遵守）

### 4.1 库存流水是所有下游能力的地基

`019` 的流水表是报表（`025`）、成本（`026`）、盘点（`020`）、多仓（`030`）、库存预警（`035`）的共同数据源。任何"新增一种库存变动来源"的功能（退货、调拨、盘点）都必须在**同一事务内**追加流水，不允许出现"库存变了但无流水"。

### 4.2 多仓库：默认不做，接入时有既定路径（修正早期判断）

- 现状**按单仓设计**（`Inventory` 唯一键 `ProductId`）。是否上多仓取决于是否存在两个以上物理存放点且需要分别掌握各点数量、需要调拨。
- **修正**：早前"流水表必须预留 `WarehouseId` 列"的判断过重，现改为**不预留**。理由：PostgreSQL 加列（含 `NOT NULL` + 默认值）是元数据操作，且流水表是纯追加表、无涉及仓库维度的唯一索引，多仓接入时为"增量迁移加列 → 回填默认仓 → 补索引"即可，不构成返工；反过来现在放一个恒为空的列会污染所有写入路径的语义。
- `030` 落地时的既定动作（届时写进该 spec）：`Inventory` 唯一键改 `(ProductId, WarehouseId)` + 回填默认仓；`StockMovements` 增 `WarehouseId` 并回填；采购 / 销售单增仓库字段；库存不足判定与安全库存按仓；调拨单独建单（`031`）。

### 4.3 结算：`SettlementStatus` 升级路径

`015` §5 已预留：`023` 把单据上的 `0/1` 状态位替换为「已结算金额 + 状态（未结 / 部分 / 结清）」，历史数据按原状态位迁移（`1 → 已结算金额 = 总额`）。收付款单与应收应付以往来单位为主键聚合，单据与收付款明细建立核销关系。

### 4.4 单据编辑：不单独做，由两段式（`024`）覆盖

一步式单据下"改单"等价于"作废重开"（`015` §5 已定），无需独立编辑功能。`024` 引入两段式后，**订单可编辑、出入库单仍不可编辑**，编辑诉求即被覆盖。

### 4.5 权限：`028` 之前，新功能沿用"登录即可见"

`028` 之前新增的菜单与接口不做权限判断；`028` 落地时统一为既有功能补齐菜单级 / 按钮级权限，并在前端隐藏无权限入口（`40300` 从预留码转为生产码）。

### 4.6 规格与规则联动

- 新增功能按其"改动类型"消费既有交互约定正文（对照表见 `.codebuddy/CONTEXT.md` §6），不重复定义。
- 新功能若改变既有规格的既定决策（例如 `019` 修订 `014` 的"库存查询页无操作列"），必须**同时**在双方 `design.md` 留注记（`012` design §4.1 的"演进"注记为格式范例）。

## 5. 范围外（明确不做）

- **WMS 级仓储作业**：库位 / 波次 / 拣货路径 / 装箱，属仓储执行系统范畴，不进本路线。
- **财务级账务**：总账、凭证、期末结转；应收应付只做到往来对账与收付款核销（`023`）。
- **电商 / 门店前台**：线上商城、POS、会员积分。
- **税务合规**：发票只做登记与关联（`034`），不做开票接口对接与税控。
- **多组织 / 多公司**：本路线只覆盖单组织实体。
