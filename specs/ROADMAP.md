## 1. 范围定义：ERP 内核 与 外围系统

一句话边界：**ERP 管"账"（钱与物与账务），外围系统管"执行与外延"（客户 / 人 / 作业）**。
业务形态：**纯贸易 / 分销**（买成品卖成品，不改变物料形态）——**不做生产制造**（见 §6.9）。

| 系统 | 定位 | 与本项目关系 | 路线处置 |
|---|---|---|---|
| **ERP 内核** | 财务 · 供需链 · 主数据 · 平台 | 现状主体 | **本路线主线** |
| **HCM**（人力资本） | 组织 / 岗位 / 员工 / 考勤 / 薪酬 | 现仅有登录账号（`009`），无组织与员工 | **并入主线**：组织 · 岗位 · 员工先行；考勤 · 薪酬后置 |
| **CRM**（客户关系） | 售前 / 客户经营 / 服务 | 交易侧（客户 · 订单 · 回款 · 客户价）已由内核覆盖 | **并入主线**：报价先行；线索 · 商机 · 服务后置 |
| **WMS**（仓储执行） | 库位 / 波次 / 拣货 / 装箱 / RF | 全无 | **独立立项**，不进主线，以单据接口集成 |
| **SRM**（供应商协同） | 询价 / 对账 / 门户 | 全无 | 后期 / 独立 |
| **MES**（制造执行） | 派工 / 报工 / 设备采集 | 全无 | **不做**（纯贸易无生产，见 §6.9） |
| **PLM**（产品数据） | BOM / 图文档源头 | 全无 | **不做**（纯贸易无生产，见 §6.9） |
| **OA**（办公协同） | 公告 · 日程 / 会议 · 任务待办 · 公文收发 · 行政事务 | 全无（轻量审批已由 `042` 覆盖，站内信通道由 `041` 提供，组织 / 员工由 `030` 提供） | **并入主线**：新增 P10（`060`–`063`，见 §6.11）；**复用** `041` / `042` / `030`，**不新建审批引擎** |
| 通用深度 BI | 自助取数 / 报表设计器 / 数仓 | 业务报表已由 `025` / `033` 覆盖 | 不单独做 / 后期 |

**边界判定要点**（防混淆）：

- **ERP 库存 ≠ WMS**：ERP 管库存台账（数量 / 金额 / 成本）与多仓 / 调拨 / 批次；WMS 管库位与作业执行。`038` / `039` / `040` 是 ERP 库存精细化，**不等于** WMS。
- **ERP 生产计划 ≠ MES / PLM**：前者管 BOM / MRP / 生产订单（计划与账）；后二者管工序执行与产品数据源头。**本路线为纯贸易，生产制造 / MES / PLM 均不做**（见 §6.9）。
- **组织模型是 HCM 与权限 / 审批的交汇点**：`028` 数据级权限与 `042` 审批流依赖组织 / 岗位 / 员工，须与组织模型一并设计（`028` §5「不做组织模型」据此修订）。
- **OA 协同 ≠ 内核审批 / 通知**：单据审批闸门（阈值 → 待审批 → 通过才生效）仍归 `042`，消息通道仍归 `041`；`060`–`063` 只做「办公协同对象」（公告 / 日程 / 任务 / 公文 / 行政申请），**不新建第二套审批引擎**（`063` 的固定单级审批复用 `042` 的审批人 / 自审禁止口径）。

## 2. 模块地图（内核 5 层 + 外围）

```
ERP 内核
├─ L5 分析与决策   经营报表 / 财务三大报表 / BI
├─ L4 财务         总账GL · 应收应付 · 资金出纳 · 成本 · 发票税务 ·（预算·固资）
├─ L3 供需链       采购 · 销售 · 库存
├─ L2 主数据       物料 · 往来 · 仓库 · 价格政策 · 财务主数据
├─ L1 平台底座     组织 · 权限 · 审计 · 审批 · 通知 · 集成
└─ 人力域(HCM)     组织岗位 · 员工档案 ·（考勤 · 薪酬 · 招聘绩效）
└─ 办公协同(OA)    公告 · 日程 · 任务 · 公文 · 行政事务
外围系统（按需，独立立项）
├─ CRM   客户与售前 / 服务
├─ WMS   仓储作业执行
└─ SRM   供应商协同
（MES 制造执行 / PLM 产品数据 / 生产制造：纯贸易不做，见 §6.9）
```

> 每层的功能需求仍以对应 `specs/<序号>-<feature>/` 为准；本图为**边界与归属**，不复制正文。

## 5. 阶段划分与排序理由

| 阶段 | 包含 | 为什么在这一阶段 |
|---|---|---|
| **P1 · 平台地基** | `028`、`029`、组织 / 员工 | 完整 ERP 的前置是"有事可管、有据可查"：权限与审计决定谁能做什么、做过什么；组织 / 员工是数据级权限与审批流的共同前置，早做免得返工（`028` 原排除组织模型，据此修订） |
| **P2 · 财务闭环** | 财务主数据、`032`、总账 GL、资金出纳 | **从"进销存"升级为 ERP 的分水岭**：先把发票纳入，再建总账让单据自动生成凭证、出三大报表；财务主数据（科目 / 税率 / 账户）是总账前置；资金出纳补齐 `023` 之外的现金视角 |
| **P3 · 主数据与政策** | `036` / 报价单（**均已交付**；原含的单位字典 `035` 已列范围外） | 主数据完整度决定后续所有单据的规范度；`036` 给销售加"取价 + 授信"闸门；报价单承接 CRM 前段 |
| **P4 · 库存精细化** | `038`、`039`、`040` | 多仓、调拨、批次属规模 / 行业特化，**默认单仓经营时不做**；启用多仓须先确认确有多点经营（见 §6.2） |
| **P5 · 流程增强** | `041`、`042`、CRM 售前 | 预警依赖定时任务与权限；审批依赖组织与权限；CRM 售前依赖报价与客户主数据。管理成熟后才需要 |
| **P6 · 外围增强** | HCM 薪酬、CRM 服务、WMS / SRM | 人力 / 服务按需；`WMS` / `SRM` 为独立系统，不进主线。**生产制造 / MES / PLM 已确认不做**（纯贸易，见 §6.9） |
| **P7 · 内核收口与运营** | 数据级权限、逾期应收提醒、期初建账 / 期末结转 / 年结、经营看板、编码规则 | `028`–`045` 已把"能做什么 / 做过什么 / 账在哪"铺开，收口项未做：数据级权限是 `028` 的最后缺口（`030` 已备前置）；期末结转是总账从"能出报表"到"能结账"的分界；看板与提醒把既有数据转成运营动作（成本低、收益直接）；编码规则是主数据规范化的收尾。**均已具备前置，故列为下一批（规格已起草）** |

### 6.1 库存流水是所有下游能力的地基

`019` 的流水表是报表（`025`）、成本（`026`）、盘点（`020`）、多仓（`038`）、库存预警（`041`）的共同数据源。任何"新增一种库存变动来源"的功能（退货、调拨、盘点）都必须在**同一事务内**追加流水，不允许出现"库存变了但无流水"。

### 6.2 多仓库：默认不做，接入时有既定路径（修正早期判断）

- 现状**按单仓设计**（`Inventory` 唯一键 `ProductId`）。是否上多仓取决于是否存在两个以上物理存放点且需要分别掌握各点数量、需要调拨。
- **修正**：早前"流水表必须预留 `WarehouseId` 列"的判断过重，现改为**不预留**。理由：PostgreSQL 加列（含 `NOT NULL` + 默认值）是元数据操作，且流水表是纯追加表、无涉及仓库维度的唯一索引，多仓接入时为"增量迁移加列 → 回填默认仓 → 补索引"即可，不构成返工；反过来现在放一个恒为空的列会污染所有写入路径的语义。
- `038` 落地时的既定动作（届时写进该 spec）：`Inventory` 唯一键改 `(ProductId, WarehouseId)` + 回填默认仓；`StockMovements` 增 `WarehouseId` 并回填；采购 / 销售单增仓库字段；库存不足判定与安全库存按仓；调拨单独建单（`039`）。
- **已落地（`038`，2026-09-23）**：上述既定动作全部完成，且比原判断多两项必要修订——① **成本随库存行按仓维护**（组织级 = 各仓合计），否则每行均价与出库结转单价失真；② 迁移内 `InsertData` 插入**固定 GUID 默认仓**（`00000000-0000-0000-0000-000000000001`）供 SQL 回填引用，并回填五类单据的仓与仓名快照。默认仓不可停用（`40124`）、停用仓不可停用 / 不进入开单下拉（`40123`）。**状态转「已实现」**：`dotnet test` 1055 通过 + `npm run e2e:run` 全量 166 通过。

### 6.3 结算：`SettlementStatus` 升级路径

`015` §5 已预留：`023` 把单据上的 `0/1` 状态位替换为「已结算金额 + 状态（未结 / 部分 / 结清）」，历史数据按原状态位迁移（`1 → 已结算金额 = 总额`）。收付款单与应收应付以往来单位为主键聚合，单据与收付款明细建立核销关系。

### 6.4 单据编辑：不单独做，由两段式（`024`）覆盖

一步式单据下"改单"等价于"作废重开"（`015` §5 已定），无需独立编辑功能。`024` 引入两段式后，**订单可编辑、出入库单仍不可编辑**，编辑诉求即被覆盖。

### 6.5 权限与组织：`028` 落地时统一补齐

`028` 之前新增的菜单与接口不做权限判断（"登录即可见"）；`028` 落地时统一为既有功能补齐菜单级 / 按钮级权限，并在前端隐藏无权限入口（`40300` 从预留码转为生产码）。**组织 / 部门 / 岗位 / 员工模型与 `028` 的开发同期或先行**，作为数据级权限与 `042` 审批流的前置；`028` §5「不做组织模型」据此修订（`2026-09-20` 升级 ERP 时确定）。

> **进度（`2026-09-22`）：`028` 已实现**——后端全部 Controller 动作已标注权限点并由集成测试守卫（漏标即拒绝）、`40300` 已由预留码转为生产码（`AGENTS.md` §4.2 同步）、角色域用例与迁移回填完成（`dotnet test` 605 通过）；前端菜单 / 按钮过滤、角色管理页、`/403` 页已落地，`npm run test:e2e` 131 通过。**既有功能「登录即可见」的时代结束**：无权限入口隐藏、无权限动作返回 `40300`。剩余缺口为数据级权限，依赖 `030` 组织 / 员工模型。

## 7. 范围外（明确不做）

- **生产制造（BOM / MRP / 生产订单）**：用户确认**纯贸易、不生产**（`2026-09-20`），不做。
- **计量单位字典（`035`，`2026-09-23` 定性不做）**：单位继续沿用 `012` 商品的 `Unit` **自由文本 + 名称快照**语义。理由：一期收益集中在"写法归一"，而改造需给 `Products` 加 `UnitId` NOT NULL 并做数据回填迁移，投入到现有 8 张单据明细的换算 / 统计口径收益不匹配；后续若确有多单位换算（箱 / 包 → 基本单位）需求，届时连同单位字典一并另立规格。
- **MES / PLM**：制造执行 / 产品数据源头，随"不做生产"一并出局。
- **WMS 级仓储作业**（库位 / 波次 / 拣货 / 装箱 / RF）：属仓储执行系统，**独立立项**，不进本主线（见 §1）。
- **SRM**：供应商协同（询价 / 对账 / 门户），按需独立立项。
- **序列号 / 逐件追溯**：`040` 只做批次 + 保质期；一物一码、逐件出入库核对与全链路追溯属另一套模型，未纳入本路线（如需另立规格）。
- **多公司 / 多组织 / 合并报表**：先单主体经营，**仍为待启用**；规格已起草（`057` / `058`），**确有多主体经营时启动**（见 §6.10）。
- **预算 / 固定资产 / 费用报销**：本阶段总账只做"业务财务一体"；规格已起草（`052`–`054`），按业务场景确认后启用（见 §6.10）。
- **绩效管理**：自 `056` 范围拆出，记 `059`（待评估）；`ROADMAP` §4.2 已登记。
- **深度税务**：发票只做登记与关联（`032`），不做开票接口对接与税控。
- **电商 / 门店前台**：线上商城、POS、会员积分。
- **通用工作流引擎**：多级 / 会签 / 可配置流程设计器**不做**；`042` 保持单级阈值审批，OA 行政事务（`063`）用固定单级审批（见 §6.11）。
- **通用深度 BI / 数仓**：自助取数、报表设计器、数据仓库不做；业务报表由 `025` / `033` 覆盖。
- **OA 的深度功能**：外部日历同步（CalDAV / Exchange）、会议室资源占用冲突检测、公文密级与电子签章、OA 移动端 App、公告附件与评论点赞——均不做；OA 协同主线见 P10（`060`–`063`，§4.2 / §6.11）。
