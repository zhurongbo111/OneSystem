# 需求规格：销售出库（erp-sale）

## 0. 进销存功能组定位

本规格是**进销存（ERP）功能组**的销售单据域，**继承 erp-purchase 的单据域共用约定**（见下）：

| 子规格 | 内容 | 依赖 |
|---|---|---|
| erp-product | 商品分类 / 商品档案 / 库存台账（Inventory + 原子增减 API） | 无 |
| erp-partner | 往来单位（供应商 / 客户） | 无 |
| erp-inventory-query | 库存查询页 | erp-product |
| erp-purchase | 采购入库单 + **单据域共用约定** | erp-product + erp-partner |
| **erp-sale（本规格）** | 销售出库单 | erp-purchase（共用约定）+ erp-product + erp-partner |

前置条件：**erp-purchase 已交付**（`PurchaseOrders` 表、`OrderStatus` / `OrderSettlementStatus` 枚举、`OrderFieldConstraints` 常量、`IOrderRepository` 同构仓储模板、`GenerateOrderNoAsync` 单号生成、共用错误码 40104 / 40108 / 40109 / 40110 均已存在）；erp-product（`Inventory` + `TryDecrementAsync` 原子条件扣减、`GET /api/products/pick` 开单商品选择含当前库存）与 erp-partner（`Partners` 按类型 / 状态筛选）已交付。

**继承关系**：本规格的 `SalesOrders` / `SalesOrderItems` 与 erp-purchase 的 `PurchaseOrders` / `PurchaseOrderItems` **结构完全同构**，实现时照抄 erp-purchase 模板，按 erp-purchase design §0「替换规则」做三处差异替换（前缀 `SO` / 客户方向 / 库存 `TryDecrementAsync`），其余逐条一致，**不重复定义**共用枚举 / 常量 / 单号生成 / 校验结构。本规格仅定义**销售特有**的部分：`40103` 库存不足错误码、`TryDecrementAsync` 防超卖、库存不足回滚、前端库存预警标红。

## 1. 背景

进销存 MVP 的销售环节：选择客户 + 多行商品明细（数量、单价），保存后**库存减少**、单据产生**应收**（简化结算：单据只记金额 + 已结算 / 未结算状态，不做独立收付款单与对账）。

- **禁止负库存**：销售数量超过当前库存时**整体拒绝**（报出首个不足商品），事务回滚，库存无任何变化。
- 仓库模型：单仓库（消费 erp-product 的 `Inventory`）。
- 单据流程：**一步式**——保存即生效（库存立即减少、应收口径立即产生），不支持编辑，只支持**作废**（库存回冲）。
- 明细单价为**保存时快照**（默认带出商品销售价、可修改），后续改商品价不影响历史单据。
- 客户校验：`Type in (Customer, Both)` 且启用（消费 erp-partner）。
- 商品校验：仅启用商品可入明细（消费 erp-product 开单选择接口）。

## 2. 目标

1. 可开**销售出库单**：选择客户（仅启用 + 类型匹配）、日期（默认当天）、多行明细（选商品 / 数量 / 单价，单价默认带出商品销售价、可改）；小计 = 数量 × 单价，总金额 = Σ 小计（**后端重算，不信任前端**）；保存时**逐行校验库存**（`TryDecrementAsync`，任一行 `Quantity < amount` → 整体拒绝 `40103`，message 含首个不足商品名），通过则**每行库存 -= 数量**，单据生成单号（`SO + yyyyMMdd + 4 位序号`）、结算状态为「未结算」。
2. 销售单支持**列表 / 详情 / 作废 / 结算标记**：
   - 列表：分页 + 单号 / 客户 / 日期范围 / 结算状态筛选，按创建时间倒序；作废行置灰。
   - 详情：表头（单号 / 客户 / 日期 / 总金额 / 结算状态）+ 明细行（商品 / 数量 / 单价 / 小计，均为快照）。
   - 作废：仅未作废单据可作废；作废后**库存 += 各明细数量**（回冲）、状态置「已作废」、前端展示作废态并禁止再操作。
   - 结算标记：未结算 / 已结算手动切换（简化结算，不做部分收款）；已作废单据禁止切换。
3. 开单页**库存预警**：明细行选商品后展示当前库存，数量 > 库存时该行数量**标红预警**（前端提示，最终以后端 `40103` 为准）。
4. 侧边菜单「销售」分组下提供「销售出库」子项；开单为独立页面，详情为独立页面。

## 3. 功能点

- **F1 销售单列表**：分页查询，支持按单号关键词 / 客户 / 日期范围 / 结算状态筛选；按创建时间倒序；作废行置灰。
- **F2 新增销售单**：选择客户（仅启用的）、日期（默认当天）、多行明细（选商品 / 数量 / 单价，单价默认带出商品销售价、可改）；保存时**逐行校验库存**：任一行数量 > 当前库存 → **整体拒绝**（报出首个不足商品，`40103`），通过则**每行库存 -= 数量**（事务内完成扣减 + 插单 + 明细，失败整体回滚）；小计 / 总额后端重算（**不信任前端传值**）；单据生成单号（`SO + yyyyMMdd + 4 位序号`）、结算状态为「未结算」。
- **F3 销售单详情**：表头 + 明细行（商品 / 数量 / 单价 / 小计）；**明细单价 / 商品名 / 单位为保存时快照**，后续改商品档案不影响。
- **F4 销售单作废**：仅未作废单据可作废；作废后**库存 += 各明细数量**（回冲）、状态置「已作废」；前端展示作废态并禁止再操作（作废 / 结算入口消失）。
- **F5 销售单结算标记**：未结算 / 已结算手动切换（简化结算，不做部分收款）；已作废单据禁止切换。
- **F6 开单页（独立页面）**：客户下拉（仅启用 + `Type in (2,3)`）、明细可编辑表格（商品下拉带库存展示、数量、单价默认带出销售价、小计实时计算展示）、添加 / 删除行、总额实时计算、**数量 > 库存行内标红预警**、提交成功后跳详情。
- **F7 前端菜单**：侧边菜单「销售」分组下提供「销售出库」子项；详情路由 `sales/detail/:id` 归属该菜单高亮。分组结构唯一来源见 `specs/025-erp-report/design.md` §0.2。

## 4. 验收标准

1. `cd backend && dotnet build` 成功（net8.0）；`dotnet test` 全部通过。
2. 执行 EF Core 迁移后 `SalesOrders`、`SalesOrderItems` 表存在，表结构与 erp-purchase design §2 同构（前缀 `SO`，`PartnerName` 为客户快照）；`SalesOrders.OrderNo` 有唯一索引；明细 `OrderId` 有索引。
3. `POST /api/sales-orders` 库存充足时保存成功返回单号（格式 `SO + yyyyMMdd + 4 位序号`）；库存按明细减少（`GET /api/inventory` 可验证）；小计 / 总额由后端重算。
4. **超卖拦截**：任一行数量 > 当前库存时整体失败，返回 `40103`（message 含首个不足商品名），**库存无任何变化**（事务回滚，单据未落库）；并发场景（两请求同时销售同一商品且合计超过库存）最多一个成功（`TryDecrementAsync` 条件更新保证）。
5. `POST /api/sales-orders` 其余业务失败路径：明细为空 → `40110`；客户不存在 → `40400`；客户停用 → `40108`；客户类型不含 Customer（纯供应商）→ `40109`；商品停用 → `40107`；商品不存在 → `40400`。
6. `GET /api/sales-orders` 分页 + 单号关键词 / 客户 / 日期范围 / 结算状态筛选正确；按创建时间倒序；作废单据也返回。
7. `GET /api/sales-orders/{id}` 返回表头 + 明细（快照字段正确）；不存在返回 `40400`。
8. `PUT /api/sales-orders/{id}/void`：作废后库存回冲（各明细 `库存 += 数量`）、状态 `voided`；不存在返回 `40400`；已作废再作废返回 `40104`。
9. `PUT /api/sales-orders/{id}/settlement`：未结算 / 已结算切换成功；对已作废单据操作返回 `40104`；不存在返回 `40400`。
10. 日期范围筛选：前端将所选日期转为本地当天 00:00:00 / 23:59:59 的 UTC ISO 串，后端按 `timestamptz` 闭区间直接比较（同登录日志既有约定）。
11. 事务性：库存扣减 + 插单 + 明细在同一事务，任一环节失败整体回滚（单据不落库、库存不变）。
12. 前端「销售出库」5 个页面全部可达（列表 / 开单 / 详情）：
    - 列表：筛选（含日期范围 / 结算 / 客户）+ 表格（作废行置灰）+ 操作列（详情 / 作废 / 结算）+ 分页。
    - 开单：客户下拉 + 明细行增删 + 单价默认带出销售价 + **数量 > 库存行内标红** + 小计 / 总额实时计算 + 提交成功跳详情 + 库存不足提交被后端拦截并展示错误提示（页面停留）。
    - 详情：表头 + 明细只读 + 作废确认（popconfirm）+ 结算切换 + 404 result。
13. `cd frontend && npm run build`、`npm run lint` 通过；`npm run test:e2e` 通过（含销售出库用例：开单（数量 ≤ 库存）→ 保存成功 → 库存减少 → **超卖场景：数量 > 库存提交 → 错误提示 + 库存不变** → 作废确认 → 库存回冲 → 单据状态「已作废」且操作消失）。
14. 代码与 `AGENTS.md`、backend / frontend 专项规则一致（分层、命名、注释语言、统一响应与错误码、字段约束单一来源、按钮 loading 约定）；与 erp-purchase 单据域模板一致（不重复定义共用枚举 / 常量 / 单号生成）。

## 5. 范围外（不做）

- 销售单编辑（一步式 + 快照设计下，改单 = 作废 + 新单）。
- 删除销售单（一律以作废代替，保留审计轨迹）。
- 折扣、运费、税点等单据附加金额字段（总金额 = Σ 数量 × 单价）。
- 完整收付款：独立收款单、部分结算、应收对账报表、逾期提醒（结算仅状态位手动切换）。
- 单据草稿 / 审核流（两步式）、单据打印 / PDF 导出、条码扫码开单。
- 销售统计报表（销售金额 / 毛利分析等）。
- 负库存销售（严格禁止，超卖一律拒绝；不做「允许超卖」开关）。
- 并发下的独立幂等 token（重复提交由前端防重入 + 后端单号唯一索引兜底；MVP 并发量下足够）。
