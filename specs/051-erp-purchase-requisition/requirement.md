# 需求规格：采购请购单（erp-purchase-requisition）

> ERP 全域路线（`specs/ROADMAP.md` §4.2）**P8 深化**项（**待评估**：须业务场景确认后启用）；补齐 `ROADMAP` §3「L3 采购」的「请购（按需评估）」缺口。
> 依赖：`024`（采购订单 `PO` / 两段式）、`012`（商品）、`030`（员工 —— 申请人）、`037`（三态转单范式参照）、`028`（权限）。
> 范围克制：只做**请购单 + 转采购订单**；不做请购审批流、比价 / 询价、采购申请预算控制、多级签核。

## 1. 背景

`024` 建成了「采购订单 → 采购入库」两段式，但**订单之前的"需求提出"环节缺失**：

- 部门要买东西，走线下申请（微信 / 口头 / 邮件），审批与需求记录散落，采购员"照着补单"容易漏项、错量。
- 采购订单一旦开立即已决策，缺少"需求 → 集中采购"的前置单据，无法回答"这批货是谁提的、什么时候提的、期望何时到"。
- `037` 已用「三态（草稿 / 已转 / 已作废）+ 一次性转单」范式实现了报价单 → 销售订单，同一范式可平移到采购前段。

本规格补上采购链路的**最前端**：请购单 → 转采购订单。

## 2. 目标

1. **请购单**：登记需求（申请人 / 日期 / 期望到货 / 明细商品与数量 / 预估单价），三态流转（草稿 → 已转订单 / 已作废）。
2. **转采购订单**：草稿请购单一次性转采购订单（明细复制、订单日期 = 转单当天），同事务回写锁定。
3. **不触碰库存 / 资金**：请购是需求单，不动库存台账、不写流水、不产生应收应付（同报价单）。
4. **权限与菜单**：权限点续行 `028` §0.2（`purchaseRequisitions.*`）；菜单「采购」分组续行首位（`025` §0.2）。
5. **前端**：请购单列表 / 表单页 / 详情（转单 / 作废）；**e2e 覆盖**。

## 3. 功能点

- **F1 列表**：`GET /api/purchase-requisitions`（单号 / 申请人 / 商品关键词、状态、日期区间筛选 + 分页）。
- **F2 登记 / 编辑**：`POST`、`PUT /{id}`（**仅草稿可编辑**，非草稿 → `40183`）；单号 `RQ + yyyyMMdd + 4`。
- **F3 作废**：`PUT /{id}/void`（仅草稿，非草稿 → `40183`）。
- **F4 转采购订单**：`POST /{id}/convert`（仅草稿、只能转一次，否则 → `40184`）；同事务建 `PO` + 回写请购单。
- **F5 权限与菜单**：`028` §0.2 续行 `purchaseRequisitions.*`；`025` §0.2「采购」分组续行首位。
- **F6 e2e**：建请购 → 转采购订单 → 采购订单列表可见该单；非草稿编辑 `40183`。

## 4. 验收标准

1. `cd backend && dotnet build` / `dotnet test` 通过（状态限制、转单一致性、非草稿限制）。
2. `cd frontend && npm run type-check` / `npm run lint` / `npm run build` 全绿；`npm run test:e2e` 全量通过（新增 `purchase-requisition.spec.ts`）。
3. 手工验证：
   - 建请购单（申请人 A、明细 2 行）→ 转采购订单 → 采购订单列表出现同明细的 `PO` 单，请购单置「已转订单」。
   - 已转订单的请购单再编辑 / 再转 / 作废 → `40183` / `40184`。
   - 请购单不影响库存 / 流水 / 应收应付。
4. 口径单一：状态取值 / 转单判据 / 单号前缀只在 `design.md` §0 定义一次。
5. 联动：`028` §0.2 续行、`025` §0.2「采购」分组续行、`ROADMAP` §6.7 单号前缀续行（`RQ`）、`ROADMAP` §6 错误码续行。

## 5. 范围外（不做）

- **请购审批流 / 多级签核**：本期三态即可（草稿即未提交）；如需接入 `042` 单据审批另评。
- **询价 / 比价 / 供应商选择**：请购不指定供应商（转订单时在订单上选）。
- **预算控制 / 请购占用预算**：`054-erp-budget` 待评估，本期不联动。
- **请购与采购订单的部分转单 / 分批转**：一次性全量转单（同 `037` 报价单）。
- **请购来源（库存预警自动生成请购 / MRP）**：不做（纯贸易，`ROADMAP` §6.9）。
- **请购单导出 / 打印**：一期不做（如需复用 `027` 另评）。
- **需求部门 / 项目归属维度**：本期只有申请人，无部门 / 项目字段。
