# 需求规格：库存流水（erp-stock-movement）

> 本规格是进销存扩展路线（`specs/ROADMAP.md`）已完成（账务地基），为后续报表、成本、盘点、多仓的共同数据源。

## 1. 背景

现状 `Inventory` 只保存商品的**当前**库存（`Quantity` + `UpdatedAt`）：库存从 10 变成 7，系统无法回答「何时、因哪张单据、谁操作」。采购 / 销售单据虽然含明细，但库存还可能因作废回冲、后续盘点反复变动，无法从单据反推库存轨迹；库存页的「最近变动时间」只是唯一线索。

库存数据要可信，前提是**每一次变动都可追溯**；并且路线图中 `020` 盘点、`025` 报表、`026` 成本核算、`041` 预警都直接消费变动明细。因此先把变动流水补齐，且越早越好——流水只能从上线日开始记，历史变动无法补。

## 2. 目标

1. 新增库存流水表，记录每次库存变动的商品、变动量、变动类型、来源单据、操作人与时间。
2. 现有四类库存变化（采购入库、采购作废回冲、销售出库、销售作废回冲）全部写入流水，且与库存变化在**同一事务**内完成。
3. 提供库存流水查询：列表页（按单号 / 商品 / 变动类型 / 时间范围筛选，服务端分页），并支持从库存查询页按商品下钻。
4. 流水可用于对账：同一商品的流水变动量合计恒等于其当前库存（作为一致性单测与后续盘点校验依据）。

## 3. 功能点

- F1 流水表 `StockMovements`（字段、索引、枚举见 `design.md` §2）；纯追加，无更新 / 删除。
- F2 **写入接入**（改造既有用例，均在其既有 `IUnitOfWork` 事务内追加一条流水）：
  - `Purchases/CreatePurchaseOrder` → 采购入库（每行 `+quantity`）；
  - `Purchases/VoidPurchaseOrder` → 采购作废（每行 `−quantity`）；
  - `Sales/CreateSalesOrder` → 销售出库（每行 `−quantity`）；
  - `Sales/VoidSalesOrder` → 销售作废（每行 `+quantity`）。
- F3 查询接口 `GET /api/stock-movements`（分页 + 筛选）。
- F4 前端「库存流水」页（`/stock-movements`，列表 + 筛选 + 分页）；库存查询页新增操作列「流水」，跳转该页并预置所选商品筛选。
- F5 e2e 覆盖：采购入库 → 流水出现 `+N`（类型「采购入库」、带来源单号）；该单作废 → 新增 `−N`（类型「采购作废」）；销售出库 / 销售作废同理；筛选（商品 / 类型 / 单号）生效。

## 4. 验收标准

1. `cd backend && dotnet build` / `dotnet test` 通过（含 `GetStockMovements` 用例、四个既有 Handler 的流水写入断言与事务回滚断言）。
2. `cd frontend && npm run type-check` / `npm run lint` / `npm run build` 全绿。
3. `cd frontend && npm run test:e2e` 全量通过（含新增 `stock-movement.spec.ts` 与既有采购 / 销售 / 库存用例回归）。
4. 手工验证：新建采购单（某商品 +10）→ 库存流水页出现一条 `+10`，类型「采购入库」、来源单号为该采购单号、操作人为当前用户；作废该单 → 新增一条 `−10`，类型「采购作废」、来源同一单号；销售出库 / 销售作废同理（方向相反）。
5. 同一商品：**Σ 流水变动量 == `Inventory.Quantity`**（单测覆盖）。
6. 事务性：采购 / 销售用例在库存写入后任一环节失败时，库存与流水**同时回滚**（单测覆盖 `RollbackAsync`）。

## 5. 范围外（不做）

- **期初建账与盘点调整**：属 `020-erp-stock-take`（本规格只接入采购 / 销售两个来源）。
- **变动前 / 变动后库存列**：不落列，结存由变动量序列累计推导（理由见 `design.md` §5）。
- **报表与成本核算**：`025` / `026`。
- **流水导出 / 打印**：`027`。
- **多仓库维度**：`038`（届时为流水表增量加列，见 `specs/ROADMAP.md` §6.2）。
- **不做流水更正 / 删除接口**：纠错一律通过新的反向流水（作废回冲即此模式）。
- **不改动库存增减的原子实现**：沿用 `012-erp-product` 的 `IncrementAsync` / `TryDecrementAsync`。
