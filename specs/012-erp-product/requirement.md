# 需求规格：商品管理（erp-product）

## 0. 进销存功能组定位

本规格是**进销存（ERP）功能组**的商品域底座，为后续进销存子规格的前置依赖：

| 子规格 | 内容 | 依赖 |
|---|---|---|
| **erp-product（本规格）** | 商品分类 / 商品档案 / 库存台账 | 无（可与 erp-partner 并行） |
| erp-partner | 往来单位（供应商 / 客户） | 无（可与本规格并行） |
| erp-category | 商品分类独立管理页（本规格分类弹窗的前端形态演进，后端零改动） | 本规格 |
| erp-inventory-query | 库存查询页 | 本规格 |
| erp-purchase | 采购入库单 | 本规格 + erp-partner |
| erp-sale | 销售出库单 | erp-purchase（单据域共用约定）+ 本规格 + erp-partner |

实现顺序：本规格与 erp-partner 可并行开发；erp-inventory-query / erp-purchase 须待本规格交付（表结构与接口可联调）后进行。

## 1. 背景

底座已具备登录 / JWT、用户管理、登录日志与前后端完整骨架（`user-management` 已交付）。进销存 MVP 整体需求已按功能拆分为多个可独立实现的子规格（见 §0），本规格负责**商品管理**，含商品分类维护与库存台账：

- 商品档案、商品分类、库存台账是后续往来单位开单（erp-purchase / erp-sale）与库存查询（erp-inventory-query）的数据基础。
- 仓库模型：**单仓库**（全局一个库存，库存记录与商品一对一）。
- 商品模型：**简单 SKU**（编码 / 名称 / 单级分类 / 单位 / 采购价 / 销售价 / 安全库存阈值）。
- 商品：编码创建后不可修改；停用不删除（保留历史单据引用）。
- 分类：单级字典，无停用状态；被商品引用的分类不可删除（改为编辑改名）。
- 库存：与商品 1:1；商品新建时初始化为 0；提供原子增加 / 条件扣减能力，由采购 / 销售规格消费。

## 2. 目标

1. 管理员可维护**商品档案**：列表（含当前库存列与低库存标识）/ 详情 / 新增 / 编辑 / 停用启用；商品编码唯一；初始库存为 0。
2. 管理员可维护**商品分类**：列表 / 新增 / 编辑 / 删除；名称唯一（大小写不敏感）；被商品引用的分类不可删除。
3. 交付**库存台账** `Inventory`（与商品 1:1、原子增减 API），作为库存查询与采购 / 销售单据的数据基础（库存查询页面本身由 erp-inventory-query 实现）。
4. 交付**开单商品选择接口**（仅启用商品，含编码 / 名称 / 单位 / 采购价 / 销售价 / 当前库存），供采购 / 销售开单页使用。
5. 前端提供商品管理页面（列表 / 筛选 / 新增 / 编辑 / 启停），侧边菜单新建「进销存」子菜单分组并放入「商品管理」子项。

## 3. 功能点

- **F1 商品列表**：分页查询，支持按关键词（编码 / 名称模糊）、分类、状态筛选；列表含**当前库存列**与低库存标识（库存 < 安全阈值且阈值 > 0 时标红 + 标签）；返回总数。
- **F2 商品详情**：按 id 查看单个商品完整信息（含当前库存、安全阈值、分类名称）。
- **F3 新增商品**：编码（唯一）、名称、分类（单级下拉，可选已有分类或就地新建）、单位、采购价、销售价、安全库存阈值、备注；**同一事务内初始化一行库存（`Quantity = 0`）**。
- **F4 编辑商品**：可改名称 / 分类 / 单位 / 采购价 / 销售价 / 安全阈值 / 备注；**编码创建后不可修改**。
- **F5 商品停用 / 启用**：停用的商品不出现在开单商品选择接口；停用不删除，保留历史单据引用。
- **F6 商品分类维护**：单级分类的列表 / 新增 / 编辑 / 删除；**被商品引用的分类不可删除**（提示改为编辑后使用）；分类名称唯一；分类无停用状态（保持最简）。
- **F7 库存台账（数据能力，无独立页面）**：`Inventory` 表与商品 1:1（`ProductId` 唯一）；商品新建时初始化 `Quantity = 0`；提供**原子增加**（delta 可为负）与**条件扣减**（`Quantity >= amount` 前置，数据库层防超卖，返回是否成功）两个仓储能力，由 erp-purchase / erp-sale 消费。
- **F8 开单商品选择**：`GET /api/products/pick` 返回仅启用商品（id / 编码 / 名称 / 单位 / 采购价 / 销售价 / 当前库存），全量返回（MVP 数据量可控）。
- **F9 前端菜单**：侧边栏新建「进销存」子菜单分组（`a-sub-menu`，key `erp`，图标 `IconStorage`，**默认展开**，交互同「示例页面」子菜单），本规格放入「商品管理」子项；后续子规格依次向该分组添加子项，最终顺序：商品管理 / 往来单位 / 采购入库 / 销售出库 / 库存查询。

## 4. 验收标准

1. `cd backend && dotnet build` 成功（net8.0）；`dotnet test` 全部通过。
2. 执行 EF Core 迁移后 `Categories`、`Products`、`Inventory` 表存在，表结构与 `design.md` 一致；`Products.Code`、`Categories.Name`、`Inventory.ProductId` 有唯一索引；`Inventory.ProductId` 有外键指向 `Products(Id)`。
3. `POST /api/products` 新增商品成功，`Inventory` 表同步出现 `Quantity = 0` 行；重复编码返回 `40101`；分类不存在返回 `40400`。
4. `GET /api/products` 分页 + 关键词 / 分类 / 状态筛选正确；列表每行含 `stockQuantity` 与 `isBelowSafetyStock`（阈值 0 → false；库存 = 阈值 → false；阈值 > 0 且库存 < 阈值 → true）。
5. `GET /api/products/{id}` 返回详情（含当前库存与分类名称）；不存在返回 `40400`。
6. `PUT /api/products/{id}` 可改名称 / 分类等字段，**编码不可改**（请求不含 code）；不存在返回 `40400`。
7. `PUT /api/products/{id}/status` 启用 / 停用切换成功；停用后 `GET /api/products/pick` 不再返回该商品；不存在返回 `40400`。
8. 商品分类：重名返回 `40105`；删除无引用分类成功、有引用返回 `40106`、不存在返回 `40400`。
9. 并发场景：库存条件扣减 `TryDecrementAsync` 在数据库层原子完成判断与扣减（`WHERE Quantity >= amount`），两请求并发扣减合计超过库存时最多一个成功。
10. `GET /api/products/pick` 仅返回启用商品，每行含 id / 编码 / 名称 / 单位 / 采购价 / 销售价 / 当前库存。
11. 前端「商品管理」页：列表 / 筛选 / 分页 / 新增 / 编辑 / 启停全部可用；低库存行库存数字标红 + 标签；侧边菜单「进销存」分组默认展开且「商品管理」可达。
12. `cd frontend && npm run build`、`npm run lint` 通过；`npm run test:e2e` 通过（含商品管理用例：建分类 → 建商品 → 列表展示库存 0 → 重名编码 40101 提示 → 停用商品后不出现在开单选择接口）。
13. 代码与 `AGENTS.md`、backend / frontend 专项规则一致（分层、命名、注释语言、统一响应与错误码、字段约束单一来源、按钮 loading 约定）。

## 5. 范围外（不做）

- 多仓库 / 库存调拨 / 多批次 / 保质期 / 多单位换算。
- 库存盘点（盘盈 / 盘亏）、期初库存导入（首期库存只能经采购单建立；后续可补「期初建账」）。
- 商品图片、规格属性（SKU 矩阵）。
- 删除商品（一律以停用代替，保留单据引用）；删除往来单位 / 单据由 erp-partner / erp-purchase / erp-sale 约定（一律停用 / 作废）。
- 采购 / 销售单据、结算、报表（由 erp-purchase / erp-sale 等子规格实现）。
- 角色 / 权限控制（RBAC）、菜单 / 按钮级权限。
