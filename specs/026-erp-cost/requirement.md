# 需求规格：成本核算与销售毛利（erp-cost）

> 进销存扩展路线（`specs/ROADMAP.md`）批次三第二项，依赖 `019-erp-stock-movement`（流水）与 `025-erp-report`（报表口径与页面）。
> 本规格引入**成本口径**：为库存与每次变动补齐金额，产出库存金额与销售毛利。

## 1. 背景

现状全系统只有**数量**没有**成本**：

- `Inventory` 只有 `Quantity`：库存「值多少钱」答不出来，`025` 的库存余额表也只能给数量。
- `StockMovements` 只落带符号的 `Quantity`（`019` §5 明确不落结存）：谁在什么时候以什么单价进出，流水上看不到。
- 销售单据只有**售价**：卖出去赚了多少（毛利）无法计算——这是老板最关心、也最常用的一个数。

成本核算是有前置条件的：必须先有「每次变动都可追溯」的流水（`019` 已具备），才能按时间顺序推演加权平均成本。越晚做，历史成本越难补（需要重算或人工补录），所以本规格紧接流水与报表落地。

## 2. 目标

1. **成本口径确立**：采用**移动加权平均**（唯一计价方法），口径正文落在 `design.md` §0，作为后续所有成本相关能力（库存金额、毛利、调拨结转、批次成本）的唯一来源。
2. **每次变动带成本**：`StockMovements` 追加成本单价与成本金额两列；所有既有写入路径（采购入库 / 采购作废 / 销售出库 / 销售作废 / 期初建账 / 盘点调整 / 采购退货 / 销售退货及其作废）在同一事务内一并落成本，不出现「有数量无成本」。
3. **库存金额**：`Inventory` 追加结存成本额与当前均价，`025` 库存余额表追加「库存金额 / 均价」列。
4. **期初成本可录**：期初建账录入**成本单价**（期初库存没有单价就没有成本基线），盘点调整按当时均价处理。
5. **销售毛利报表**：按期间（可按商品 / 单据 / 往来单位分组）给出销售收入、销售成本、毛利、毛利率，并冲减销售退货。
6. **成本重算（初始化）能力**：提供一次幂等的「按流水顺序重算成本」用例，用于本规格上线时为历史流水一次性补齐成本、以及后续发现异常时修复。

## 3. 功能点

- **F1 成本列**：`Inventory` 追加 `CostAmount`（结存成本额 `numeric(18,4)`）、`AverageCost`（当前移动加权平均单价 `numeric(18,4)`）；`StockMovements` 追加 `UnitCost` / `TotalCost`（`numeric(18,4)`）；`StockTakeItems` 追加 `UnitCost`（期初成本单价）。
- **F2 写入接入**：`019` / `020` / `021` / `022` 的全部库存写入路径在同一事务内更新成本（入库加权、出库按均价结转）；**不改变任何数量语义与既有业务判定**。
- **F3 期初成本录入**：`CreateStockTake` 在期初模式下要求每行 `unitCost`（必填、≥ 0、≤ 9999999.99）；盘点模式下不允许传（忽略或校验拒绝，见 `design.md` §3.5）；新建页期初模式增加成本单价列并实时展示「期初金额 = 实盘数量 × 成本单价」。
- **F4 库存金额**：`025` 库存余额表追加「库存金额 / 均价」列与合计；`014` 明细视图不改造（金额是汇总口径，见 `design.md` §5）。
- **F5 成本与毛利报表**（`/reports/cost-profit`）：筛选（期间、商品、分类、分组维度）；列：分组名称、销售数量、销售收入、销售成本、毛利、毛利率；合计行；成本缺失的行标注（历史数据缺价的兜底提示）。
- **F6 成本重算**：新增用例 `Costs/RecalculateCosts`（`POST /api/costs/recalculate`，入参可选期间 / 商品）：按流水时间顺序重放全部入库 / 出库，重算 `UnitCost` / `TotalCost` / `Inventory` 成本列，幂等；返回重算条数与缺价（成本单价无法推算）条数。
- **F7 前端**：新增成本与毛利报表页（归「报表」分组）；成本页操作行「重算成本」入口（`a-popconfirm` + `recalculating` loading）；期初建账页增加成本单价录入。

## 4. 验收标准

1. `cd backend && dotnet build` / `dotnet test` 通过（含成本重算、加权平均、出库结转、期初必填、毛利汇总、重算幂等与并发拒绝等单测）。
2. `cd frontend && npm run type-check` / `npm run lint` / `npm run build` 全绿；`npm run test:e2e` 全量通过（含新增 `cost.spec.ts` 与 `stock-take` / `report` 既有用例回归——期初建账新增必填项会影响既有 e2e，需同步改造）。
3. 手工验证（加权平均）：
   - 期初建账 10 件 × 10 元 → 均价 10、结存金额 100。
   - 采购入库 10 件 × 20 元 → 数量 20、结存金额 300、均价 15。
   - 销售出库 5 件 → 该出库流水成本单价 15、成本 75，均价仍 15、结存金额 225。
   - 采购作废原入库（−10 件）→ 按该单入库单价 20 结转 −200，结存金额 25、均价重算为 2.5（数量 10）。
4. 手工验证（毛利）：销售出库 5 件 × 售价 30 = 收入 150、成本 75 → 毛利 75、毛利率 50%；该销售单作废后毛利归 0（收入与成本同步回冲）。
5. 期初成本：期初建账未填成本单价 → 提交被拦（提示必填）；填写后成本列与流水 `UnitCost` 正确。
6. 重算幂等：连续执行两次重算，结果完全一致（`UnitCost` / `TotalCost` / `Inventory` 成本列）；重算与库存数量无关（不改变任何 `Quantity`）。
7. 对账口径仍成立：`Σ 流水 Quantity == Inventory.Quantity` 不受本规格影响（回归断言）。
8. 口径单一：本规格新增的成本定义（加权公式、单价来源表、四舍五入与精度、零结存处理）只在 `design.md` §0 定义一次，`025` / `030` / `031` / `032` 只引用不重定义。

## 5. 范围外（不做）

- **其他计价方法**：先进先出（FIFO）/ 后进先出 / 个别计价 / 标准成本——只做移动加权平均（如需切换须单独立规格，含历史重算与口径迁移）。
- **成本调整单 / 人工改成本**：不允许直接改 `UnitCost` / `AverageCost`（与「不开放直接改库存」同一原则）；纠错靠重算或通过单据（退货 / 盘点 + 重算）。
- **暂估入库 / 发票到时调整成本**：`034` 只做发票登记，不做暂估与成本调整。
- **期间成本与期末结转**：不做月结、不做「结转下期期初」的账务动作（报表按期间实时计算）。
- **费用分摊**：运费 / 关税 / 装卸费等采购附加费用不摊入成本（总金额 = Σ 数量 × 单价）。
- **分仓 / 分批次成本**：`030` / `032` 落地时按各自规格追加维度（届时在 §0 续行「按仓均价」「按批次成本」）。
- **税务口径**：成本为不含税口径，不做税会差异与进项税转出。
- **库存跌价准备 / 资产减值**：属财务级处理（`specs/ROADMAP.md` §5）。

## 6. 对新功能（`025` / `030` / `031` / `032`）的约束

- `025` 的库存余额表「库存金额 / 均价」列与本规格同时落地（`025` §0 与页面按本规格新增列）。
- 后续任何**新增库存变动来源**（`030` 调拨、`032` 批次）都必须在写入时同时给出成本单价与金额（引用 §0 的单价来源表），不允许出现无成本流水。
