# 需求规格：数据级权限 / 数据范围（erp-data-scope）

> ERP 全域路线（`specs/ROADMAP.md` §4.2）**P7 内核收口与运营**项；`028-erp-rbac` 的**收口缺口**（`028` §0.1 只做功能级权限，本规格补数据级）。
> 依赖：`028`（角色 / 权限 / 校验入口）、`030`（员工↔账号绑定、部门树）、`029`（操作日志范围表）。
> 范围克制：只做**组织 / 本人维度**的数据范围；不做按往来 / 商品分类的数据权限、字段级权限、行列级明细裁剪。

## 1. 背景

`028` 建立了功能级权限（菜单级 + 按钮级）并默认拒绝，但它回答的是**"能做什么"**，不回答**"能看到哪些数据"**：

- 任何拥有 `purchases.view` 的用户都能看到**全部**采购入库单、销售出库单、收付款单、凭证……多组织 / 多部门经营时，"销售只能看自己部门的单、业务员只能看自己的单"无法表达。
- `028` §0.1 已把"菜单级 = `<域>.view`"定为唯一口径，数据级权限是其明确留出的下一层（`ROADMAP` §3「L1 平台 · 权限 / 审计」缺口）。
- 组织 / 员工模型（`030`）已就绪（员工经 `UserId` 绑定账号），数据范围所需的"人 → 部门"链路已具备。

本规格补上数据级权限：**在角色上配置数据范围**，请求进入时解析出可见范围，**单据列表 / 详情 / 导出按其过滤**，越权访问返回 `40300`。

## 2. 目标

1. **角色数据范围**：角色新增「数据范围」属性（`全部 / 本部门及下级 / 本部门 / 仅本人`）；用户多角色时取**最宽**范围（并集）。
2. **解析即生效**：请求内解析当前用户可见的**用户集合**（`visibleUserIds`）；`全部` 表示不过滤。
3. **统一过滤**：范围内单据（按单据 `CreatedBy` 归属）的**列表 / 详情 / 导出**一致过滤；越权详情 = `40300`。
4. **默认兼容**：既有角色迁移后数据范围 = `全部`，**不改变现有行为**（无感）。
5. **前端**：角色表单增「数据范围」下拉；列表 / 详情页无感（过滤在后端）。
6. **e2e 覆盖**。

## 3. 功能点

- **F1 角色数据范围配置**：`PUT /api/roles/{id}` 请求体增 `dataScope`；`RoleDetailDto` / `RoleListItemDto` 增 `dataScope`；内置角色 `SuperAdmin` 恒为 `全部`（`40175` 既有约束不变）。
- **F2 数据范围解析**：`IDataScopeProvider.ResolveAsync(userId)` → `DataScopeFilter`（`All == true` 或 `visibleUserIds`）；多角色取最宽；`SuperAdmin` → 全部；**单请求缓存**（同 `028` `IPermissionResolver`）。
- **F3 范围过滤**：`design.md` §0.2 列出的**受约束资源**（采购入库 / 销售出库 / 采购退货 / 销售退货 / 收付款单 / 报价单 / 发票 / 记账凭证 / 操作日志）的查询仓储追加 `createdBy ∈ visibleUserIds` 过滤；详情越权 → `40300`。
- **F4 无绑定员工时的口径**：用户未绑员工 → `本部门 / 本部门及下级` 退化为**仅本人**；`仅本人` = 仅 `CreatedBy == 自己`。
- **F5 前端**：角色抽屉表单增「数据范围」`a-select`；`api/role.ts` 类型扩充。
- **F6 e2e**：构造受限角色用户，验证列表只见范围内单据、越权详情 `40300`。

## 4. 验收标准

1. `cd backend && dotnet build` / `dotnet test` 通过（解析并集、退化口径、各资源过滤、越权详情 `40300`）。
2. `cd frontend && npm run type-check` / `npm run lint` / `npm run build` 全绿；`npm run test:e2e` 全量通过（新增 `data-scope.spec.ts`）。
3. 手工验证：
   - 建角色「销售一组」数据范围 `本部门`，用户 A（属销售一组）只见本组单据；用户 B（销售二组）不可见。
   - A 直接访问 B 的单据详情 → `40300`。
   - 既有角色（迁移后 `全部`）行为与升级前**完全一致**。
4. 口径单一：数据范围取值、可见性判据、受约束资源清单只在 `design.md` §0 定义一次。
5. 联动：`028` §0.2 无需新增权限点（数据范围由 `roles.update` 保护）；`029` §0.1 操作日志资源纳入受约束集。

## 5. 范围外（不做）

- **按往来单位 / 商品 / 商品分类的数据权限**：只做组织 / 本人维度。
- **字段级 / 行列级明细裁剪**（同一单据组内可见部分字段或部分明细行）：不做。
- **组织树调整时的历史数据重算**：数据范围按**查询时的当前部门树**判定，部门移动不重算历史可见性（如需固化另行评估）。
- **按岗位 / 角色的差异化数据范围**（同人多角色取交集）：本规格取**并集（最宽）**，不做交集 / 自定义表达式。
- **跨组织的全量报表豁免**：报表（`025` / `033`）本期**不受**数据范围约束（口径见 `design.md` §0.2 说明）。
- **数据范围审批 / 授权申请流**：不做。
