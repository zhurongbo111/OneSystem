# 需求规格：采购入库（erp-purchase）

## 0. 进销存功能组定位

本规格是**进销存（ERP）功能组**的采购单据域，同时定义采购 / 销售**共用的单据域约定**（供 erp-sale 继承）：

| 子规格 | 内容 | 依赖 |
|---|---|---|
| erp-product | 商品分类 / 商品档案 / 库存台账（Inventory + 原子增减 API） | 无 |
| erp-partner | 往来单位（供应商 / 客户） | 无 |
| erp-inventory-query | 库存查询页 | erp-product |
| **erp-purchase（本规格）** | 采购入库单 + 单据域共用约定（单号生成 / 明细快照 / 金额重算 / 单据实体模板 / 共用错误码） | erp-product + erp-partner |
| erp-sale | 销售出库单 | 本规格（共用约定）+ erp-product + erp-partner |

前置条件：erp-product（`Products` / `Inventory` / 开单商品选择接口 `GET /api/products/pick`）与 erp-partner（`Partners` + 按类型 / 状态筛选查询）已交付。

**单据域共用约定**：本规格首次引入 `PurchaseOrders` / `PurchaseOrderItems` 表、`PurchaseOrder` / `PurchaseOrderItem` 实体、`IOrderRepository` 同构仓储模板、`GenerateOrderNoAsync` 单号生成、`OrderStatus` / `OrderSettlementStatus` 枚举、明细快照与金额后端重算规则、单据共用错误码（40104 / 40108 / 40109 / 40110）。erp-sale 的 `SalesOrders` / `SalesOrderItems` 与本规格**结构完全同构**（前缀 `SO`，`PartnerName` 为客户快照），实现时照抄本规格模板并做前缀 / 校验方向 / 库存操作方向三处替换，不再重复定义。

## 1. 背景

进销存 MVP 的采购环节：选择供应商 + 多行商品明细（数量、单价），保存后**库存增加**、单据产生**应付**（简化结算：单据只记金额 + 已结算 / 未结算状态，不做独立收付款单与对账）。

- 仓库模型：单仓库（消费 erp-product 的 `Inventory`）。
- 单据流程：**一步式**——保存即生效（库存立即增加、应付口径立即产生），不支持编辑，只支持**作废**（库存回冲）。
- 明细单价为**保存时快照**（默认带出商品采购价、可修改），后续改商品价不影响历史单据。
- 供应商校验：`Type in (Supplier, Both)` 且启用（消费 erp-partner）。
- 商品校验：仅启用商品可入明细（消费 erp-product 开单选择接口）。

## 2. 目标

1. 可开**采购入库单**：选择供应商（仅启用 + 类型匹配）、日期（默认当天）、多行明细（选商品 / 数量 / 单价，单价默认带出商品采购价、可改）；小计 = 数量 × 单价，总金额 = Σ 小计（**后端重算，不信任前端**）；保存后**每行库存 += 数量**，单据生成单号、结算状态为「未结算」。
2. 采购单支持**列表 / 详情 / 作废 / 结算标记**：
   - 列表：分页 + 单号 / 供应商 / 日期范围 / 结算状态筛选，按创建时间倒序；作废行置灰。
   - 详情：表头（单号 / 供应商 / 日期 / 总金额 / 结算状态）+ 明细行（商品 / 数量 / 单价 / 小计，均为快照）。
   - 作废：仅未作废单据可作废；作废后**库存 -= 各明细数量**（允许冲负）、状态置「已作废」、前端展示作废态并禁止再操作。
   - 结算标记：未结算 / 已结算手动切换（简化结算，不做部分支付）。
3. 侧边菜单「进销存」分组添加「采购入库」子项；开单为独立页面，详情为独立页面。

## 3. 功能点

- **F1 采购单列表**：分页查询，支持按单号关键词 / 供应商 / 日期范围 / 结算状态筛选；按创建时间倒序；作废行置灰。
- **F2 新增采购单**：选择供应商（仅启用的）、日期（默认当天）、多行明细（选商品 / 数量 / 单价，单价默认带出商品采购价、可改）；小计 = 数量 × 单价，总金额 = Σ 小计（后端按 `数量 × 单价` 重算，**不信任前端传值**，前端传的小计 / 总额忽略）；保存后**每行库存 += 数量**（事务内完成插单 + 明细 + 库存增减），单据生成单号（`PO + yyyyMMdd + 4 位序号`，后端生成）、结算状态为「未结算」。
- **F3 采购单详情**：表头 + 明细行（商品 / 数量 / 单价 / 小计）；**明细单价 / 商品名 / 单位为保存时快照**，后续改商品档案不影响。
- **F4 采购单作废**：仅未作废单据可作废；作废后**库存 -= 各明细数量**（允许冲负：采购入库后商品可能已被卖光，回冲必须可执行）、状态置「已作废」；前端展示作废态并禁止再操作（作废 / 结算入口消失）。
- **F5 采购单结算标记**：未结算 / 已结算手动切换（简化结算，不做部分支付）；已作废单据禁止切换。
- **F6 开单页（独立页面）**：供应商 / 客户下拉（仅启用 + 类型匹配，采购取 `Type in (1,3)`）、明细可编辑表格（商品下拉带库存展示、数量、单价默认带出采购价、小计实时计算展示）、添加 / 删除行、总额实时计算、提交成功后跳详情。
- **F7 前端菜单**：侧边菜单「进销存」分组添加「采购入库」子项；详情路由 `purchases/detail/:id` 归属该菜单高亮。

## 4. 验收标准

1. `cd backend && dotnet build` 成功（net8.0）；`dotnet test` 全部通过。
2. 执行 EF Core 迁移后 `PurchaseOrders`、`PurchaseOrderItems` 表存在，表结构与 `design.md` 一致；`PurchaseOrders.OrderNo` 有唯一索引；明细 `OrderId` 有索引。
3. `POST /api/purchase-orders` 保存成功返回单号（格式 `PO + yyyyMMdd + 4 位序号`）；库存按明细增加（`GET /api/inventory` 可验证）；小计 / 总额由后端重算（**前端传错的小计 / 总额不影响落库值**）。
4. `POST /api/purchase-orders` 业务失败路径：明细为空 → `40110`；供应商不存在 → `40400`；供应商停用 → `40108`；供应商类型不含 Supplier（纯客户）→ `40109`；商品停用 → `40107`；商品不存在 → `40400`。
5. `GET /api/purchase-orders` 分页 + 单号关键词 / 供应商 / 日期范围 / 结算状态筛选正确；按创建时间倒序；作废单据也返回。
6. `GET /api/purchase-orders/{id}` 返回表头 + 明细（快照字段正确）；不存在返回 `40400`。
7. `PUT /api/purchase-orders/{id}/void`：作废后库存回冲（各明细 `库存 -= 数量`，允许冲负）、状态 `voided`；不存在返回 `40400`；已作废再作废返回 `40104`。
8. `PUT /api/purchase-orders/{id}/settlement`：未结算 / 已结算切换成功；对已作废单据操作返回 `40104`；不存在返回 `40400`。
9. 日期范围筛选：前端将所选日期转为本地当天 00:00:00 / 23:59:59 的 UTC ISO 串，后端按 `timestamptz` 闭区间直接比较（同登录日志既有约定）。
10. 事务性：插单 + 明细 + 库存增减在同一事务，任一环节失败整体回滚（单号不落库、库存不变）。
11. 前端「采购入库」5 个页面全部可达（列表 / 开单 / 详情）：
    - 列表：筛选（含日期范围 / 结算 / 供应商）+ 表格（作废行置灰）+ 操作列（详情 / 作废 / 结算）+ 分页。
    - 开单：供应商下拉 + 明细行增删 + 单价默认带出 + 小计 / 总额实时计算 + 提交成功跳详情。
    - 详情：表头 + 明细只读 + 作废确认（popconfirm）+ 结算切换 + 404 result。
12. `cd frontend && npm run build`、`npm run lint` 通过；`npm run test:e2e` 通过（含采购入库用例：开单 → 保存成功跳详情（单号 / 总额正确）→ 库存页数量增加 → 标记已结算 → 作废确认 → 库存回冲 → 单据状态「已作废」且操作消失）。
13. 代码与 `AGENTS.md`、backend / frontend 专项规则一致（分层、命名、注释语言、统一响应与错误码、字段约束单一来源、按钮 loading 约定）。

## 5. 范围外（不做）

- 采购单编辑（一步式 + 快照设计下，改单 = 作废 + 新单）。
- 删除采购单（一律以作废代替，保留审计轨迹）。
- 折扣、运费、税点等单据附加金额字段（总金额 = Σ 数量 × 单价）。
- 完整收付款：独立付款单、部分结算、应付对账报表、逾期提醒（结算仅状态位手动切换）。
- 单据草稿 / 审核流（两步式）、单据打印 / PDF 导出、条码扫码开单。
- 采购统计报表（采购金额 / 供应商对账等）。
- 并发下的独立幂等 token（重复提交由前端防重入 + 后端单号唯一索引兜底；MVP 并发量下足够）。
