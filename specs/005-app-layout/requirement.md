# 需求规格：全局页面布局（app-layout）

## 1. 背景

项目脚手架已建立登录页、首页与组件示例页。当前各页面各自实现头部（首页自带 header、组件示例页自带顶部标题栏），布局互不共享，`src/components/` 为空目录，没有统一的全局布局壳。随着功能页面增加，需要一套统一的页面布局（侧边导航 + 顶部栏 + 内容区），后续功能页面只需提供内容即可挂载到该布局下。

## 2. 目标

1. 提供统一的全局页面布局：侧边导航菜单 + 顶部栏 + 内容区，各业务页面只负责内容。
2. 将首页、组件示例页纳入该布局，通过侧边菜单导航切换。
3. 布局可折叠侧边栏，顶部栏展示当前登录用户与退出登录入口。
4. 登录页保持独立全屏，不进入布局。

## 3. 功能点

- F1 全局布局组件：`src/components/AppLayout.vue`，基于 Arco `a-layout`：
  - 侧边栏 `a-layout-sider`（可折叠）+ `a-menu`（`inline` 模式）。
  - 顶部栏 `a-layout-header`：左侧折叠按钮 + logo，右侧当前用户下拉（展示 `displayName`，含退出登录）。
  - 内容区 `a-layout-content` 内嵌 `RouterView`。
- F2 侧边菜单项：首页（`/`）、示例页面（`a-sub-menu` 子菜单，含组件示例 `/components`、列表示例 `/list`、表单与详情示例 `/form`）；菜单当前项与路由联动选中。
  - 子菜单**默认折叠**：进入首页等不属于任何分组的页面时，所有子菜单收起；仅当当前路由属于某分组时，该分组自动展开（用户手动折叠后不再自动展开，直到下次进入该分组页面）。
  - 用户可手动点击分组标题展开 / 折叠任意子菜单。
- F3 侧边栏可折叠（折叠按钮切换），折叠状态为内存态，不持久化。
- F4 路由改造：`AppLayout` 作为父路由承载 `home`（`/`）与 `components`（`/components`）子路由；`/login` 保持独立；现有路由守卫逻辑不变。
- F5 页面收敛：`HomeView` 移除自带头部（用户信息 / 退出登录上移到布局顶部栏）；`ComponentShowcaseView` 移除自带顶部标题栏与"返回首页"（导航由侧边菜单承担），保留页面标题与 tab 主体。
- F6 未登录访问需登录页面时，守卫跳转登录页的行为不变；已登录访问登录页跳转首页的行为不变。

## 4. 验收标准

1. `cd frontend && npm run build` 通过，无 TypeScript 错误；`npm run lint` 通过。
2. 登录后进入首页，可见全局布局（侧边菜单 + 顶部栏），侧边菜单"首页"项选中。
3. 展开侧边菜单"示例页面"子菜单，点击"组件示例"跳转 `/components`，该菜单项选中；内容区渲染组件示例。
4. 折叠按钮可收起 / 展开侧边栏。
5. 顶部栏用户下拉可退出登录，退出后跳转登录页。
6. 登录后进入首页，所有子菜单处于折叠态（子项不可见）；点击分组标题可展开；直接访问子页面（如 `/products`）时所属分组自动展开。
7. e2e 覆盖（`npm run test:e2e` 通过）：布局渲染与菜单选中联动、菜单切换、子菜单默认折叠与展开、侧边栏折叠、用户下拉退出登录。

## 5. 范围外（不做）

- 菜单暂不动态化（按路由 meta 自动生成），当前为静态配置；后续功能页面增加菜单项时再评估。
- 不做面包屑（当前层级浅）。
- 侧边栏折叠状态不做持久化（不写 localStorage）。
- 不改动接口层（`src/api/`）与后端。
- 不新增业务功能页面（仅将现有首页、组件示例页纳入布局）。
