# 需求规格：多仓库（erp-multi-warehouse）

> 进销存扩展路线（`specs/ROADMAP.md`）批次四第一项，落实其 §4.2 的既定路径（当年刻意**不预留** `WarehouseId`，因为流水是纯追加表、加列与回填是增量操作）。
> 本规格为**破坏性维度改造**：`Inventory` 唯一键、`StockMovements` 维度、五类单据的仓库字段与既有全部开单前置校验都要跟着改。

## 1. 背景

现状**按单仓设计**（`012` §2.3：`Inventory` 唯一键 `ProductId`，全局一份库存），这在「一个仓库、一个门店」的场景够用；但一旦有第二个物理存放点就立刻暴露问题：

- **分不清数量**：两个仓各放多少货，系统只有一个总数；盘点、拣货、调拨都无从下手。
- **单据无落点**：采购到货进了哪个仓、销售从哪个仓发货，单据上无处填写。
- **流水无维度**：`019` 的流水虽可追溯，但全部落在同一维度上，无法按仓对账。
- **安全库存无意义**：商品级阈值无法表达「上海仓需要 100、北京仓只要 20」。

`ROADMAP` §4.2 已定修正判断与既定路径：不预留空列（会污染所有写入路径的语义），而是在本规格一次性做「加列 + 回填默认仓 + 唯一键升级 + 索引补齐」，代价可控、无返工。

## 2. 目标

1. **仓库档案**：仓库的列表 / 新增 / 编辑 / 启停（编码唯一、名称唯一），**一个默认仓**（不可停用、不可删除）；**仓库只停用不删除**（保留库存、流水与单据引用）。
2. **库存按仓**：`Inventory` 唯一键升级为 `(ProductId, WarehouseId)`；安全库存下沉为**仓级阈值**（商品档案阈值作为新建库存行的初始值）；库存数量、低库存判定、库存不足判定全部按仓。
3. **单据带仓**：采购入库（入库仓）、销售出库（出库仓）、采购退货（出库仓）、销售退货（入库仓）、库存盘点（盘点仓）均带仓库；**未指定时取默认仓**（兼容既有前端与历史数据）。
4. **流水带仓**：`StockMovements` 增 `WarehouseId`（回填默认仓），流水可按仓筛选与对账（`Σ 流水 == 该仓库存`）。
5. **兼容与平滑**：迁移为既有数据回填默认仓；既有开单 / 查询 / 报表接口**参数可空**，历史调用方（含 e2e）不改也能跑通。
6. **维度贯通**：库存查询、库存流水、进销存报表、库存余额表、盘点页均支持按仓筛选 / 分组（报表口径在 `025` §0.1 续行）。

## 3. 功能点

- **F1 仓库档案**：`Warehouses`（编码唯一 / 名称唯一 / 地址 / 联系人 / 电话 / 状态 / 是否默认 / 审计）+ 用例 `GetWarehouses` / `CreateWarehouse` / `GetWarehouseById` / `UpdateWarehouse` / `UpdateWarehouseStatus` / `SetDefaultWarehouse` / `GetWarehousePickList`（开单下拉）。
- **F2 库存维度升级**：`Inventory` 增 `WarehouseId`（唯一键 `(ProductId, WarehouseId)`）与 `SafetyStock`（仓级阈值）；`IInventoryRepository` 全部方法追加 `warehouseId`；`IncrementAsync` 语义升级为「确保库存行存在后累加」。
- **F3 单据带仓**：五类单据表与实体增 `WarehouseId`；创建时校验（存在 / 启用）；列表与详情出参增 `warehouseId` / `warehouseName`，列表支持 `warehouseId` 筛选。
- **F4 流水带仓**：`StockMovements` 增 `WarehouseId`（NOT NULL）；流水查询支持 `warehouseId` 筛选并在列表展示仓库列；`029` 审计摘要含仓库（单据类）。
- **F5 仓级安全库存维护**：库存查询页行内「设安全库存」（单字段 Modal）→ `PUT /api/inventory/safety-stock`。
- **F6 前端**：仓库管理页（「基础档案」分组）；各开单页仓库下拉（默认仓预选、仅启用仓）；库存查询 / 库存流水 / 盘点列表加仓筛选与列；报表按仓筛选（`025` / `026` 页面演进）。
- **F7 e2e 覆盖**：仓库 CRUD 与默认仓切换；两个仓各自入库 → 库存查询按仓显示不同数量；销售出库从指定仓扣减（另一仓不受影响）；库存不足按仓判定（A 仓不足但 B 仓充足时仍拒绝）；流水按仓筛选；默认仓兜底（不选仓直接开单进入默认仓）。

## 4. 验收标准

1. `cd backend && dotnet build` / `dotnet test` 通过（含仓库用例、库存按仓、单据带仓、流水带仓、默认仓兜底、唯一键与回填等单测）。
2. `cd frontend && npm run type-check` / `npm run lint` / `npm run build` 全绿；`npm run test:e2e` 全量通过（既有各域 spec 需回归：开单多了一个仓库下拉，默认已预选）。
3. **数据迁移正确**：迁移后 —— `Warehouses` 含「默认仓」（`IsDefault = true`）；既有 `Inventory` 行全部指向默认仓且数量不变；既有 `StockMovements` / 单据全部回填默认仓；`Inventory` 唯一约束为 `(ProductId, WarehouseId)`；`Products.SafetyStock` 的既有值被复制到对应库存行的仓级阈值。
4. **按仓隔离**：商品 A 在「上海仓」入库 10、在「北京仓」入库 30 → 库存查询按仓分别显示 10 / 30；从北京仓销售 30 后上海仓仍为 10。
5. **按仓防超卖**：上海仓库存 5、北京仓库存 100，从上海仓销售 10 → 拒绝（`40103`，message 含仓名与当前 / 需要数量），库存无变化。
6. **默认仓兜底**：不传 `warehouseId` 开单 → 落在默认仓；默认仓不可停用（`40124`）、不可删除。
7. **对账口径按仓成立**：任一「商品 × 仓」满足 `Σ 流水 Quantity == Inventory.Quantity`（单测守护；`019` 口径的按仓版本）。
8. 口径单一：仓库维度定义（唯一键、仓级安全库存、默认仓规则、回填策略）只在 `design.md` §0 定义一次；`019` / `020` / `021` / `022` / `025` / `029` 只引用并留演进注记。

## 5. 范围外（不做）

- **调拨单**：`031-erp-transfer`（本规格只把「按仓」维度打通，不含跨仓转移业务）。
- **批次 / 保质期 / 序列号**：`032-erp-batch-expiry`。
- **库位 / 货架 / 波次 / 拣货路径**：WMS 级作业（`ROADMAP` §5 明确不进本路线）。
- **按仓的采购 / 销售默认仓策略**（如「某供应商默认入 A 仓」）：不做自动默认规则，用户手工选（下拉预选默认仓）。
- **跨仓库存调价的独立成本核算**：成本仍为**组织级移动加权平均**（`026` 口径），本规格**不做按仓成本**；按仓成本需在 `026` §0.1 续行并单独评估（决策记录）。
- **按仓的权限隔离**（只能操作自己仓）：属数据级权限（`028` 范围外）。
- **仓库容量 / 库容预警**：不做。
- **历史单据的仓库追溯修正**：历史单统一回填默认仓，不支持拆分到多仓（那时确实只有一仓）。
- **删除仓库**：一律停用（保留引用与审计）。
