# 需求规格：主数据编码规则（erp-code-rule）

> ERP 全域路线（`specs/ROADMAP.md` §4.2）**P7 内核收口与运营**项；补齐 `ROADMAP` §3「L2 主数据 · 物料 / 往来 / 分类」的「编码规则（后置）」缺口。
> 依赖：`012`（商品 `Code` 手工录入、`40101` 唯一）、`028`（权限）、`029`（操作日志）。
> 范围克制：首期只接入**商品**编码自动生成；机制**可扩展**（资源类型枚举续行）但**往来 / 分类**编码本期不做（往来无 `Code` 列，另评）。

## 1. 背景

`012` 的商品编码（`Code`）目前**纯手工录入**（2–32 位、创建后不可改）：

- 多人 / 多批次录入时，编码靠"人记规则"（如 `A001`、`A002`…），易重号（撞 `40101`）、易跳号、写法不统一，运营上反复返工。
- 分类（`017`）与往来（`013`）没有编码列；`013` 只有名称唯一。主数据缺少可配置的"编码规则"这一基础设施。
- 商品编码后续被单据明细**快照引用**（`015` / `016` 等），一旦录入不规范，影响面广。

本规格提供**可配置的编码规则与生成能力**：配置「前缀 + 日期段 + 序号位数」后，商品创建时编码可留空由系统自动生成。

## 2. 目标

1. **编码规则配置**：按资源类型配置 `前缀 + 日期段 + 序号位数`（商品一种，机制可扩展）。
2. **自动生成**：商品创建时 `code` 留空（且规则已配置）→ 自动生成；填了则用填的值。
3. **日期段重置**：序号按「前缀 + 日期段」维度自增，跨日期段（如换月 / 换日）自动从 1 重置。
4. **唯一与并发**：生成结果仍走唯一性校验（`40101`）；并发创建不重号（库层保证）。
5. **规则未配置时**：商品编码**仍必填**（保持 `012` 既有行为，不破坏既有用法）。
6. **前端**：编码规则配置页 + 商品抽屉「留空自动生成」提示；**e2e 覆盖**。

## 3. 功能点

- **F1 规则配置页**：`GET /api/code-rules`、`PUT /api/code-rules/{resourceType}`（按资源类型保存）；资源类型枚举首期仅 `Product`。
- **F2 编码生成**：`ICodeGenerator.GenerateAsync(resourceType)`（`前缀 + 日期段 + 序号补零`）；序号自增在事务内完成并做并发保护。
- **F3 商品创建接入**：`CreateProductRequest.code` 改为**可空**；空且规则已配置 → 生成；空且未配置 → `40181`；非空 → 用填值（`012` 行为不变）。
- **F4 唯一性**：生成 / 填值后均校验 `ExistsByCodeAsync`（`40101`）。
- **F5 前端**：`views/CodeRuleManagement/CodeRulesView.vue`（规则表单）；`ProductFormDrawer` 编码在规则启用时可留空并提示。
- **F6 e2e**：配规则 → 建商品留空编码 → 自动生成且连续递增（跨日期段重置）。

## 4. 验收标准

1. `cd backend && dotnet build` / `dotnet test` 通过（生成格式、日期段重置、并发不重号、未配置 `40181`、填值走原路径）。
2. `cd frontend && npm run type-check` / `npm run lint` / `npm run build` 全绿；`npm run test:e2e` 全量通过（新增 `code-rule.spec.ts`）。
3. 手工验证：
   - 配商品规则（前缀 `A`、日期段 `yyyyMMdd`、位数 `4`）→ 建商品留空编码 → 生成如 `A202610070001`；再建 → `A202610070002`。
   - 未配规则建商品留空编码 → `40181`；填编码 → 成功（与升级前一致）。
   - 并发建两个商品（留空编码）→ 两个不同编码。
4. 口径单一：编码组成的取值 / 重置规则 / 生成格式只在 `design.md` §0 定义一次。
5. 联动：`028` §0.2 续行 `codeRules.*`；`025` §0.2「系统」分组续行「编码规则」；`012` §3.5 / §4.4 标注 `code` 可空（演进指针）。

## 5. 范围外（不做）

- **往来 / 分类 / 员工等其它资源类型编码**：机制预留（资源类型枚举续行），本期只做商品；往来需先加 `Code` 列，另评。
- **编码规则的可视化模板 / 正则自定义 / 多段组合**：只做「前缀 + 日期段 + 序号」三段固定结构。
- **序号自定义起始值 / 手工跳号 / 回收空号**：只自增，不跳号回收。
- **已生成编码的批量重编**：编码创建后不可改（`012` 既有约束不变）。
- **条码 / 二维码生成**：不做。
- **按分类 / 按组织差异化规则**：全局单规则 / 资源。
