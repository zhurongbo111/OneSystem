# 需求规格：发票登记（erp-invoice）

> 进销存扩展路线（`specs/ROADMAP.md`）批次四第五项，依赖 `023-erp-settlement`（单据与往来口径、可核销单据查询模式）。
> 严格限定范围：**只做发票登记与单据关联**，不做开票接口对接与税控（见 §5）。

## 1. 背景

`023` 打通了「单据 → 资金」闭环（收付款、应收应付、往来对账），但**发票这一环是空的**：

- **登记无处可放**：收到的进项票、开出的销项票没有地方记录，财务只能线下 Excel 维护，与系统里的单据对不上。
- **口径对不上**：「这张销售单开票了吗、开了多少、还剩多少没开」无法回答；开票金额与单据金额的差异靠人对。
- **作废无痕**：发票作废（冲红）在系统里无记录，对账时无法解释金额变化。

本规格在 `023` 的模式上加一个平行能力：**发票 ↔ 单据**的关联（与「收付款 ↔ 单据」的核销同构），并明确「发票只做到登记 + 关联 + 金额校验」。

## 2. 目标

1. **发票登记**：进项（采购取得）/ 销项（销售开出）发票的登记，含发票号、开票日期、往来单位、不含税金额、税率、税额、价税合计（税额与合计由后端按税率计算）。
2. **发票号唯一**：全局唯一（`40132`），避免同号重复登记。
3. **单据关联**：一张发票可关联**多张**单据（部分开票）；关联方向受发票类型约束（进项 ↔ 采购类、销项 ↔ 销售类），往来单位必须一致。
4. **金额闸门**：每行开票金额 ≤ 该单据**未开票金额**（`单据总额 − 已开票金额`），超出拒绝（`40133`）。
5. **可作废**：发票可作废，作废后其占用金额**自动释放**（未开票金额按聚合口径回退，无需人工冲销）。
6. **可查可下钻**：发票列表（类型 / 往来 / 日期 / 金额筛选 + 分页）、新建页（选往来 → 拉取可开票单据 → 录入金额）、详情页（含关联单据与作废）；单据侧可在发票列表按单据号检索（不做单据页改造，见 §5）。

## 3. 功能点

- **F1 数据模型**：`Invoices`（发票主表）+ `InvoiceItems`（关联单据明细，含单据号 / 日期 / 金额快照），字段见 `design.md` §2。
- **F2 用例**：`GetInvoices` / `CreateInvoice`（校验方向与往来 → 校验未开票金额 → 计算税额与合计 → 落单）/ `GetInvoiceById` / `VoidInvoice` / `GetInvoicableOrders`（按往来 + 类型拉取可开票单据）。
- **F3 方向约束**：进项发票只能关联采购入库单 / 采购退货单；销项只能关联销售出库单 / 销售退货单；错配 `40134`；往来不一致 `40135`。
- **F4 金额计算**：`TaxAmount = Round(AmountExcludingTax × TaxRate, 2)`；`TotalAmount = AmountExcludingTax + TaxAmount`（后端重算，不信任前端）。
- **F5 作废**：作废发票（`OrderStatus = Voided`），明细保留；未开票金额按聚合自动回退。
- **F6 前端**：新增「发票登记」页（`/invoices` 列表 + `/invoices/new` 新建 + `/invoices/detail/:id` 详情含作废），归「资金」分组。
- **F7 e2e 覆盖**：登记销项发票关联 2 张销售单（部分开票）→ 详情正确；同一单据再次开票超未开票金额被拒（`40133`）；用销项票关联采购单被拒（`40134`）；作废后该单据可再次开票。

## 4. 验收标准

1. `cd backend && dotnet build` / `dotnet test` 通过（含税额计算、未开票金额、方向 / 往来校验、作废释放金额等单测）。
2. `cd frontend && npm run type-check` / `npm run lint` / `npm run build` 全绿；`npm run test:e2e` 全量通过。
3. 手工验证：
   - 销售单 GI001 金额 1000 → 登记销项发票（不含税 900、税率 13%）→ 税额 117.00、合计 1017.00；关联 GI001 开票金额 900 → 该单据未开票金额 100。
   - 再用另一张发票给 GI001 开 150 → 拒绝（`40133`，提示含单据号与未开票金额）；开 100 → 通过（未开票金额 0）。
   - 作废第一张发票 → GI001 未开票金额回到 1000（金额自动释放）。
4. 方向与往来：销项票关联采购入库单 → `40134`；发票往来与单据往来不一致 → `40135`；发票号重复 → `40132`。
5. 金额口径单一：税额与合计只在 `design.md` §0 定义一次（精度 / 舍入）；未开票金额口径与 `023` 的「未结金额」并列定义、不混用。
6. 范围克制：系统中不存在任何开票接口调用、税控对接或发票影像附件功能（范围外清单逐条核对）。

## 5. 范围外（不做）

- **开票接口对接 / 税控设备 / 电子发票平台**：只做**手工登记**（`ROADMAP` §5 明确「发票只做登记与关联，不做开票接口对接与税控」）。
- **红字发票 / 冲红专用流程**：作废即冲销（登记层面），不做「红字发票关联原蓝票」的税务流程。
- **按明细开票**（按单据的某几行商品开票）：本期只到**单据级**（整单 / 部分金额），不做行级开票。
- **发票影像 / 附件上传**：不做文件存储。
- **发票与收付款的核销联动**（按发票收款）：`023` 的核销以单据为对象，不做「按发票核销」。
- **税务申报数据导出 / 进项税抵扣台账**：不做申报表与抵扣管理。
- **发票批量导入（Excel）**：不做（`027` 只做导出）。
- **单据页展示已开票金额**：本期不做（避免改动 5 类单据页面与列表）；查询入口在发票列表（支持按单据号关键词检索）。
- **发票类型扩展**（收据 / 形式发票 / 报关单）：只有进项 / 销项两类。
