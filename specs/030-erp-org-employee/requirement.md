# 需求规格：组织架构与员工档案（erp-org-employee）

> ERP 全域路线（`specs/ROADMAP.md` §4.2）**P1 平台地基**第三项；**HCM 前置**：为 `028` 数据级权限与 `042` 审批流提供「组织 / 岗位 / 员工」主数据。
> 依赖：`009`（用户账号，员工可选绑定）、`028`（权限基础设施，本规格仅续行权限点）、`027`（导出基建，仅员工导出复用）。
> 范围口径：`ROADMAP` §1「HCM 并入主线：组织 · 岗位 · 员工先行；考勤 · 薪酬后置」。

## 1. 背景

现状**只有"登录账号"（`009` 的 `Users`），没有"人"与"组织"**：

- 账号只回答"谁能登录系统"，不回答"这个人在哪个部门、什么岗位"；也没有人事档案（工号 / 入职离职 / 联系方式）。
- `028-erp-rbac` §5 明确「不做组织 / 部门 / 岗位模型」，其数据级权限（按部门 / 数据范围过滤）因此一直缺前提；`042-erp-approval` 也需要"组织 / 岗位 / 员工"来定位审批人。
- HCM 后续（考勤 / 薪酬 / 绩效，`ROADMAP` P6）必须建立在员工档案之上。

本规格补齐这块**主数据地基**：部门（树）、岗位（字典）、员工（档案），并允许员工**可选绑定一个系统账号**。**不做**考勤 / 薪酬，也**不做**基于组织的数据级权限（仍属范围外，见 §5）。

## 2. 目标

1. **部门树**：维护多级部门（编码 / 名称 / 上级 / 排序 / 状态），支持新增下级、编辑、启停；删除受"有子部门或有员工"保护。
2. **岗位字典**：维护岗位（编码 / 名称 / 说明 / 状态），独立于部门（员工同时挂"部门 + 岗位"）。
3. **员工档案**：工号（唯一）、姓名、性别、手机、邮箱、部门、岗位、入职 / 离职日期、在职状态、备注；支持列表（筛选 + 分页）、新增、编辑、启停、导出。
4. **员工 ↔ 账号**：员工**可选**绑定**一个**系统账号（1:0..1）；一个账号最多被一个员工绑定；**员工本身不是账号**，登录一律走 `009`。
5. **权限与菜单**：沿用 `028` 机制（`Permissions` 常量 + `[RequirePermission]`）；本规格在其 §0.2 续行 `departments.*` / `positions.*` / `employees.*` 权限点；菜单续行至 `025` §0.2 的「系统」分组。
6. **前端**：新增「部门 / 岗位 / 员工」三个页面（归同一功能域目录 `OrgManagement/`），复用既有列表 / 表单 / 操作列 / 按钮 loading 约定。

## 3. 功能点

- **F1 部门树**：`GET /api/departments`（返回树，含每节点在职员工数）；新增 / 编辑 / 删除 / 启停；编码全局唯一（`40138`），名称**同一上级下**唯一（`40139`）；上级不能是自身或后代（防环，`40141`）；有子部门或有关联员工 → 禁止删除（`40140`）。
- **F2 岗位字典**：`GET /api/positions`（分页 + 关键词 / 状态筛选）；新增 / 编辑 / 删除 / 启停；编码（`40142`）与名称（`40143`）唯一；被员工引用 → 禁止删除（`40144`）；另提供 `GET /api/positions/picks`（启用的精简列表，供员工表单下拉）。
- **F3 员工列表**：`GET /api/employees`（分页；按工号 / 姓名关键词、部门、岗位、状态筛选）；出参含部门名 / 岗位名 / 关联账号显示名。
- **F4 员工新增 / 编辑**：工号唯一（`40145`）且创建后不可改；手机（`40147`）/ 邮箱（`40148`）非空时唯一；入职日期必填、离职日期可空；部门 / 岗位可空。
- **F5 员工启停**：在职 ↔ 离职切换；离职**不删除**记录（保留历史，同 `009` 不删用户）。
- **F6 员工-账号绑定**：员工表单可选一个系统账号；该账号已被其他员工绑定 → `40146`；解绑即置空；可选账号来源 `GET /api/employees/available-users`（启用且未被绑定 + 当前员工已绑定的）。
- **F7 员工导出**：列表导出 Excel（复用 `027` 的 `IExcelExporter` 与文件下载契约例外）。
- **F8 权限与菜单**：权限点续行至 `028` §0.2；菜单续行至 `025` §0.2「系统」分组（部门管理 / 岗位管理 / 员工档案）。
- **F9 e2e 覆盖**：建部门树 → 建岗位 → 建员工（绑账号）→ 列表筛选 / 编辑 / 离职 / 导出；部门删除保护与防环校验；员工绑定冲突；无权限账号不可见菜单 / 403。

## 4. 验收标准

1. `cd backend && dotnet build` / `dotnet test` 通过（部门树与防环、删除保护、岗位唯一与占用、员工唯一性 / 绑定冲突 / 启停等单测）。
2. `cd frontend && npm run type-check` / `npm run lint` / `npm run build` 全绿；`npm run test:e2e` 全量通过（新增 `org-employee.spec.ts`）。
3. 手工验证（部门）：三级部门树正常展示与展开；同级重名 → `40139`；编码重复 → `40138`；把上级设为自身 / 后代 → `40141`；删除有子部门或有员工的部门 → `40140`。
4. 手工验证（岗位）：编码 / 名称重复 → `40142` / `40143`；删除被员工引用的岗位 → `40144`。
5. 手工验证（员工）：工号重复 → `40145`；绑定已被占用的账号 → `40146`；离职后记录保留、状态为「离职」、默认筛选不再出现在职；导出 Excel 可打开、列与列表一致。
6. 绑定与登录：员工绑定的账号可正常登录（登录仍走 `009`）；未绑定账号的员工不产生任何登录能力（系统无"员工登录"）。
7. 权限生效：无 `employees.view` 的账号不可见「员工档案」菜单、直接访问路由显示 403、直接调接口返回 `40300`（机制复用 `028`，不新增校验路径）。
8. 口径单一：部门 / 岗位 / 员工的字段约束、唯一性范围、删除保护规则只在 `design.md` §0 / §2 定义一次。
9. 联动：`028` §0.2 续行权限点、§5「不做组织模型」加演进注记；`025` §0.2「系统」分组续行三项；`042` `design.md` 注明可用组织定位审批人。

## 5. 范围外（不做）

- **考勤 / 休假 / 薪酬 / 招聘 / 绩效**：HCM 后置能力（`ROADMAP` P6 `erp-hcm-payroll`）。
- **基于组织的数据级权限（数据范围 / 行级过滤）**：`028` §5 范围外的延续；本期只提供组织主数据，不改查询层的范围注入。
- **汇报关系 / 上下级 / 审批线**：不做组织汇报图；`042` 仍用"权限点 + 指定审批人"。
- **员工自助 / 员工登录 / 员工个人中心**：员工不是账号，登录一律走 `009` 的 `Users`。
- **员工照片 / 附件 / 证件**：不做文件存储。
- **多公司 / 多法人主体 / 多组织**：单主体（`ROADMAP` §7）。
- **岗位职级 / 职类 / 薪级**：只做岗位字典。
- **组织变更历史**：留痕由 `029-erp-audit-log` 承担，不单独做版本。
- **部门 / 岗位的生效时间与版本**：单值（改了即覆盖）。
- **员工批量导入（Excel）**：不做（`027` 只做导出）。
- **一个员工绑定多个账号 / 一个账号绑定多个员工**：均为 1:0..1。
